The integration shape below is correct conceptually; treat exact package names/imports as needing a v3 check.

**Goal:** Turn the page editor into a live multiplayer surface. When a `Y.Doc` is supplied, TipTap edits sync through a `HocuspocusProvider` to the `cairn-collab` service (Yjs = source of truth); the collab server materializes the merged doc back into `pages.content` so search/export/public-render keep reading `pages.content` unchanged. The v0.1.0 debounced content PATCH + 409 conflict path is retired on the collab path; title/icon/cover PATCH stays.

**Architecture:** A new client hook `useCollabDoc(pageId)` fetches a short-lived collab JWT from `GET /api/collab/token?pageId=` (built in Plan 1) and opens a `HocuspocusProvider` (doc name = pageId, token in `parameters`/`token`). The `Editor` accepts the provider's `Y.Doc`; when present it disables StarterKit `history` and adds `Collaboration` + (read/write) `CollaborationCursor`. Custom nodes (callout/image/file/database) ride through `y-prosemirror` unchanged — each is verified Yjs-safe in Task 2. On the server side, `collab/server.ts` (from Plan 1) gains a debounced `onStoreDocument` (and a flush on last disconnect) that runs `yjsStateToProseDoc` (from Plan 1) and writes `pages.content` via raw SQL; the existing `pages_sync_search_columns` trigger refreshes FTS. Read-only viewers connect with a viewer-role token and `editable: false`, writing no awareness.

**Tech Stack:** Yjs (`yjs`, `y-prosemirror`), Hocuspocus (`@hocuspocus/provider` client, `@hocuspocus/server` already in `cairn-collab` from Plan 1), TipTap 2.27.x (`@tiptap/extension-collaboration`, `@tiptap/extension-collaboration-cursor`). Vitest for the one extractable pure helper; the rest is smoke-verified against a live `cairn` + `cairn-collab` stack.

**Spec:** `docs/superpowers/specs/2026-05-21-cairn-v0.3.0-design.md` (§2 decisions 2 & 5, §5 Editor integration + Materialization, §8 risks).

**Builds on:** v0.3.0 Plan 1 (`2026-05-21-cairn-v0.3.0-collab-infra.md`). Assumes these exist and are committed:

```ts
import Collaboration from '@tiptap/extension-collaboration';
import CollaborationCursor from '@tiptap/extension-collaboration-cursor';
import type { HocuspocusProvider } from '@hocuspocus/provider';
import type * as Y from 'yjs';

export type CollabUser = { name: string; color: string };

/**
 * Same node/mark set as baseExtensions(), but Yjs-driven:
 *  - StarterKit `history` is DISABLED (Yjs owns undo/redo via its own history).
 *  - Collaboration binds the shared Y.Doc; CollaborationCursor renders remote carets.
 * Custom nodes (callout/image/file/database) are unchanged — see Yjs-safety note.
 */
export function collabExtensions(opts: {
  ydoc: Y.Doc;
  provider: HocuspocusProvider;
  user: CollabUser;
  withCursor: boolean; // false for read-only viewers (no awareness writes)
}) {
  const base = baseExtensions().filter(
    (e) => e.name !== 'history', // StarterKit's history sub-extension; remove if present
  );
  // Belt-and-suspenders: also disable history via StarterKit config in the editor
  // (filtering by name depends on TipTap exposing the sub-extension — verify).
  const ext = [
    ...base,
    Collaboration.configure({ document: opts.ydoc }),
  ];
  if (opts.withCursor) {
    ext.push(
      CollaborationCursor.configure({ provider: opts.provider, user: opts.user }),
    );
  }
  return ext;
}
```

The robust approach is to configure StarterKit with `history: false` **when collab is active**. Since `baseExtensions()` is shared, refactor it to take an optional `{ history?: boolean }` and pass `history: false` from `collabExtensions`. Implement whichever the installed StarterKit supports; verify with `pnpm build` + Task 7 (double-undo / no-undo-stack-conflict).

## Task 3: Client hook `useCollabDoc(pageId)`

**Goal:** Fetch the collab token, open a `HocuspocusProvider`, expose `{ ydoc, provider, status }`.

**Files:** Create `src/components/editor/use-collab-doc.ts`

- [x] **Step 1: Write the hook**

> API flag: the `HocuspocusProvider` option keys (`url`, `name`, `token`, `document`) and status-event wiring vary by version — **confirm against https://tiptap.dev/docs/hocuspocus/provider** before finalizing. Shape below.

```ts
'use client';

import { HocuspocusProvider } from '@hocuspocus/provider';
import { useEffect, useMemo, useState } from 'react';
import * as Y from 'yjs';

export type CollabStatus = 'connecting' | 'connected' | 'disconnected' | 'error';

export type UseCollabDoc = {
  ydoc: Y.Doc;
  provider: HocuspocusProvider | null;
  status: CollabStatus;
};

export function useCollabDoc(pageId: string): UseCollabDoc {
  // One Y.Doc per page for the component's lifetime.
  const ydoc = useMemo(() => new Y.Doc(), []);
  const [provider, setProvider] = useState<HocuspocusProvider | null>(null);
  const [status, setStatus] = useState<CollabStatus>('connecting');

  useEffect(() => {
    let cancelled = false;
    let p: HocuspocusProvider | null = null;

    void (async () => {
      try {
        const res = await fetch(`/api/collab/token?pageId=${encodeURIComponent(pageId)}`);
        if (!res.ok) {
          if (!cancelled) setStatus('error');
          return;
        }
        const { token, collabUrl } = (await res.json()) as { token: string; collabUrl: string };
        if (cancelled) return;

        // VERIFY option keys against provider docs (url/name/token/document):
        p = new HocuspocusProvider({
          url: collabUrl,
          name: pageId, // doc name = pageId
          token,
          document: ydoc,
          onStatus: ({ status: s }) => {
            if (cancelled) return;
            setStatus(s === 'connected' ? 'connected' : 'connecting');
          },
          onDisconnect: () => !cancelled && setStatus('disconnected'),
        });
        if (!cancelled) setProvider(p);
      } catch {
        if (!cancelled) setStatus('error');
      }
    })();

    return () => {
      cancelled = true;
      p?.destroy();
      ydoc.destroy();
    };
  }, [pageId, ydoc]);

  return { ydoc, provider, status };
}
```

Notes: the token is fetched fresh per mount (Plan 1 mints a ~5-min JWT; if the socket outlives it, reconnection re-fetches — handle token-refresh on reconnect only if Task 7 surfaces drops, otherwise leave as a documented limitation). `ydoc.destroy()` + `provider.destroy()` on unmount prevent leaks.

describe('materialize scheduler', () => {

- [x] **Step 2: Write `src/collab/materialize-scheduler.ts`**

```ts
type Opts = {
  debounceMs: number;
  flush: (pageId: string) => void | Promise<void>;
};

/**
 * Pure-ish scheduler: debounces per-page store events and forces an immediate,
 * debounce-cancelling flush on last disconnect so the final edits are never lost.
 * No Yjs / no DB — those are injected via `flush`.
 */
export function createMaterializeScheduler({ debounceMs, flush }: Opts) {
  const timers = new Map<string, ReturnType<typeof setTimeout>>();

  function clear(pageId: string) {
    const t = timers.get(pageId);
    if (t) {
      clearTimeout(t);
      timers.delete(pageId);
    }
  }

  return {
    onStore(pageId: string) {
      clear(pageId);
      timers.set(pageId, setTimeout(() => {
        timers.delete(pageId);
        void flush(pageId);
      }, debounceMs));
    },
    onLastDisconnect(pageId: string) {
      clear(pageId); // cancel pending debounce — we flush now instead
      void flush(pageId);
    },
  };
}
```

  if (!ydoc) return;
  // Prefer encoding to Uint8Array so materialize.ts's Plan-1 signature is unchanged:
  const state = Y.encodeStateAsUpdate(ydoc);
  const prose = yjsStateToProseDoc(state);
  // Raw SQL update; the pages_sync_search_columns trigger refreshes content_text/content_tsv.
  await sql/* sql */`
    UPDATE pages SET content = ${JSON.stringify(prose)}::jsonb, updated_at = now()
    WHERE id = ${pageId}
  `;
}

const scheduler = createMaterializeScheduler({ debounceMs: 2000, flush: materialize });

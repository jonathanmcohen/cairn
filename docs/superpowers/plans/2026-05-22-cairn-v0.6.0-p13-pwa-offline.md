# Cairn v0.6.0 Plan 13 — PWA + bounded offline (Yjs)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Cairn an **installable PWA with a *bounded* offline mode**. Ship a web app manifest + maskable icons (installability), a service worker via **`@serwist/next`** with an **allow-listed route-strategy map** (precache the app shell + static assets; stale-while-revalidate idempotent page reads; **network-only, NEVER cached** for auth, all mutations, signed `/api/files/*` URLs, and the Hocuspocus collab WebSocket; an offline fallback page for failed navigations), `y-indexeddb` persistence on **already-opened** collab docs so recently-viewed pages **read offline** and **simple queued edits CRDT-merge on reconnect**, an offline status indicator, and disabled-when-offline affordances for everything non-Yjs. A Lighthouse-PWA + offline-read docker smoke proves installability + the offline-read path.

**THE LOAD-BEARING CONSTRAINT (read first, do not drift):** This is **bounded offline, NOT offline-first** (spec §2.22, §8). The *only* correctness-safe offline write is an ordinary Yjs update on a doc **already loaded into IndexedDB this session** — the Hocuspocus provider buffers it while disconnected and the CRDT merges it on reconnect. **Everything else is DISABLED offline, not silently queued:** page create, structural ops (move/delete/reorder/restore), database row/cell mutations, file uploads, comments, sharing, admin. Non-Yjs data has **no automatic conflict story**, so a hand-rolled outbox is forbidden. The two hazards this plan must *not* introduce: (1) the SW caching a mutation / an auth response / a signed file URL / the WS (a correctness + **security** bug — caching a signed `/api/files` URL would serve a stale/forgeable read); (2) any offline UI that *accepts* a non-Yjs write and pretends it will sync. Both are asserted in tests (Task 2 strategy-map units, Task 4 offline-gate units).

**Architecture:** `@serwist/next` wraps `next.config.mjs` (it injects the SW build + a precache manifest) and compiles a source SW at `src/app/sw.ts` (Serwist's App-Router convention) to `public/sw.js`. The SW installs a **`defaultCache`-derived but explicitly overridden** runtime-caching list: a single ordered `runtimeCaching` array where the FIRST matching route wins, with **network-only entries listed first** so they can never be shadowed by a broad read rule. Navigations are `NetworkFirst` with an offline-document fallback (`/offline`). The manifest is a Next metadata route (`src/app/manifest.ts`) — no static `manifest.json`. SW **registration** is the one CSP-sensitive seam: Serwist auto-injects a `<script>` that calls `navigator.serviceWorker.register('/sw.js')`; under our nonce CSP that inline script is blocked unless it carries the per-request nonce (exactly the v0.5.1 class of bug). We register the SW from a **nonce'd client component** (`src/components/pwa/register-sw.tsx`) reading the nonce the proxy already forwards, and we **disable Serwist's own auto-registration** so there is one, CSP-clean registration path. The SW *script itself* is served same-origin from `/sw.js` (`script-src 'self'` already allows it — it is not inline). For offline editing, the collab provider setup attaches an `IndexeddbPersistence` (from `y-indexeddb`) keyed by `pageId` to each opened `Y.Doc`, so an opened page's state survives reload + is editable offline; the existing `HocuspocusProvider` buffers offline updates and merges them on reconnect (no new queue). An `OfflineGate` context (`navigator.onLine` + the provider connection status) drives the status indicator and disables non-Yjs affordances.

**Tech Stack:** New deps — **`@serwist/next`** (dev dep; the Next plugin + SW build) and **`serwist`** (the SW runtime it pulls/peers — install explicitly to pin a single version, mirroring the y-prosemirror singleton lesson), **`y-indexeddb`** (runtime dep; `IndexeddbPersistence`). Reuses: `yjs` + `@hocuspocus/provider` (v0.3.0), `src/components/editor/use-collab-doc.ts` (the hook that owns the `Y.Doc` + provider — this plan extends it), `src/proxy.ts` + `src/lib/security/headers.ts` (the nonce CSP), `next.config.mjs`. **Unit-tested** (the only pure logic): the **strategy-map matcher** (Task 2 — given a request URL+method, which strategy applies; assert mutations/auth/signed-files/WS resolve to network-only and are *never* cacheable) and the **offline-gate predicate** (Task 4 — given `{online, providerStatus, actionKind}`, is the action allowed). **Build/integration-verified** (PWA + SW are integration surfaces): `pnpm build` (Serwist compiles the SW), the docker-compose smoke, and a **Lighthouse PWA + offline-read** run (Task 5). Do NOT fabricate unit tests around the live SW lifecycle or IndexedDB I/O — those are smoke-verified.

**Spec:** `docs/superpowers/specs/2026-05-22-cairn-v0.6.0-design.md` — §2.22 (offline = `y-indexeddb` + replay-on-reconnect, NOT a hand-rolled outbox; the scope limit), §2.23 (`@serwist/next` SW + the route-strategy map), §3 Mobile (PWA: manifest/icons/installability/offline fallback; Offline bounded), §5 Mobile/PWA (`@serwist/next` in `next.config` + `src/app/sw.ts`; `src/app/manifest.ts`; maskable icons; SW registration from a nonce'd client script; `y-indexeddb` per opened doc; disabled-offline affordances), §6 Testing (SW + manifest under CSP/nonce; SW never caches mutations/auth/signed file URLs/ws — assert the strategy map; Lighthouse PWA + offline-read smoke; the offline-edit→reconnect→merge path is part of the Yjs round-trip audit), §8 (PWA offline + Yjs is the riskiest correctness surface — the hard scope boundary is the mitigation; SW caching is a correctness + security hazard if mis-scoped).

## CSP coexistence — the v0.5.1-class seam (read before Task 1 & 2)

The proxy (`src/proxy.ts`) mints a per-request nonce and emits `script-src 'self' 'nonce-<nonce>'` (no `'unsafe-inline'`). Implications for the SW:

1. **The SW file `/sw.js` is served same-origin and loaded by the browser's SW machinery, NOT as a page `<script>`** — `script-src 'self'` already permits it; **no `worker-src`/`script-src` change is needed for the SW *file* itself.** Verify (Task 5) that `/sw.js` loads with no CSP console error.
2. **SW *registration* is the trap.** `@serwist/next`'s default behavior injects an inline registration script into the page. An inline script with no matching nonce is **blocked** under our CSP → the SW never registers → installability + offline silently fail (green build, broken runtime — the exact v0.5.1 failure mode). **Mitigation:** set `register: false` (or the package's equivalent — VERIFY the option name in Task 2) on the `@serwist/next` plugin to suppress auto-registration, and register from our own **nonce'd client component** (`src/components/pwa/register-sw.tsx`, Task 1). That component reads the nonce the proxy already forwards and either (a) is rendered with `nonce={nonce}` so any inline it emits is allowed, or (b) — preferred — calls `navigator.serviceWorker.register('/sw.js')` from a normal module `useEffect` (NOT an inline string), which needs no nonce at all because it ships in the app bundle, not as inline HTML. **Prefer (b).** Confirm under CSP in Task 5 (no `Refused to ... because it violates the Content-Security-Policy` in the console).
3. **`connect-src`:** the offline-read SWR cache and `navigator.serviceWorker` use no new origins; the collab WS origin is already in `connect-src` (v0.3.0). **No CSP directive change is required by this plan** beyond confirming registration is nonce-clean. If Task 2/5 surfaces a genuine need (e.g. Serwist demands an inline bootstrap that cannot be nonce'd), add a `worker-src 'self'` directive to `buildCsp()` in `src/lib/security/headers.ts` and a matching unit assertion — but only if proven necessary; do not add it speculatively.
4. **The SW must coexist with the public CSP too.** `/p/` and `/s/` carry the stricter public CSP. The SW scope is the whole origin; confirm (Task 5) the SW does not break a public-page load.

```tsx
'use client';

import { useEffect } from 'react';

/**
 * Registers the Serwist-built /sw.js from the app bundle (NOT an inline script),
 * so it needs no CSP nonce — it ships under `script-src 'self'`. Serwist's own
 * auto-registration is disabled in next.config (register:false) so this is the
 * single registration path. Guarded for SSR + unsupported browsers.
 */
export function RegisterSw() {
  useEffect(() => {
    if (typeof window === 'undefined') return;
    if (!('serviceWorker' in navigator)) return;
    // Register on load to avoid contending with first-paint fetches.
    const onLoad = () => {
      void navigator.serviceWorker.register('/sw.js').catch(() => {
        /* registration failure is non-fatal: app works online without the SW */
      });
    };
    if (document.readyState === 'complete') onLoad();
    else window.addEventListener('load', onLoad, { once: true });
    return () => window.removeEventListener('load', onLoad);
  }, []);
  return null;
}
```

- [ ] **Step 4: Write `src/lib/pwa/sw-strategy.ts`** — pure, ordered, network-only-first. **This is the single source of truth the SW's `runtimeCaching` is built from** (Step 6 maps each strategy onto the Serwist strategy classes). The ORDER is the invariant: a request that matches *any* network-only predicate returns `'network-only'` before any read rule is consulted.

```ts
export type SwStrategy = 'network-only' | 'swr' | 'network-first' | 'precache';

const MUTATING_METHODS = new Set(['POST', 'PUT', 'PATCH', 'DELETE']);

/** Static-asset extensions that are content-hashed / safe to precache. */
const STATIC_EXT = /\.(?:js|css|woff2?|png|jpg|jpeg|gif|svg|ico|webp|avif|json|webmanifest)$/i;

/**
 * Decide the SW caching strategy for a request. NETWORK-ONLY is checked FIRST and
 * exhaustively: mutations, auth, signed file reads, and the collab token/WS must
 * NEVER be cached (correctness + security — a cached signed /api/files URL would
 * serve a stale/forgeable read; a cached auth/mutation is a correctness bug).
 * The WebSocket upgrade (wss:) is not an HTTP fetch the SW intercepts, but we
 * classify it network-only for completeness/assertion.
 */
export function matchStrategy(url: URL, method: string): SwStrategy {
  const path = url.pathname;

  // 1. NETWORK-ONLY — never cached. Order matters: this block wins.
  if (MUTATING_METHODS.has(method.toUpperCase())) return 'network-only';
  if (path.startsWith('/api/auth')) return 'network-only';
  if (path.startsWith('/api/files')) return 'network-only'; // signed reads — never cache
  if (path.startsWith('/api/collab')) return 'network-only'; // short-lived JWT
  if (url.protocol === 'ws:' || url.protocol === 'wss:') return 'network-only';

  // 2. PRECACHE class — content-hashed static assets + Next static output.
  if (path.startsWith('/_next/static') || STATIC_EXT.test(path)) return 'precache';
```

## Task 3: `y-indexeddb` on opened docs + reconnect merge (bounded offline editing)

**Goal:** Persist each **opened** collab `Y.Doc` to IndexedDB via `y-indexeddb`'s `IndexeddbPersistence`, so a recently-viewed page **loads + reads offline** and **edits made offline buffer in the provider and CRDT-merge on reconnect** — no new queue, strictly scoped to docs already loaded this session (spec §2.22). Extend `use-collab-doc.ts` (the v0.3.0 hook that owns the `Y.Doc` + `HocuspocusProvider`).

**Files:** modify `src/components/editor/use-collab-doc.ts`.

- [ ] **Step 1: Re-read `src/components/editor/use-collab-doc.ts`** (current: `useMemo` `new Y.Doc()`, fetches the collab token, opens `HocuspocusProvider({ url, name: pageId, token, document: ydoc, onStatus, onDisconnect })`, destroys provider + ydoc on unmount).

- [ ] **Step 2: Attach `IndexeddbPersistence` to the doc.** Create it as soon as the `Y.Doc` exists (NOT gated on the provider/token — the whole point is offline read works without the network). Key the IndexedDB store by `pageId` so each page has its own store. Track a `synced`/`offlineReady` flag from its `'synced'` event (fired when the local state has loaded). Destroy it on unmount alongside the provider/doc.

```tsx
'use client';

import { HocuspocusProvider } from '@hocuspocus/provider';
import { useEffect, useMemo, useState } from 'react';
import { IndexeddbPersistence } from 'y-indexeddb';
import * as Y from 'yjs';

export type CollabStatus = 'connecting' | 'connected' | 'disconnected' | 'error';

export type UseCollabDoc = {
  ydoc: Y.Doc;
  provider: HocuspocusProvider | null;
  status: CollabStatus;
  /** True once the local IndexedDB copy of this doc has loaded (offline-readable). */
  offlineReady: boolean;
};

export function useCollabDoc(pageId: string): UseCollabDoc {
  const ydoc = useMemo(() => new Y.Doc(), []);
  const [provider, setProvider] = useState<HocuspocusProvider | null>(null);
  const [status, setStatus] = useState<CollabStatus>('connecting');
  const [offlineReady, setOfflineReady] = useState(false);

  // Local persistence: load/save this doc to IndexedDB so it survives reload and
  // is editable offline. Scoped to THIS opened page only (the bounded-offline
  // contract — we never persist or sync docs the user hasn't opened this session).
  useEffect(() => {
    // Store name = stable per page. y-indexeddb merges persisted state into ydoc.
    const persistence = new IndexeddbPersistence(`cairn-doc-${pageId}`, ydoc);
    const onSynced = () => setOfflineReady(true);
    persistence.on('synced', onSynced);
    return () => {
      persistence.off('synced', onSynced);
      // Destroy releases the IndexedDB connection; persisted data REMAINS on disk
      // so the next open reads it (do NOT call clearData()).
      void persistence.destroy();
    };
  }, [pageId, ydoc]);

  useEffect(() => {
    let cancelled = false;
    let p: HocuspocusProvider | null = null;
    void (async () => {
      try {
        const res = await fetch(`/api/collab/token?pageId=${encodeURIComponent(pageId)}`);
        if (!res.ok) {
          if (!cancelled) setStatus('error');
          return;
        }
        const { token, collabUrl } = (await res.json()) as { token: string; collabUrl: string };
        if (cancelled) return;
        p = new HocuspocusProvider({
          url: collabUrl,
          name: pageId,
          token,
          document: ydoc, // SAME doc y-indexeddb is bound to: offline edits buffer here,
          //               the provider replays + CRDT-merges them on reconnect.
          onStatus: ({ status: s }) => {
            if (cancelled) return;
            setStatus(s === 'connected' ? 'connected' : 'connecting');
          },
          onDisconnect: () => !cancelled && setStatus('disconnected'),
        });
        if (!cancelled) setProvider(p);
      } catch {
        if (!cancelled) setStatus('error');
      }
    })();
    return () => {
      cancelled = true;
      p?.destroy();
      ydoc.destroy();
    };
  }, [pageId, ydoc]);

  return { ydoc, provider, status, offlineReady };
}
```

> **Why no new queue:** the same `Y.Doc` is shared by `IndexeddbPersistence` (durable local copy) and `HocuspocusProvider` (network sync). Offline, edits land in the doc + IndexedDB; the provider holds unsynced updates and, on reconnect, exchanges state vectors and merges — Yjs guarantees convergence. This is the *entire* offline-write mechanism. **Do NOT add any other persistence or replay path.**

> **Lifecycle ordering:** y-indexeddb loads asynchronously; if the provider connects and seeds before the local load completes, Yjs still merges correctly (CRDT) — order does not affect correctness. The `offlineReady` flag is for UI only.

- [ ] **Step 3: Write the `OfflineGate` context `src/components/pwa/offline-context.tsx`** — tracks `navigator.onLine` via `online`/`offline` events, exposes `{ online }` + a `useOfflineGate()` hook + a `useActionAllowed(kind)` convenience wrapping the pure predicate:

```tsx
'use client';

import { createContext, useContext, useEffect, useMemo, useState } from 'react';
import { type ActionKind, isActionAllowedOffline } from './offline-gate';

type Ctx = { online: boolean };
const OfflineContext = createContext<Ctx>({ online: true });

export function OfflineProvider({ children }: { children: React.ReactNode }) {
  const [online, setOnline] = useState(true);
  useEffect(() => {
    setOnline(navigator.onLine); // hydrate from the real value post-mount
    const up = () => setOnline(true);
    const down = () => setOnline(false);
    window.addEventListener('online', up);
    window.addEventListener('offline', down);
    return () => {
      window.removeEventListener('online', up);
      window.removeEventListener('offline', down);
    };
  }, []);
  const value = useMemo(() => ({ online }), [online]);
  return <OfflineContext.Provider value={value}>{children}</OfflineContext.Provider>;
}

export function useOfflineGate(): Ctx {
  return useContext(OfflineContext);
}

/** True if the action is permitted given the current connection state. */
export function useActionAllowed(action: ActionKind): boolean {
  const { online } = useOfflineGate();
  return isActionAllowedOffline(action, { online });
}
```

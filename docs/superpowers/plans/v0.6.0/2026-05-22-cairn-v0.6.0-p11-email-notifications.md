# Cairn v0.6.0 Plan 11 — Email notifications + preferences

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add **opt-in BYO-SMTP email notifications** on top of the existing in-app notification system. SMTP is configured purely by env (`SMTP_HOST`/`PORT`/`USER`/`PASS`/`FROM`/`SECURE`) and is **fully disabled — a clean no-op — when `SMTP_HOST` is unset**. Per-event email rides the existing in-process notification-creation path (fired alongside the `notifications` row insert, fire-and-forget, non-blocking, errors swallowed — mirroring the webhook `emit` pattern). A digest mode (`scanDigests`, CLI/interval-runnable) batches each user's unread notifications into one email. Email bodies render plain-text + minimal HTML. A notification-preferences UI backed by `notification_email_prefs` lets each user choose, per notification type, whether they receive email, in-app, or a digest.

**Architecture:** Email is **best-effort, never transactional** (spec §8: "a down SMTP server must never block a notification or request"). The transport (`src/lib/email/transport.ts`) is a thin `nodemailer` wrapper that returns `null` when `SMTP_HOST` is unset; every send path checks that first and no-ops. The per-event hook (`src/lib/email/notify-email.ts#sendNotificationEmail`) is fired via `setImmediate` from the in-app notification path (`src/lib/notifications/create.ts`) exactly like `webhooks/dispatch.ts#emit` schedules delivery off the request path — it is **never awaited** by the caller, so notification/comment latency is unaffected, and the whole body is guarded so a failure is at worst a logged error. The hook reads `notification_email_prefs` to **decide whether to send** (per-type `email_enabled`; `digest_only` rows are skipped by the per-event path and picked up by the digest scan instead). Digests are a periodic flush (`scanDigests(now)`, run by `pnpm cli email:digest` OR the opt-in single-instance interval ticker from the ops decisions §2.36) batching each user's unread, digest-eligible notifications into one email and stamping a per-user `digest_sent_at` watermark (stored in `system_meta`) so a re-run is idempotent. All outbound links pass the existing SSRF guard (`src/lib/webhooks/ssrf.ts#assertPublicUrl`) — the link base is `NEXTAUTH_URL` (operator env), and the SMTP host is operator env (low risk), but we guard the link host defensively per spec §6.

**Tech Stack:** New runtime dep: **`nodemailer`** (+ `@types/nodemailer` dev). No third-party email SaaS (spec §2.14, deferred forever). Drizzle + Zod + Vitest 4 + Testcontainers for the prefs CRUD + the decide-to-send logic (transport mocked); React client component (`'use client'`) for the prefs UI; the existing `getAuthContext` gating for the prefs API. Reuses `src/lib/env.ts` (optional `SMTP_*`), `src/lib/webhooks/dispatch.ts` (the `setImmediate` fire-and-forget precedent), `src/lib/webhooks/ssrf.ts` (link guard), and the `notifications` table from v0.3.0.

**Spec:** `docs/superpowers/specs/2026-05-22-cairn-v0.6.0-design.md` — §2.14 (BYO-SMTP, opt-in, per-event sender + digest cron, nodemailer, disabled-if-unset), §3 Sharing & collaboration (Email notifications in scope), §5 Collaboration → Email (`src/lib/email/*` layout), §6 Testing (email template render + SMTP-unset no-op + SSRF on email links; `notification_email_prefs` per-event/digest enqueue), §8 (email is best-effort not transactional; single-instance scheduling ceiling).

- [ ] **Step 3: Write `src/lib/email/transport.ts`**

```ts
import nodemailer, { type Transporter } from 'nodemailer';
import { env } from '@/lib/env';

let cached: Transporter | null | undefined;

/**
 * The single source of truth for "is email enabled?". Returns a configured
 * nodemailer transport when SMTP_HOST is set, or `null` when it is unset
 * (email is fully disabled — every send path no-ops on null). Cached so we
 * reuse one connection pool process-wide. Tests reset the cache via
 * `__resetTransport`.
 */
export function getTransport(): Transporter | null {
  if (cached !== undefined) return cached;
  const e = env();
  if (!e.SMTP_HOST) {
    cached = null;
    return cached;
  }
  cached = nodemailer.createTransport({
    host: e.SMTP_HOST,
    port: e.SMTP_PORT,
    secure: e.SMTP_SECURE,
    auth: e.SMTP_USER ? { user: e.SMTP_USER, pass: e.SMTP_PASS } : undefined,
  });
  return cached;
}

/** True iff SMTP is configured (email enabled). */
export function emailEnabled(): boolean {
  return getTransport() !== null;
}

/** The configured From address (falls back to SMTP_USER, then a sane default). */
export function fromAddress(): string {
  const e = env();
  return e.SMTP_FROM ?? e.SMTP_USER ?? 'cairn@localhost';
}

/** Test-only: drop the cached transport so a re-parsed env takes effect. */
export function __resetTransport(): void {
  cached = undefined;
}
```

```ts
import { env } from '@/lib/env';
import type { Notification } from '@/db/schema';
import { assertPublicUrl } from '@/lib/webhooks/ssrf';

export type RenderedEmail = { subject: string; text: string; html: string };

const COPY: Record<string, { verb: string; subject: string }> = {
  mention: { verb: 'mentioned you in a comment', subject: 'You were mentioned' },
  comment_reply: { verb: 'replied in a thread you’re part of', subject: 'New reply' },
};

function escapeHtml(s: string): string {
  return s.replace(/[&<>"']/g, (c) => `&#${c.charCodeAt(0)};`);
}

/** Build + SSRF-guard a deep link to the page/comment for a notification. */
async function linkFor(n: Notification): Promise<string> {
  const base = env().NEXTAUTH_URL.replace(/\/$/, '');
  const url = `${base}/pages/${n.payload.pageId}#comment-${n.payload.commentId}`;
  await assertPublicUrl(url); // base is operator env; guard defensively (spec §6)
  return url;
}

/** A single per-event email. */
export async function renderNotificationEmail(n: Notification): Promise<RenderedEmail> {
  const copy = COPY[n.type] ?? { verb: 'sent you a notification', subject: 'Notification' };
  const url = await linkFor(n);
  const text = `Someone ${copy.verb}.\n\nView it: ${url}\n\n— Cairn`;
  const html =
    `<div style="font-family:system-ui,sans-serif;font-size:14px;color:#111">` +
    `<p>Someone ${escapeHtml(copy.verb)}.</p>` +
    `<p><a href="${escapeHtml(url)}" style="color:#2563eb">View it</a></p>` +
    `<hr style="border:none;border-top:1px solid #eee"/><p style="color:#888">— Cairn</p></div>`;
  return { subject: copy.subject, text, html };
}

/** One digest email batching N unread notifications for a user. */
export async function renderDigestEmail(notifications: Notification[]): Promise<RenderedEmail> {
  const lines = await Promise.all(
    notifications.map(async (n) => {
      const copy = COPY[n.type] ?? { verb: 'a notification', subject: '' };
      return { verb: copy.verb, url: await linkFor(n) };
    }),
  );
  const n = notifications.length;
  const subject = `Cairn digest — ${n} new notification${n === 1 ? '' : 's'}`;
  const text =
    `You have ${n} new notification${n === 1 ? '' : 's'}:\n\n` +
    lines.map((l) => `• Someone ${l.verb}: ${l.url}`).join('\n') +
    `\n\n— Cairn`;
  const html =
    `<div style="font-family:system-ui,sans-serif;font-size:14px;color:#111">` +
    `<p>You have ${n} new notification${n === 1 ? '' : 's'}:</p><ul>` +
    lines
      .map(
        (l) =>
          `<li>Someone ${escapeHtml(l.verb)} — ` +
          `<a href="${escapeHtml(l.url)}" style="color:#2563eb">view</a></li>`,
      )
      .join('') +
    `</ul><hr style="border:none;border-top:1px solid #eee"/><p style="color:#888">— Cairn</p></div>`;
  return { subject, text, html };
}
```

Pattern after `src/lib/notifications/create.ts` (typed `PostgresJsDatabase<typeof schema>` injection). The default when no row exists: **in-app only** (no email) — email is opt-in (spec §2.14).
```ts
import { and, eq } from 'drizzle-orm';
import type { PostgresJsDatabase } from 'drizzle-orm/postgres-js';
import * as schema from '@/db/schema';

type Db = PostgresJsDatabase<typeof schema>;

export type EmailPref = { notificationType: string; emailEnabled: boolean; digestOnly: boolean };
export const NOTIFICATION_TYPES = ['mention', 'comment_reply'] as const;

/** All of a user's prefs in a workspace, merged over the opt-in defaults. */
export async function getEmailPrefs(
  db: Db,
  userId: string,
  workspaceId: string,
): Promise<EmailPref[]> {
  const rows = await db
    .select()
    .from(schema.notificationEmailPrefs)
    .where(
      and(
        eq(schema.notificationEmailPrefs.userId, userId),
        eq(schema.notificationEmailPrefs.workspaceId, workspaceId),
      ),
    );
  const byType = new Map(rows.map((r) => [r.notificationType, r]));
  return NOTIFICATION_TYPES.map((t) => {
    const r = byType.get(t);
    return {
      notificationType: t,
      emailEnabled: r?.emailEnabled ?? false, // opt-in: default off
      digestOnly: r?.digestOnly ?? false,
    };
  });
}

/** The single effective pref for one (user, workspace, type). */
export async function getEmailPref(
  db: Db,
  userId: string,
  workspaceId: string,
  notificationType: string,
): Promise<EmailPref> {
  const all = await getEmailPrefs(db, userId, workspaceId);
  return all.find((p) => p.notificationType === notificationType) ?? {
    notificationType,
    emailEnabled: false,
    digestOnly: false,
  };
}

/** Upsert one pref row. */
export async function setEmailPref(
  db: Db,
  input: { userId: string; workspaceId: string; notificationType: string; emailEnabled: boolean; digestOnly: boolean },
): Promise<void> {
  await db
    .insert(schema.notificationEmailPrefs)
    .values(input)
    .onConflictDoUpdate({
      target: [
        schema.notificationEmailPrefs.userId,
        schema.notificationEmailPrefs.workspaceId,
        schema.notificationEmailPrefs.notificationType,
      ],
      set: { emailEnabled: input.emailEnabled, digestOnly: input.digestOnly },
    });
}
```

- [ ] **Step 2: Write `src/lib/email/notify-email.ts`** (the decide-to-send hook)

```ts
import { eq } from 'drizzle-orm';
import type { PostgresJsDatabase } from 'drizzle-orm/postgres-js';
import type { Notification } from '@/db/schema';
import * as schema from '@/db/schema';
import { getEmailPref } from './prefs';
import { renderNotificationEmail } from './templates';
import { emailEnabled, fromAddress, getTransport } from './transport';

type Db = PostgresJsDatabase<typeof schema>;

/**
 * Decide whether a per-event email should go out for one in-app notification,
 * and if so, send it. Best-effort: returns `false` (no send) for any of:
 *   - SMTP unset (email disabled),
 *   - the user's pref has email_enabled = false (in-app only),
 *   - the user's pref is digest_only (the digest scan handles it),
 *   - the recipient has no email address.
 * Sends and returns `true` otherwise. NEVER throws to the caller — the hook
 * is fired fire-and-forget (see notifications/create.ts), mirroring the
 * webhooks emit pattern; a failure is logged, not fatal.
 */
export async function sendNotificationEmail(db: Db, n: Notification): Promise<boolean> {
  try {
    if (!emailEnabled()) return false;
    const pref = await getEmailPref(db, n.userId, n.workspaceId, n.type);
    if (!pref.emailEnabled || pref.digestOnly) return false;

    const [user] = await db
      .select({ email: schema.users.email })
      .from(schema.users)
      .where(eq(schema.users.id, n.userId))
      .limit(1);
    if (!user?.email) return false;

    const transport = getTransport();
    if (!transport) return false;
    const { subject, text, html } = await renderNotificationEmail(n);
    await transport.sendMail({ from: fromAddress(), to: user.email, subject, text, html });
    return true;
  } catch (err) {
    console.error('[email] sendNotificationEmail failed', err);
    return false;
  }
}
```

## Task 4: Digest mode — cron-able scan of unread notifications

**Goal:** `scanDigests(now)` finds users with unread, digest-eligible notifications (pref `digest_only` OR — operator choice — pref `email_enabled` too; this plan scopes the digest to **`digest_only` prefs** so per-event and digest never double-send the same type), batches each user's unread into one email, sends it, and stamps a per-user `digest_sent_at` watermark in `system_meta` so a re-run within the window is **idempotent** (no second email for the same already-digested notifications). Exposed as `pnpm cli email:digest` and an opt-in `CAIRN_DIGEST_INTERVAL` ticker. **External-cron / single-instance ceiling:** the app hosts no cron daemon; external cron invoking the CLI is the recommended path, and the in-process interval ticker is single-instance only (two instances double-fire — documented ceiling, consistent with the collab single-instance ceiling, spec §2.36).

- [ ] **Step 1: Write `src/lib/email/digest.ts`**

```ts
import { and, eq, gt, isNull, sql } from 'drizzle-orm';
import type { PostgresJsDatabase } from 'drizzle-orm/postgres-js';
import * as schema from '@/db/schema';
import { renderDigestEmail } from './templates';
import { emailEnabled, fromAddress, getTransport } from './transport';

type Db = PostgresJsDatabase<typeof schema>;

const WATERMARK_KEY = (userId: string) => `email_digest_sent_at:${userId}`;

/**
 * Batch each user's unread, digest-eligible notifications into one email.
 * Idempotent: only notifications created AFTER the user's stored watermark
 * are included, and the watermark advances to `now` after a successful send,
 * so a re-run in the same window sends nothing. Best-effort — a per-user
 * failure is logged and skipped, never aborting the whole scan.
 *
 * Returns the count of digest emails actually sent.
 */
export async function scanDigests(db: Db, now: Date = new Date()): Promise<number> {
  if (!emailEnabled()) return 0;
  const transport = getTransport();
  if (!transport) return 0;

  // Users who have at least one digest_only pref enabled.
  const digestUsers = await db
    .selectDistinct({ userId: schema.notificationEmailPrefs.userId })
    .from(schema.notificationEmailPrefs)
    .where(eq(schema.notificationEmailPrefs.digestOnly, true));

  let sent = 0;
  for (const { userId } of digestUsers) {
    try {
      const watermark = await getWatermark(db, userId);
      const unread = await db
        .select()
        .from(schema.notifications)
        .where(
          and(
            eq(schema.notifications.userId, userId),
            isNull(schema.notifications.readAt),
            watermark ? gt(schema.notifications.createdAt, watermark) : undefined,
          ),
        );
      if (unread.length === 0) continue;

      const [user] = await db
        .select({ email: schema.users.email })
        .from(schema.users)
        .where(eq(schema.users.id, userId))
        .limit(1);
      if (!user?.email) continue;

      const { subject, text, html } = await renderDigestEmail(unread);
      await transport.sendMail({ from: fromAddress(), to: user.email, subject, text, html });
      await setWatermark(db, userId, now);
      sent += 1;
    } catch (err) {
      console.error('[email] digest for user failed', userId, err);
    }
  }
  return sent;
}

async function getWatermark(db: Db, userId: string): Promise<Date | null> {
  const [row] = await db
    .select({ value: schema.systemMeta.value })
    .from(schema.systemMeta)
    .where(eq(schema.systemMeta.key, WATERMARK_KEY(userId)))
    .limit(1);
  return row?.value ? new Date(row.value) : null;
}

async function setWatermark(db: Db, userId: string, now: Date): Promise<void> {
  await db
    .insert(schema.systemMeta)
    .values({ key: WATERMARK_KEY(userId), value: now.toISOString() })
    .onConflictDoUpdate({
      target: schema.systemMeta.key,
      set: { value: now.toISOString() },
    });
}
```

NOTE: confirm `schema.systemMeta`'s actual column names (`key`/`value`) against `src/db/schema/system-meta.ts` before writing; if it's shaped differently, adjust the two helpers (the watermark store is the only system-meta dependency). If `system_meta` can't hold a per-user key, fall back to a `digest_sent_at timestamptz` column — but that needs a migration owned elsewhere; prefer the `system_meta` key to keep this plan migration-free.

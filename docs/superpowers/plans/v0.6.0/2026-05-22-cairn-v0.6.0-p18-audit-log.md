# Cairn v0.6.0 Plan 18 — Audit log + per-page activity feed

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the **append-only audit log** and the **per-page activity feed**. Replace P17's `recordAudit` stub with the real helper that appends an `audit_log` row *inside the action's own transaction*, then **wire it into every sensitive-action site** (member role change / removal, invite create/revoke, page publish/unpublish, per-page share-setting changes, API-key create/revoke, webhook create/delete, page delete, database delete, transfer-ownership, delete-workspace, template save / version restore). Add an **admin audit viewer** (paginated + filterable, with a JSON API) and a **per-page activity feed** (a read-only view *over* `audit_log` filtered to one page's `target_id`). Enforce the **secret-redaction invariant**: audit metadata must never contain secrets — extend the v0.5.1 secret-leak test to scan `audit_log` rows + the viewer API response.

**Architecture:** The audit log is a single append-only `audit_log` table (per spec §2.27 / §4 `0020`). Writes go through one helper, `recordAudit(tx, {workspaceId, actorId, action, targetType, targetId, metadata, ip?})`, called *inside the same transaction* that performed the audited action so the log can never drift from reality (a rolled-back action rolls back its audit row). The helper is pure + db/tx-injected (mirroring `src/lib/notifications/create.ts` and the comment helpers) so it's unit-testable without HTTP, and it accepts both a `db` and a `tx` (both satisfy the injected `PostgresJsDatabase`/transaction type). **No updates or deletes** at the app layer — append-only is the contract; pruning is a separate explicit admin/CLI action (out of scope here, audited as `audit.pruned` when it lands). `metadata` is `jsonb` carrying **ids / role-names / flags / before-after diffs only — NEVER secrets** (no password/token/secret values, no `secret_encrypted` bytea, no signing keys). The **per-page activity feed** is *not a second store*: it is a query over `audit_log WHERE target_type='page' AND target_id=$pageId` (decision §2.28), surfaced in a `src/components/pages/activity-feed.tsx` panel that links structural/sensitive events to the v0.5.0 version history for content diffs (page content edits are deliberately NOT audited). The admin viewer is an `admin`-gated route group page reading a paginated/filterable JSON API.

**Tech Stack:** No new runtime deps. Drizzle (the `audit_log` schema + table already shipped in P17's `0020`) + Zod v4 for query/body validation + Vitest 4 + Testcontainers (real Postgres) for the helper / wiring / API / redaction tests; an `admin`-gated React Server Component page + a small `'use client'` filter form for the viewer; `requireRole('admin')` / `requirePageAccess` for gating, exactly like every other surface.

**Spec:** `docs/superpowers/specs/2026-05-22-cairn-v0.6.0-design.md` — §2.27 (audit log = append-only `audit_log`, written by one `recordAudit(tx, ...)` at the helper/transaction site; documented `action` set; metadata never secrets), §2.28 (per-page activity feed = a *view over* `audit_log`, content edits not individually audited, feed links to version history), §3 "Admin, observability & ops" in-scope (audit log + viewer + activity feed), §4 `0020` (`audit_log` columns + the two indexes), §5 "Admin / observability / ops" (`src/lib/audit/record.ts`, viewer route, `activity-feed.tsx`), §6 Security (extend the v0.5.1 secret-leak test so secrets never appear in the audit log) and §8 risks (audit-log growth bounded by append-only + no per-keystroke auditing).

- [ ] **Step 3: Replace the stub in `src/lib/audit/record.ts`**

Pattern after `src/lib/notifications/create.ts` (typed `PostgresJsDatabase<typeof schema>` injection that also accepts a transaction; `import * as schema`). Use the **actual** `audit_log` schema export + column names from Step 0.

```ts
import type { PostgresJsDatabase } from 'drizzle-orm/postgres-js';
import * as schema from '@/db/schema';
import type { AuditAction, AuditTargetType } from './actions';

// A db handle OR a transaction both satisfy this (Drizzle's tx is assignable).
type Db = PostgresJsDatabase<typeof schema>;

export type RecordAuditInput = {
  workspaceId: string;
  actorId?: string | null; // null = system/cron
  action: AuditAction;
  targetType?: AuditTargetType | null;
  targetId?: string | null;
  metadata?: Record<string, unknown>;
  ip?: string | null;
};

const FORBIDDEN_SUBSTRINGS = ['AUTH_SECRET', 'cairn_whsec_', 'cairn_sk_', 'token_hash', 'password_hash', 'secret_encrypted'];
const SECRETISH_KEY = /(secret|token|hash|password)/i;

/** Throws if audit metadata appears to carry a secret. Defense-in-depth. */
export function assertAuditMetadataClean(metadata: Record<string, unknown> | undefined): void {
  if (!metadata) return;
  const json = JSON.stringify(metadata);
  for (const bad of FORBIDDEN_SUBSTRINGS) {
    if (json.includes(bad)) throw new Error(`audit metadata contains forbidden token: ${bad}`);
  }
  const live = process.env.AUTH_SECRET;
  if (live && json.includes(live)) throw new Error('audit metadata contains the live AUTH_SECRET');
  for (const [k, v] of Object.entries(metadata)) {
    if (SECRETISH_KEY.test(k) && typeof v === 'string' && /^[A-Za-z0-9+/=_-]{40,}$/.test(v)) {
      throw new Error(`audit metadata key "${k}" looks like a secret blob`);
    }
  }
}

export async function recordAudit(db: Db, input: RecordAuditInput): Promise<schema.AuditLog> {
  assertAuditMetadataClean(input.metadata);
  const [row] = await db
    .insert(schema.auditLog)
    .values({
      workspaceId: input.workspaceId,
      actorUserId: input.actorId ?? null,
      action: input.action,
      targetType: input.targetType ?? null,
      targetId: input.targetId ?? null,
      metadata: input.metadata ?? {},
      ip: input.ip ?? null,
    })
    .returning();
  return row;
}
```

NOTE: if P17's `audit_log` `$inferSelect` type isn't exported as `schema.AuditLog`, use the actual exported type name (or `typeof schema.auditLog.$inferSelect`). If P17's stub had a different parameter shape, keep this richer shape and update P17's already-wired callers (P17 wired transfer/delete-workspace) to match — Step 0 will reveal whether any callers exist; Task 2 re-verifies all wiring.

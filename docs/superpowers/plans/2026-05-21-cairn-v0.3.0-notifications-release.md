# Cairn v0.3.0 Plan 6 — Notifications + release

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the last v0.3.0 feature — **notifications** (a polled feed + unread bell, fed by @mention and comment-reply triggers) — then ship v0.3.0. This plan owns the `notifyMentions` / `notifyCommentReply` helpers that consume the `mentionedUserIds` seam Plan 5 left on `createComment`, the `GET /api/notifications` feed + mark-read route, the bell UI, and the **dual-image release**: the existing workflow must now build + publish BOTH `cairn` and the new `cairn-collab` image. Closes with the (human-run) `v0.3.0` tag.

**Architecture:** Notifications are workspace-scoped rows (`notifications` table) written synchronously inside comment creation. Per spec §4 delivery decision: **polled, not pushed** — the bell polls `GET /api/notifications?unreadOnly=true` every ~30s; there's no coupling to the collab WebSocket. Helpers are pure + db-injected (mirroring `oauth-gate.ts` / comments helpers) so they're unit-testable without HTTP; the feed routes are gated by `requireRole`/`getAuthContext` exactly like every other API surface. The release workflow `.github/workflows/release.yml` already exists and is private-repo-safe (it gates `provenance`/`sbom`/the attestation step on `github.event.repository.visibility == 'public'`). v0.3.0's only workflow change is adding a SECOND build-push (+ meta + attest) for `ghcr.io/<owner>/cairn-collab`, built from `Dockerfile.collab` (created in Plan 1), gated the same way. Homelab deployment goes from 2 containers (cairn + db) to 3 (cairn + cairn-collab + db).

**Tech Stack:** No new runtime deps. Drizzle + Zod + Vitest + Testcontainers for the helpers/routes; React client component (`'use client'`) + `setInterval` polling for the bell; the existing `docker/build-push-action@v6` matrix-style second step for the collab image; curl + docker compose for the smoke; git for the tag.

**Spec:** `docs/superpowers/specs/2026-05-21-cairn-v0.3.0-design.md` (§3 notifications in-scope, §4 notifications table, §5 notifications architecture, §6 security, §8 risk that the release must also build/publish `cairn-collab`).

Mirror the style of `pages.ts` (uuid PK `defaultRandom`, cascade FKs to `users`/`workspaces`, `jsonb`/`timestamp` columns, an index on the read column). Per spec §4:

```ts
import { index, jsonb, pgTable, text, timestamp, uuid } from 'drizzle-orm/pg-core';
import { users } from './users';
import { workspaces } from './workspaces';

export const notifications = pgTable(
  'notifications',
  {
    id: uuid('id').primaryKey().defaultRandom(),
    userId: uuid('user_id')
      .notNull()
      .references(() => users.id, { onDelete: 'cascade' }),
    workspaceId: uuid('workspace_id')
      .notNull()
      .references(() => workspaces.id, { onDelete: 'cascade' }),
    type: text('type').notNull(), // 'mention' | 'comment_reply'
    payload: jsonb('payload').$type<NotificationPayload>().notNull(),
    readAt: timestamp('read_at', { withTimezone: true }),
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  },
  (t) => ({
    userUnreadIdx: index('notifications_user_unread_idx').on(t.userId, t.readAt),
  }),
);

export type NotificationType = 'mention' | 'comment_reply';
export type NotificationPayload = {
  pageId: string;
  commentId: string;
  actorId: string;
};

export type Notification = typeof notifications.$inferSelect;
export type NewNotification = typeof notifications.$inferInsert;
```

## Task 2: Notification helpers — `notifyMentions` + `notifyCommentReply`

**Goal:** Pure, db-injected helpers that write `notifications` rows. `notifyMentions` writes one `mention` per mentioned user (skip self, dedupe); `notifyCommentReply` writes one `comment_reply` per prior thread participant (the page's existing distinct comment authors other than the actor; skip self, dedupe).

`notifyMentions(db, { actorId, pageId, commentId, workspaceId, mentionedUserIds })`:
- writes one `mention` row per id in `mentionedUserIds`, each with `type: 'mention'`, `payload: { pageId, commentId, actorId }`, `readAt: null`;

- **skip-self**: the actor is never notified even if they authored earlier comments;
- **dedupe**: a user who left 3 prior comments gets exactly one notification;
- when the actor is the only/first commenter (no prior others), writes nothing;
- payload `{ pageId, commentId, actorId }`, `type: 'comment_reply'`, `readAt: null`.

- [ ] **Step 2: Write `src/lib/notifications/create.ts`**

Pattern after `src/lib/auth/oauth-gate.ts` (typed `PostgresJsDatabase<typeof schema>` injection, `import * as schema`). Sketch:

```ts
import { and, eq, ne } from 'drizzle-orm';
import type { PostgresJsDatabase } from 'drizzle-orm/postgres-js';
import * as schema from '@/db/schema';

type Db = PostgresJsDatabase<typeof schema>;

export async function notifyMentions(
  db: Db,
  input: {
    actorId: string;
    pageId: string;
    commentId: string;
    workspaceId: string;
    mentionedUserIds: string[] | undefined;
  },
): Promise<schema.Notification[]> {
  const targets = [...new Set(input.mentionedUserIds ?? [])].filter((id) => id !== input.actorId);
  if (targets.length === 0) return [];
  return db
    .insert(schema.notifications)
    .values(
      targets.map((userId) => ({
        userId,
        workspaceId: input.workspaceId,
        type: 'mention',
        payload: { pageId: input.pageId, commentId: input.commentId, actorId: input.actorId },
      })),
    )
    .returning();
}

export async function notifyCommentReply(
  db: Db,
  input: { actorId: string; pageId: string; commentId: string; workspaceId: string },
): Promise<schema.Notification[]> {
  // Prior distinct comment authors on this page, excluding the actor.
  const rows = await db
    .selectDistinct({ authorId: schema.comments.authorId })
    .from(schema.comments)
    .where(and(eq(schema.comments.pageId, input.pageId), ne(schema.comments.authorId, input.actorId)));
  const targets = [...new Set(rows.map((r) => r.authorId))];
  if (targets.length === 0) return [];
  return db
    .insert(schema.notifications)
    .values(
      targets.map((userId) => ({
        userId,
        workspaceId: input.workspaceId,
        type: 'comment_reply',
        payload: { pageId: input.pageId, commentId: input.commentId, actorId: input.actorId },
      })),
    )
    .returning();
}
```

NOTE: confirm the comments table/column names against what Plan 4 shipped (`schema.comments`, `authorId`, `pageId`). If `selectDistinct` on the author column isn't available in the Drizzle version, fall back to a `select` + JS `Set` dedupe. The `comment_reply` "prior author" query intentionally includes the just-inserted comment's row too, but since that row's author IS the actor it's filtered by `ne(authorId, actorId)` — so calling this AFTER inserting the new comment is correct.

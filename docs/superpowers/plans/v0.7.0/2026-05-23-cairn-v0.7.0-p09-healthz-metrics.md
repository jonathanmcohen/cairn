# Cairn v0.7.0 — Plan P9: Open `/healthz` + new MCP/embedding/automation/connector metric series

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two things in one plan:
1. A new always-open `GET /healthz` endpoint that returns `{status, version, db, uptime_seconds}` — for K8s liveness probes and load-balancer health checks. Touches the DB with `SELECT 1` and returns 503 on DB failure. The v0.6 `/api/health` route stays for backward compatibility; `/healthz` is the new canonical endpoint at the root (no `/api/` prefix).
2. Extend the v0.6 P20 `prom-client` registry with the new v0.7.0 metric series — MCP, embedding, automation, and connector — all with **closed `labelNames` lists containing no tenant/user/page identifiers** (extending P20's leak guard). The `/metrics` token gate from v0.6 P20 stays unchanged.

**Architecture:**
- `src/app/healthz/route.ts` — single `GET` handler at the root (no auth, no token gate). Calls `getDb().execute(sql\`SELECT 1\`)` inside a `try/catch`; tracks process uptime via the difference between `Date.now()` and a module-level `START_TIME` captured at load. Returns `200 { status: 'ok', ... }` on DB green, `503 { status: 'degraded', db: 'unreachable', ... }` on DB red. Mirrors the existing `/api/health` shape but moves to the K8s-canonical `/healthz` path. The existing `/api/health` route is NOT removed (a separate plan can deprecate it later).
- `src/lib/observability/metrics.ts` (existing from v0.6 P20) — extended with seven new metric instances. Each carries a `labelNames` array containing ONLY closed-enum label keys (`tool`, `outcome`, `provider`, `action_type`, `kind`). No tenant/user/page identifiers. New record helpers (`incMcpTool`, `incEmbedding`, `incAutomationRule`, `incConnectorSync`) are exported for the dispatcher / pipeline / engine to call in P6, P12, P16, P19. The v0.6 P20 leak-guard test is extended to assert the new labels stay clean.

**Tech Stack:** Next 16 route handler (nodejs runtime). `prom-client` already a dep from v0.6 P20. No new deps.

**Spec:** `docs/superpowers/specs/2026-05-23-cairn-v0.7.0-design.md` Section 2.8 (open `/healthz` + token-gated `/metrics` stays), Section 3 G3 (`/healthz` shape, new metrics added to the P20 registry — bounded cardinality `tool` from closed registry), Section 5.4 (the seven new metric series + closed labelNames). Plan slot: index P9. **Depends on:** v0.6 P20 (registry + leak guard test). **Optional precedence:** P6 will start *recording* `mcp_tool_called_total` once it lands; the metric helper here registers the series so it's safe for P6 to call.

/**
 * The closed-enum outcomes vocabulary for MCP tool calls (per spec §5.4):
 * success | scope_denied | allowlist_denied | acl_denied | handler_error
 * The dispatcher (P6) emits these strings; callers MUST NOT pass arbitrary
 * outcome values — the cardinality guarantee depends on this being a closed
 * set.
 */
export type McpOutcome =
  | 'success'
  | 'scope_denied'
  | 'allowlist_denied'
  | 'acl_denied'
  | 'rate_limited'
  | 'handler_error';

export type EmbeddingProvider = 'local' | 'remote';
export type ConnectorKind = 'google_sheets' | 'airtable' | 'csv';
export type AutomationActionType = 'notify' | 'send_webhook' | 'set_property' | 'create_page';

export function incMcpTool(s: { tool: string; outcome: McpOutcome; durationSec: number }): void {
  const labels = { tool: s.tool, outcome: s.outcome };
  mcpToolTotal.inc(labels);
  mcpToolDuration.observe({ tool: s.tool }, s.durationSec);
}

export function incEmbedding(s: {
  provider: EmbeddingProvider;
  outcome: 'success' | 'failed';
  durationSec: number;
}): void {
  embeddingTotal.inc({ provider: s.provider, outcome: s.outcome });
  embeddingDuration.observe({ provider: s.provider }, s.durationSec);
}

export function incAutomationRule(s: {
  actionType: AutomationActionType;
  outcome: 'success' | 'failed' | 'condition_unmet';
}): void {
  automationRuleTotal.inc({ action_type: s.actionType, outcome: s.outcome });
}

export function incConnectorSync(s: {
  kind: ConnectorKind;
  outcome: 'success' | 'failed' | 'conflict';
  durationSec: number;
}): void {
  connectorSyncTotal.inc({ kind: s.kind, outcome: s.outcome });
  connectorSyncDuration.observe({ kind: s.kind }, s.durationSec);
}

- [x] **Step 3: Write `src/app/healthz/route.ts`**

```ts
import { sql } from 'drizzle-orm';
import { NextResponse } from 'next/server';
import { getDb } from '@/db/client';
import { appVersion } from '@/lib/version';

// Always-open liveness endpoint. NO auth, NO token gate. Suitable for K8s
// liveness probes and load-balancer health checks at the root path.
//
// CONTRACT (spec §2.8 + §3 G3):
//   GET /healthz → 200 { status: 'ok',       version, db: 'ok',          uptime_seconds }
//                  503 { status: 'degraded', version, db: 'unreachable', uptime_seconds }
//
// The DB touch is a cheap `SELECT 1`; on connection failure the route returns
// 503 so the LB sheds traffic from a broken replica.
export const runtime = 'nodejs';
export const dynamic = 'force-dynamic';

const START_TIME_MS = Date.now();

function uptimeSeconds(): number {
  return Math.floor((Date.now() - START_TIME_MS) / 1000);
}

export async function GET(): Promise<Response> {
  let dbStatus: 'ok' | 'unreachable' = 'unreachable';
  try {
    await getDb().execute(sql`SELECT 1`);
    dbStatus = 'ok';
  } catch {
    dbStatus = 'unreachable';
  }
  const body = {
    status: dbStatus === 'ok' ? ('ok' as const) : ('degraded' as const),
    version: appVersion(),
    db: dbStatus,
    uptime_seconds: uptimeSeconds(),
  };
  return NextResponse.json(body, { status: dbStatus === 'ok' ? 200 : 503 });
}
```

- **Module-load timestamp:** the `START_TIME_MS` at module load is the simplest pattern. In test mode `vi.resetModules()` will re-run module load, so each test sees a fresh start time — that's fine; uptime is non-negative either way.

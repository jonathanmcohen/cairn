# Cairn v0.7.0 — Plan P3: Page ACL resolver + `requirePageAcl` helper + tests

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve effective permission for `(userId, pageId)` against `page_acls` with inheritance through the page tree, and a workspace-role fallback when no ACL is set. **Owner role bypasses the ACL chain entirely.** Wrapped in a `requirePageAcl(pageId, minPermission)` helper that mirrors v0.6 `requirePageAccess` as a SIBLING (not a replacement) — v0.7 routes opt in.

**Architecture:** A pure, db-injected lib (`src/lib/pages/acl.ts`) wrapping one recursive CTE: walk `pages.parent_id` from `pageId` upward and LEFT JOIN `page_acls` on `user_id = $userId`. Return the first non-null permission encountered (deepest first → walking outward = ancestor-deep override → caller picks the first row). If no ACL hits anywhere up the chain, fall back to the user's workspace role from `workspace_members`: `owner` → `'owner'` (the bypass), `admin` / `editor` → `'edit'`, `viewer` → `'view'`. The min-permission gate enforces a partial order (`view < comment < edit < owner`) — owner is also `edit` for any consumer that gates on `'edit'`.

The lib lives next to `src/lib/pages/access.ts` (v0.6 `requirePageAccess`) but does NOT replace it. v0.6 routes keep calling `requirePageAccess`; v0.7-only routes (MCP tool handlers, dev settings, future ACL-aware endpoints) call `requirePageAcl`. Co-existing buys: v0.6 routes don't regress; v0.7 routes get the ACL inheritance.

**Tech Stack:** Drizzle `db.execute(rawSql\`...\`)` for the recursive CTE (canonical Cairn pattern — see `src/lib/pages/delete.ts`, `src/lib/pages/move.ts`, `src/lib/pages/duplicate.ts`). No new deps.

**Spec:** `docs/superpowers/specs/2026-05-23-cairn-v0.7.0-design.md` (§2.4 page-permission precedence, §3 G1 "Page ACL resolver").

```ts
import { sql as rawSql } from 'drizzle-orm';
import type { PostgresJsDatabase } from 'drizzle-orm/postgres-js';
import * as schema from '@/db/schema';

/**
 * Effective permission tier returned by the resolver. Ordered for the
 * min-permission gate in requirePageAcl: 'view' < 'comment' < 'edit' < 'owner'.
 * 'owner' is the workspace-owner bypass; routes that gate on 'edit' accept
 * 'owner' transparently via the comparator below.
 */
export type EffectivePermission = 'view' | 'comment' | 'edit' | 'owner';

const ORDER: Record<EffectivePermission, number> = {
  view: 1,
  comment: 2,
  edit: 3,
  owner: 4,
};

export function permissionAtLeast(
  actual: EffectivePermission,
  required: EffectivePermission,
): boolean {
  return ORDER[actual] >= ORDER[required];
}

const UUID_RE = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

type Row = { permission: 'view' | 'comment' | 'edit' | null; depth: number };
type RoleRow = { role: schema.MemberRole };

/**
 * Walk pages.parent_id upward from pageId. For each level, LEFT JOIN
 * page_acls(user_id = $userId). Return the deepest (closest-to-pageId)
 * non-null permission. If no ACL exists anywhere in the chain, fall back to
 * the user's workspace role:
 *   - owner   → 'owner'  (workspace-wide bypass)
 *   - admin   → 'edit'
 *   - editor  → 'edit'
 *   - viewer  → 'view'
 *   - no membership → null
 *
 * Returns null for an unknown / malformed pageId.
 */
export async function resolveEffectivePermission(
  db: PostgresJsDatabase<typeof schema>,
  args: { userId: string; pageId: string },
): Promise<EffectivePermission | null> {
  if (!UUID_RE.test(args.pageId)) return null;
  if (!UUID_RE.test(args.userId)) return null;

  // Recursive CTE: start at the target page, walk up via parent_id, LEFT JOIN
  // page_acls. depth=0 is the target page; deeper depth = farther ancestor.
  // ORDER BY depth ASC then LIMIT 1 returns the nearest non-null ACL.
  const aclRows = (await db.execute(rawSql`
    WITH RECURSIVE chain(id, parent_id, depth) AS (
      SELECT id, parent_id, 0 FROM pages WHERE id = ${args.pageId}::uuid
      UNION ALL
      SELECT p.id, p.parent_id, c.depth + 1
        FROM pages p
        INNER JOIN chain c ON p.id = c.parent_id
    )
    SELECT acl.permission AS permission, c.depth AS depth
      FROM chain c
      LEFT JOIN page_acls acl
        ON acl.page_id = c.id AND acl.user_id = ${args.userId}::uuid
     WHERE acl.permission IS NOT NULL
     ORDER BY c.depth ASC
     LIMIT 1
  `)) as unknown as Row[];

  if (aclRows.length > 0) {
    const hit = aclRows[0];
    if (hit?.permission === 'view' || hit?.permission === 'comment' || hit?.permission === 'edit') {
      return hit.permission;
    }
  }

  // No ACL anywhere up the chain. Resolve the workspace role via the page's
  // workspace_id (one extra round-trip; cached per request by callers).
  const roleRows = (await db.execute(rawSql`
    SELECT wm.role AS role
      FROM pages p
      INNER JOIN workspace_members wm ON wm.workspace_id = p.workspace_id
     WHERE p.id = ${args.pageId}::uuid AND wm.user_id = ${args.userId}::uuid
     LIMIT 1
  `)) as unknown as RoleRow[];

  const row = roleRows[0];
  if (!row) return null;
  switch (row.role) {
    case 'owner':
      return 'owner';
    case 'admin':
    case 'editor':
      return 'edit';
    case 'viewer':
      return 'view';
    default:
      return null;
  }
}
```

### Allowed deviations (Task 2)

- If a future page-tree change introduces an alternative parent column (e.g. a hard-link or symlink table), this CTE walks ONLY `pages.parent_id`. That matches the spec — ACLs are tree-scoped, not graph-scoped.
- The fallback queries the workspace role through the page itself. An alternative is to require the caller to pass `workspaceId` so this lib doesn't re-query — but the calling sites (MCP handlers, future routes) don't always have it on hand. Keep the round-trip; React `cache()`-wrap at the call site if needed.
- The CTE uses `LEFT JOIN`; using `INNER JOIN` would never return rows for pages without an ACL match (the desired behavior — we explicitly want the no-ACL-row case to fall out and trigger the role fallback). Do not refactor to INNER.

```ts
import { and, eq, isNull } from 'drizzle-orm';
import { getDb } from '@/db/client';
import { getAuthContext, HttpError, type WorkspaceContext } from '@/lib/auth/require-role';

export type PageAclAccess = {
  page: schema.Page;
  ctx: WorkspaceContext;
  effectivePermission: EffectivePermission;
};

/**
 * v0.7 sibling of v0.6 requirePageAccess. Validates the page exists in the
 * active workspace, resolves the user's effective permission via the ACL
 * resolver, and gates on minPermission.
 *
 * - 404 for non-UUID pageId (no DB cast error)
 * - 404 for cross-workspace pageId (no existence leak)
 * - 403 when effectivePermission < minPermission
 * - returns {page, ctx, effectivePermission} otherwise
 *
 * Does NOT replace requirePageAccess — v0.6 routes keep their role-based gate.
 * New v0.7 routes opt into ACL-aware access by calling this instead.
 */
export async function requirePageAcl(
  pageId: string,
  minPermission: EffectivePermission,
): Promise<PageAclAccess> {
  const auth = await getAuthContext();
  if (!auth?.workspaceId || !auth.userId) {
    throw new HttpError(401, 'Unauthenticated');
  }
  if (!UUID_RE.test(pageId)) {
    throw new HttpError(404, 'Page not found');
  }
  const db = getDb();
  const [page] = await db
    .select()
    .from(schema.pages)
    .where(and(eq(schema.pages.id, pageId), isNull(schema.pages.deletedAt)))
    .limit(1);
  if (!page) throw new HttpError(404, 'Page not found');
  if (page.workspaceId !== auth.workspaceId) {
    // Same status as not-found to avoid leaking page existence across workspaces.
    throw new HttpError(404, 'Page not found');
  }

  const permission = await resolveEffectivePermission(db, {
    userId: auth.userId,
    pageId,
  });
  if (!permission) {
    throw new HttpError(403, 'No access to this page');
  }
  if (!permissionAtLeast(permission, minPermission)) {
    throw new HttpError(403, `Requires ${minPermission} permission`);
  }

  return {
    page,
    ctx: { userId: auth.userId, workspaceId: auth.workspaceId, role: auth.role },
    effectivePermission: permission,
  };
}
```

# G13 Audit Polish (See-Also Emoji / Search Subtitle / Truncation Tooltips) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to execute this plan — one implementer subagent per task, fresh context, full task text pasted in; the main thread reviews and commits between tasks.

**Goal:** Three independent polish fixes uncovered in the post-v0.9.6 audit:
- **V (MEDIUM):** The vector "See also" panel renders the raw `emoji::` shortcode before a related page's title — the same root cause as the originally-fixed page-icon bug (#1), but on a code path (`see-also-panel.tsx`) that never routed `pages.icon` through the shortcode parser. Fix: parse `r.icon` through `parseIcon` in the row, matching the sidebar's `renderNodeIcon`.
- **W (LOW):** The sidebar search button's label carries a tiny `(command palette)` parenthetical that renders sub-12px and reads as redundant noise beside the ⌘K badge. Fix: drop the parenthetical from the label string (the `⌘K` `<kbd>` already signals it is the palette) across all three locales.
- **X (LOW):** Truncated page names in the sidebar tree (`Unt…`, `Copy of …`) have no way to reveal the full title. Fix: add a native `title` attribute carrying the full title to the truncating `<span>` so a hover tooltip appears, with no new dependency or focus-trap risk.

**Architecture:** All three are surgical, self-contained UI fixes in existing client/server components plus message-catalog edits. No schema, no API, no migration. V touches one RSC and its existing jsdom test. W touches three JSON catalogs and the existing search-hint behavior (no new string, only an edit to existing values). X touches one client component and adds one jsdom assertion. The shortcode parser (`src/lib/pages/icon-format.ts#parseIcon`) and the sidebar's existing `renderNodeIcon` helper are the reference implementations — V mirrors them so the `emoji::`/`file::` prefix never leaks into the DOM.

**Tech Stack:** Next.js 16 App Router (RSC + client components), React 19, TypeScript 6 strict, Vitest 4 (jsdom for these component tests — no Testcontainers needed since none of the three fixes touch the DB), `@testing-library/react`, Biome v2, i18n via `useT()` with `messages/{en,es,ar}.json`.

## Task V — See-also panel: route page icon through `parseIcon`

The "See also" row renders `{r.icon ?? '📄'}` raw (`src/components/pages/see-also-panel.tsx` line ~56). `findRelatedPages` returns `icon: string | null` straight from `pages.icon` (`src/lib/search/see-also.ts` line ~91), which may be a `emoji::📄` / `file::<uuid>` shortcode. We mirror the sidebar's `renderNodeIcon` (`src/components/sidebar/virtualized-page-tree.tsx` lines ~21-26): run `parseIcon`, render the emoji value, and show a neutral 🖼️ placeholder for file-backed icons (the panel is a compact list — a signed `<img>` is out of scope and would pull `env()`/`signFileUrl` into an RSC that the existing test mocks without env). `📄` stays the null fallback.

Add a module-level render helper directly below the imports / above the `SeeAlsoPanelProps` type, mirroring the sidebar's `renderNodeIcon`:

```ts
/**
 * Render a related page's stored icon string. Routes through `parseIcon` so the
 * `emoji::`/`file::` shortcode prefix never leaks into the DOM (the bug fixed in
 * the page-icon polish, now applied to this code path too). File-backed icons
 * collapse to a neutral placeholder here — the compact panel intentionally does
 * not resolve signed image URLs.
 */
function renderRelatedIcon(stored: string | null): React.ReactNode {
  const parsed = parseIcon(stored);
  if (!parsed) return '📄';
  if (parsed.kind === 'emoji') return parsed.value;
  return '🖼️';
}
```

Then replace the raw render in the row. Change:

```tsx

```

to:

```tsx

```

## Task X — Sidebar tree: hover tooltip (native `title`) for truncated page names

The page row's title renders in `<span className="min-w-0 flex-1 truncate">{node.title}</span>` (`src/components/sidebar/virtualized-page-tree.tsx` line ~295). When the name overflows it shows `Copy of …` with no way to read the full title. The lightest, focus-trap-free fix is a native `title` attribute carrying `node.title` — browsers render the full string as a hover tooltip with no new dependency and no layout/measurement cost (a shadcn/radix `Tooltip` would require a `Tooltip.Provider` per virtualized row and is overkill for a passive reveal). We also add it to the space-header name span (`<span className="truncate">{row.name}</span>`, line ~203) for the same reason. No new user-facing string — the tooltip shows the existing title verbatim.

**Files:**
- Modify: `src/components/sidebar/virtualized-page-tree.tsx`
- Test: `tests/components/sidebar/virtualized-page-tree-title-tooltip.test.tsx` (new)

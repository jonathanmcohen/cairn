# G7 — DB Views + Sidebar Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Polish the database "+ Add view" dropdown (per-type icons + disabled-state tooltips), tighten the empty-database state (emphasised "Add your first row" CTA + row-count, less dead vertical space), and clarify the sidebar search label so it advertises the full command palette it actually opens.

**Architecture:** All three fixes are UI-layer only — no schema, no API, no migration. `ViewSwitcher` (`src/components/databases/view-switcher.tsx`) already renders a shadcn/Radix `<Select>` for adding views; we add lucide icons per `SelectItem` and a native `title` tooltip on the disabled calendar/timeline items (Radix `SelectItem` spreads `...props` to the DOM node, so `title` works without a new Tooltip component). `TableView` (`src/components/databases/table-view.tsx`) already has a zero-rows branch; we restructure it to lead with the CTA and drop the redundant centered hint, and pluralise the row count via the existing `database.rowCount` ICU plural key. `SearchHintButton` (`src/components/search-hint-button.tsx`) already dispatches ⌘K and names the palette in its aria-label; we only rename the visible `searchHint.label` string (en/es/ar) so the label matches the palette behaviour while the ⌘K `<kbd>` stays.

**Tech Stack:** React 19 / Next 16 (client components), shadcn/ui Radix `<Select>`, lucide-react icons, the in-repo i18n `useT()` (`src/lib/i18n/provider`) backed by `messages/{en,es,ar}.json`, Vitest 4 + `@testing-library/react` under jsdom (`// @vitest-environment jsdom`).

**Closes:** #84, #142, #143, #144

# G6c — Sidebar Page-Tree Rows Clickable Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make every sidebar page-tree row navigate to `/pages/[id]` on click and on Enter/Space, while the trailing `…`/`+` action cluster keeps working without itself triggering navigation.

**Architecture:** The page row lives in `src/components/sidebar/virtualized-page-tree.tsx` (`PageTreeRow`, ~line 224, called once per visible virtualizer item). The row already renders a `<Link href={\`/pages/${id}\`}>`, but that Link is a `flex-1` sibling that only spans the icon+title — the row's `pr-1` padding band and the always-mounted (opacity-0) `PageRowActionsMenu` cluster are non-navigating dead zones, and the cluster's `min-h-11 min-w-11` (44px) buttons are taller than the 32px row so their hit area bleeds over it. The fix converts the row's leading area so the **entire row hit-target** navigates: the `<Link>` becomes a full-bleed positioned overlay (covering icon, title, and the padding band) with the icon/title rendered visually on top, and the action cluster sits above it (`relative z-10`) and `stopPropagation`s on its own buttons so clicking `…`/`+` never navigates. The row also gains `role`-less native semantics by keeping the single `<Link>` as the only navigating element (no nested interactives), and Enter activation comes from the Link itself being focusable.

**Tech Stack:** Next.js 16 / React 19 / TS6 strict, `next/link` + typed routes (`as Route`), `@tanstack/react-virtual`, radix-ui (DropdownMenu/ContextMenu), Tailwind v4 (`@theme` in `globals.css`), Vitest 4 (jsdom for components), Biome v2, i18n flat-dot-key catalogs in `messages/{en,es,ar}.json`.

## Background — the real cause (read before Task 2)

Confirmed by reading the source (do NOT re-guess):

- `PageTreeRow` (`src/components/sidebar/virtualized-page-tree.tsx`, lines 224–286) renders, inside a `PageRowContextMenu` wrapper, a `<div className="group flex items-center gap-1 rounded pr-1 …">`. Inside that flex row, when **not** renaming, it renders TWO siblings:
  1. `<Link href={\`/pages/${node.id}\`} className="flex min-w-0 flex-1 items-center gap-2 py-1">` — icon + title. This is the ONLY navigating element.
  2. `<span className="shrink-0 opacity-0 … group-hover:opacity-100 …"><PageRowActionsMenu …/></span>` — the `+`/`…` cluster, **always mounted** (revealed via opacity, never `hidden`).
- The Link is `flex-1` but NOT full-bleed: it does not cover (a) the row's `pr-1` right padding band, nor (b) the horizontal strip occupied by the always-present action `<span>`. Those regions render no navigating element, so a click there does nothing.
- `PageRowActionsMenu` buttons (`src/components/sidebar/page-row-actions-menu.tsx`, `ICON_BTN`) are `min-h-11 min-w-11` = **44px** tall, but `ROW_HEIGHT_PX = 32`. The cluster `<span>` therefore overflows the 32px row vertically; because it is always in the DOM (opacity-0, full layout box), its 44px hit area overlaps the row above/below and steals clicks even when visually invisible. The `…` trigger and `+` button already `stopPropagation`, but the row itself has no click handler to propagate TO — so the net effect is large dead/ambiguous zones where clicking the row does not navigate.
- This regressed in the v0.9.4 row-action work (Task 2/3 added the always-mounted hover cluster + 44px touch targets next to the Link instead of giving the row a single full-bleed navigation target).

**Fix strategy:** Make the `<Link>` a full-bleed `absolute inset-0` overlay that covers the whole row (it becomes the row's single navigation hit-target and is keyboard-focusable → Enter/Space navigate for free). Render the icon + title visually on top of it (`pointer-events-none`, so they don't intercept clicks but the Link underneath receives them). Render the action cluster as a `relative z-10` sibling so it sits ABOVE the overlay and receives its own clicks; its buttons keep `stopPropagation`. Net: clicking anywhere on the row navigates; clicking `+`/`…` does not.

// tests/components/sidebar/virtualized-page-tree.test.tsx so the row renders.
beforeAll(() => {
  const H = 600;
  const W = 240;
  Object.defineProperty(HTMLElement.prototype, 'offsetHeight', {
    configurable: true,
    get(this: HTMLElement) {
      return this.classList?.contains?.('overflow-y-auto') ? H : 0;
    },
  });

    configurable: true,
    get(this: HTMLElement) {
      return this.classList?.contains?.('overflow-y-auto') ? W : 0;
    },
  });
  if (typeof globalThis.ResizeObserver === 'undefined') {
    class NoopResizeObserver {
      observe(): void {}
      unobserve(): void {}
      disconnect(): void {}
    }
    (globalThis as unknown as { ResizeObserver: typeof NoopResizeObserver }).ResizeObserver =
      NoopResizeObserver;
  }
});

afterEach(cleanup);

    // assert it is a genuine anchor with href (not a div with onClick).

    expect((cluster as HTMLElement).className).toMatch(/z-10/);

# UI/UX Polish (G23) Implementation Plan

REQUIRED SUB-SKILL: superpowers:test-driven-development

**Goal:** Resolve **#170** (v0.9.7 G23). A `ui-ux-pro-max` review surfaced six classes of low-level polish defects across already-shipped surfaces. This plan fixes them in bite-sized, test-first slices: (1) replace emoji "structural" glyphs (📄 🖼️ ✕ ↵ ↑ ↓ ▸ ▾) with crisp, theme-aware lucide SVG icons in the sidebar page tree + move-to picker, the suggestions drawer + link popover, the database sort-config / virtualized-row-body / list-view, the automation condition group, and the icon-picker neutral fallback; (2) add accessible loading states (a `Loader2` spinner + `disabled` while a request is in flight, `motion-reduce:animate-none` so the spin honours `prefers-reduced-motion`) to the async save/mark actions in move-to picker, sidebar row actions, the security two-factor card, the cover picker, the automation test panel + rule canvas save, and the notifications drawer mark-read / mark-all; (3) give empty result sets a real empty-state instead of a bare line (database gallery view, the automation notify / set-property pickers, the cover-picker Unsplash tab); (4) raise sub-12px text (`text-[10px]` / `text-[11px]`) to `text-xs` (12px) in the calc-footer row, list-view calc footer, calendar view, and the notification bell badge so it clears the WCAG-aligned minimum-legible-size bar; (5) add `title` tooltips to truncated text in the list-view rows, the notifications drawer + page-list rows, the members table, and the SIEM forwarders view so clipped labels are still readable on hover; (6) wire a single-image lightbox into the editor image block so a standalone image opens full-screen (reusing the existing gallery `Lightbox`). Target release: **v0.9.7**.

**Architecture:** Every touched surface is an existing client component. Icons come from `lucide-react` (already a dependency; `FileText`, `Image as ImageIcon`, `X`, `CornerDownLeft`, `ArrowUp`, `ArrowDown`, `ChevronRight`, `ChevronDown`, `Loader2`). The shared spinner pattern is `<Loader2 aria-hidden className="h-4 w-4 animate-spin motion-reduce:animate-none" />` rendered inside an already-`disabled` button while a `busy` boolean is true — Tailwind v4 ships the `motion-reduce:` variant, so no new CSS. Empty states reuse the canonical `EmptyState` card (`src/components/empty-state/empty-state.tsx`) or the database-specific bare-card pattern, driven by `useT()`. The single-image lightbox reuses `src/components/editor/lightbox.tsx` (portal-mounted, focus-trapped, `images: {src,alt}[]` + `startIndex`) exactly as `src/components/editor/blocks/gallery.tsx` does — `ImageView` passes a one-element array. The icon-picker keeps its emoji *value* rendering (a chosen emoji is real content, not structural chrome) and only swaps the **no-icon fallback** glyph for `FileText` and the file-kind placeholder for `ImageIcon`. Several touched components currently hardcode English (`sort-config.tsx`, `virtualized-row-body.tsx`, `list-view.tsx`, `two-factor-card.tsx`, the notifications `drawer.tsx`); for those, every NEW user-facing string this plan introduces (and every existing hardcoded string adjacent to a line we are already editing) is routed through `useT()` with a key added to all three catalogs.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript 6 (strict), Drizzle/Postgres, Auth.js v5, Biome v2 (no eslint), Vitest 4 + jsdom + `@testing-library/react` (component tests) and Testcontainers (DB tests), TipTap 3, Tailwind v4 + shadcn/ui. i18n via `useT()` from `@/lib/i18n/provider`; component tests wrap the unit under test in `<I18nProvider locale="en" messages={enMessages}>` (importing `enMessages` from `messages/en.json`); every new user-facing string lands in `messages/en.json`, `messages/es.json`, `messages/ar.json`. No native `confirm`/`alert`/`prompt` — themed dialogs live in `src/components/ui/`. The settings nav lives in `src/components/settings/sidebar.tsx` (`SECTIONS`) — untouched by this plan. No new DB migration is needed (latest is `0056`; the next would be `0057`). Tests run with `pnpm vitest run <path>`; lint with `pnpm lint`; typecheck with `pnpm typecheck`. All shell commands are prefixed `source ~/.zshenv && `.

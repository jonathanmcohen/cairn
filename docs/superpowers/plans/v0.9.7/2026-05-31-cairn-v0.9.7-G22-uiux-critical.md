# UI/UX Critical Accessibility Fixes Implementation Plan

REQUIRED SUB-SKILL: superpowers:test-driven-development

**Goal:** Close the CRITICAL accessibility findings from the `ui-ux-pro-max` review for v0.9.7. Concretely: (1) honor `prefers-reduced-motion` globally so animations/transitions stop for users who request reduced motion (WCAG 2.3.3); (2) restore a visible keyboard focus indicator on five surfaces that suppress it with `outline-hidden`/`outline-none` (`cell-editor`, `relation-cell`, `property-panel`, `search-palette`) and add `focus-visible` rings to the bare-hover links/buttons in five sidebar/editor components (WCAG 2.4.7); (3) raise dark-mode contrast so `--destructive` text reads ≥ 4.5:1 on `--card` and replace six raw light-only red/green banners with semantic tokens that carry proper dark variants (WCAG 1.4.3); (4) bump the base `Button`/`Input` minimum height toward the 44×44 px touch-target floor (WCAG 2.5.5 / 2.5.8); (5) gate two irreversible admin actions (`upgrade-apply-button`, `workspace-e2e-toggle`) behind the themed `ConfirmDialog` instead of firing on first click; (6) add a real focus-trap + Esc handler to the command palette (`search-palette`) and the cover-picker custom modal (`cover-picker`); (7) give the two 2FA inputs real `<label>` elements instead of placeholder-only labelling (WCAG 1.3.1 / 4.1.2). Resolves **#169**. Target release: **v0.9.7**.

**Architecture:**

- **Reduced-motion is a single global CSS block.** Tailwind v4 is CSS-first (`@theme` in `src/app/globals.css`, no `tailwind.config.*`). The reduced-motion guard is a plain `@media (prefers-reduced-motion: reduce)` block appended to `globals.css` that neutralizes `animation`/`transition` durations app-wide; it does not touch component code. The existing `comment-anchor-flash` keyframes animation is covered by the same block. We keep `scroll-behavior: auto` in the same guard so smooth-scroll respects the preference too.
- **Focus rings are theme-token-driven.** `globals.css` already installs a global `:focus-visible { outline: 2px solid hsl(var(--ring)); }` for most controls but explicitly exempts `.ProseMirror`/`.cairn-slash-popup`. The five inputs that hard-suppress focus with `outline-hidden`/`outline-none` win the cascade because the utility sets `outline-style: none` at a higher specificity than the layered base rule. The fix replaces those utilities with `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-1` (and `focus-visible:outline-none` to suppress the doubled native outline) on each element — a per-element ring that survives regardless of the base layer. The five bare-hover links/buttons get the same ring utilities added (they currently have `hover:bg-accent` but no keyboard affordance). The `--ring` token already adapts light/dark and per-accent, so no token work is needed for focus.
- **Dark-mode contrast uses tokens, not raw colors.** Two distinct problems: (a) the `.dark` `--destructive` token is `0 62.8% 30.6%` (a dark red) which, used as *text* on the `.dark` `--card` (`240 10% 3.9%`, near-black), is ~3:1 — below AA. We bump the `.dark --destructive` lightness to `0 72% 58%` (a brighter red, ~5.2:1 on the dark card) while leaving the light token untouched, and keep `--destructive-foreground` for solid-fill destructive buttons. (b) Six components paint *raw* `red-*`/`green-*` Tailwind palette classes that only have a light tint (or a half-applied `dark:` variant), so the success/error banners are illegible or off-theme in dark mode. We introduce two semantic banner token pairs in `globals.css` — `--success`/`--success-foreground` and `--warning`/`--warning-foreground` (light + dark values, registered in `@theme inline` as `--color-success`, etc.) — and a reusable `<StatusBanner variant="error|success|warning">` component in `src/components/ui/status-banner.tsx` that maps to `bg-destructive/10 text-destructive`, `bg-success/10 text-success`, `bg-warning/10 text-warning` (the `/10` tint reads in both themes because the text token itself is AA on `--card`). Each of the six call sites swaps its raw-color markup for `<StatusBanner>` (or, for the inline `statusClass`/single-line cases, for `text-destructive`/`text-success`/`text-warning`).
- **Touch targets via a new `size` variant, not a base-height change.** Bumping the default `Button`/`Input` height from `h-9` (36 px) straight to `h-11` (44 px) would visually disrupt dense admin tables and the editor toolbar. Instead we (a) raise the base `Input` height to `h-10` (40 px) + `min-h-10` which is a safe small bump, and (b) add an `auth` size variant to `buttonVariants` (`h-11 px-4` = 44 px) plus widen the `default`/`icon` heights to `h-10`/`size-10` (40 px) so the common case clears the comfortable floor while the explicit `auth` variant hits the strict 44 px target used on the touch-critical sign-in/2FA buttons. The existing `sm` size is left at `h-8` for dense toolbars (allowed: 2.5.8 AA floor is 24 px, and these are not the primary action).
- **Destructive confirms reuse the existing `ConfirmDialog`.** `src/components/ui/confirm-dialog.tsx` already exports a promise-based `useConfirm()` (`{ title, description, confirmLabel, cancelLabel, variant: 'danger' }`) mounted via `<ConfirmProvider>` at the app root. `upgrade-apply-button.tsx` and `workspace-e2e-toggle.tsx` call `await confirm({ variant: 'danger', ... })` and bail if it returns `false`, before the irreversible fetch. No native `confirm`.
- **Focus trap + Esc reuse the existing primitive.** `src/lib/a11y/focus-trap.ts` exports `useFocusTrap<T>(active)` (wraps Tab/Shift+Tab, restores focus on close). The cover-picker modal attaches the returned ref to its dialog container and adds an `onKeyDown` Escape→close. The command palette already closes on Escape (its `Command` `onKeyDown`) but is NOT focus-trapped; we attach `useFocusTrap` to the palette container so Tab cycles inside it. cmdk owns arrow-key list nav; the trap only governs Tab, so the two do not collide.
- **2FA labels.** `two-factor-card.tsx` has two placeholder-only inputs. Each gets a visible `<label htmlFor>` (the disable input and the confirm-token input), both i18n'd. The enroll/disable copy in this file is also migrated to `useT()` where it is currently hard-coded English, because the rule is *every user-facing string → i18n*; we scope the i18n migration to the two new labels plus the strings on the inputs/buttons we touch, not the whole file's already-shipped error strings (those stay as-is to keep the change bite-sized).
- **i18n:** every new user-facing string is added to `messages/en.json`, `messages/es.json`, and `messages/ar.json` and read via `useT()`. New keys: `statusBanner.error`/`.success`/`.warning` (visually-hidden role hints), `cover.close` already exists, `security.twoFactor.disableLabel`, `security.twoFactor.confirmLabel`. Component tests wrap UI in `<I18nProvider locale="en" messages={getMessages('en')}>` (the established `tests/components/security/two-factor-card.test.tsx` pattern) or mock `@/lib/i18n/provider` (`useT: () => (k) => k`) for the palette per `tests/components/search-palette-escape.test.tsx`.
- **No native dialogs / no new strings without i18n / no eslint:** lint+format is Biome v2 (`pnpm lint`). Settings nav (if a new page were added) would live in `src/components/settings/sidebar.tsx` `SECTIONS` — not needed here, this group adds no routes.

**Tech Stack:** Next.js 16 App Router (React 19 client components), TypeScript 6 strict, Tailwind v4 (CSS-first `@theme` in `src/app/globals.css`) + shadcn/ui, Biome v2 (lint+format), Vitest 4 with jsdom + `@testing-library/react` for component tests, `@/lib/i18n` (`I18nProvider`, `useT`, `getMessages`), the existing `useConfirm()`/`ConfirmProvider` (`src/components/ui/confirm-dialog.tsx`) and `useFocusTrap` (`src/lib/a11y/focus-trap.ts`). **No migration** — this group is pure UI/CSS/component work; latest migration is 0056 and we do NOT create 0057. No new dependencies.

/*

import { join } from 'node:path';

const css = readFileSync(join(process.cwd(), 'src/app/globals.css'), 'utf8');

/** Extract `--name: H S% L%;` from inside the `.dark { ... }` block. */
function darkToken(name: string): [number, number, number] {
  const dark = css.slice(css.indexOf('.dark {'), css.indexOf('@theme inline'));
  const m = dark.match(new RegExp(`--${name}:\\s*([\\d.]+)\\s+([\\d.]+)%\\s+([\\d.]+)%`));
  if (!m) throw new Error(`missing dark token --${name}`);
  return [Number(m[1]), Number(m[2]), Number(m[3])];
}

function hslToRgb(h: number, s: number, l: number): [number, number, number] {
  s /= 100;
  l /= 100;
  const k = (n: number) => (n + h / 30) % 12;
  const a = s * Math.min(l, 1 - l);
  const f = (n: number) => l - a * Math.max(-1, Math.min(k(n) - 3, Math.min(9 - k(n), 1)));
  return [f(0), f(8), f(4)].map((v) => Math.round(v * 255)) as [number, number, number];
}

function lum([r, g, b]: [number, number, number]): number {
  const c = [r, g, b].map((v) => {
    const x = v / 255;
    return x <= 0.03928 ? x / 12.92 : ((x + 0.055) / 1.055) ** 2.4;
  });
  return 0.2126 * c[0] + 0.7152 * c[1] + 0.0722 * c[2];
}

function ratio(a: [number, number, number], b: [number, number, number]): number {
  const la = lum(a);
  const lb = lum(b);
  return (Math.max(la, lb) + 0.05) / (Math.min(la, lb) + 0.05);
}

describe('dark-mode semantic token contrast (AA, ≥4.5:1 on --card)', () => {
  const card = hslToRgb(...darkToken('card'));
  for (const token of ['destructive', 'success', 'warning'] as const) {
    it(`--${token} text reads ≥4.5:1 on the dark card`, () => {
      const fg = hslToRgb(...darkToken(token));
      expect(ratio(fg, card)).toBeGreaterThanOrEqual(4.5);
    });
  }
});
```

'use client';

import type { ReactNode } from 'react';
import { useT } from '@/lib/i18n/provider';
import { cn } from '@/lib/utils';

export type StatusBannerVariant = 'error' | 'success' | 'warning';

const VARIANT_CLASS: Record<StatusBannerVariant, string> = {
  // The `/10` tint surface reads in both themes because the text token is AA on
  // --card (Task 2). Border + text share the semantic token; no raw palette.
  error: 'border-destructive/30 bg-destructive/10 text-destructive',
  success: 'border-success/30 bg-success/10 text-success',
  warning: 'border-warning/30 bg-warning/10 text-warning',
};

const ROLE: Record<StatusBannerVariant, 'alert' | 'status'> = {
  error: 'alert',
  success: 'status',
  warning: 'status',
};

const LABEL_KEY: Record<StatusBannerVariant, string> = {
  error: 'statusBanner.error',
  success: 'statusBanner.success',
  warning: 'statusBanner.warning',
};

/**
 * #169 — themed status banner. Replaces raw `bg-red-50 text-red-800` /
 * `text-green-600` markup that was illegible or off-theme in dark mode. The
 * semantic tokens (Task 2) carry AA-contrast light + dark values, so a single
 * component is correct in both themes. A visually-hidden label gives screen
 * readers the severity (the color alone is not an accessible cue — WCAG 1.4.1).
 */
export function StatusBanner({
  variant,
  className,
  children,
}: {
  variant: StatusBannerVariant;
  className?: string;
  children: ReactNode;
}) {
  const t = useT();
  return (
    <div
      role={ROLE[variant]}
      className={cn('rounded border p-3 text-sm', VARIANT_CLASS[variant], className)}
    >
      <span className="sr-only">{t(LABEL_KEY[variant])}: </span>
      {children}
    </div>
  );
}
```

'use client';

import { useState } from 'react';
import { useConfirm } from '@/components/ui/confirm-dialog';
import { useT } from '@/lib/i18n/provider';

/**
 * v0.9.0 G8 P42 — admin "Apply upgrade now" client button.
 *
 * POSTs to `/api/admin/upgrade/apply` and reads the SSE stream into a local
 * log. The RSC page only crosses the boundary with the primitive `disabled`
 * prop; the button owns its own state machine. #169 — the irreversible restart
 * is gated behind a themed confirm dialog (no fire-on-first-click).
 */
export function UpgradeApplyButton({ disabled }: { disabled: boolean }): React.ReactElement {
  const t = useT();
  const confirm = useConfirm();
  const [running, setRunning] = useState(false);
  const [log, setLog] = useState<string[]>([]);

  async function onClick(): Promise<void> {
    const ok = await confirm({
      title: t('admin.upgrade.confirmTitle'),
      description: t('admin.upgrade.confirmBody'),
      confirmLabel: t('admin.upgrade.confirmCta'),
      variant: 'danger',
    });
    if (!ok) return;
    setRunning(true);
    setLog([]);
    let res: Response;
    try {
      res = await fetch('/api/admin/upgrade/apply', { method: 'POST' });
    } catch (err) {
      setLog([`error: ${(err as Error).message}`]);
      setRunning(false);
      return;
    }
    if (!res.ok || !res.body) {
      setLog((l) => [...l, `error: HTTP ${res.status}`]);
      setRunning(false);
      return;
    }
    const reader = res.body.getReader();
    const decoder = new TextDecoder();
    let buf = '';
    for (;;) {
      const { value, done } = await reader.read();
      if (done) break;
      buf += decoder.decode(value, { stream: true });
      const events = buf.split('\n\n');
      buf = events.pop() ?? '';
      for (const ev of events) {
        const line = ev.replace(/^data:\s*/, '').trim();
        if (line) setLog((l) => [...l, line]);
      }
    }
    setRunning(false);
  }

  return (
    <div>
      <button
        type="button"
        onClick={onClick}
        disabled={disabled || running}
        className="rounded bg-primary px-4 py-2 text-primary-foreground disabled:opacity-50"
      >
        {running ? 'Applying...' : 'Apply upgrade now'}
      </button>
      {log.length > 0 && (
        <pre className="mt-4 max-h-96 overflow-auto rounded bg-muted p-3 text-xs">
          {log.join('\n')}
        </pre>
      )}
    </div>
  );
}

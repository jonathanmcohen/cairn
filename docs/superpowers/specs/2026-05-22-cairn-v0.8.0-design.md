# Cairn v0.8.0 — Mobile, Accessibility & i18n Design

**Status:** Draft (autonomously specced at the user's direction; all design decisions mine, flagged below; revisit before building).
**Date:** 2026-05-22
**Target release:** v0.8.0
**Builds on:** v0.7.0 (sharing & collaboration depth) — third release of the road-to-1.0 (`roadmap-0.6-to-1.0.md`).

## 1. Purpose

Make Cairn **usable everywhere, by everyone** — the cross-cutting polish release. After v0.6.0 (content/db parity) and v0.7.0 (sharing/collab depth), the feature surface is broad enough that it's worth retrofitting it for small screens, offline use, assistive tech, and non-English locales **once**, before the v0.9.0 ops work and the v1.0.0 freeze.

Five pillars: a **responsive/mobile UI** (editor, sidebar drawer, database views), a **PWA with bounded offline** (installable + read-offline recent pages + queued simple edits replayed on reconnect), an **accessibility pass to WCAG 2.1 AA** (keyboard, focus, ARIA, contrast, screen-reader, axe-in-CI), a **keyboard-shortcut registry + discoverable sheet** (⌘/), and **i18n scaffolding** (externalized strings, locale switch, en + one proof locale, RTL-ready CSS).

Folded in from the v1.0.0 design §9 (items slotted to v0.8): **column ergonomics** (per-view width/freeze/hide), **favorites/pinned + recents** (per-user sidebar customization), **command-palette actions** (run new-page/toggle-theme/switch-workspace from ⌘K, not just navigate), and **block conversion + multi-select** (turn a block into another type; shift/drag-select multiple blocks).

This release is **mostly client/UI** — the only persistence is per-user preferences (favorites/recents). It must not regress the v0.5.1 security posture (CSP/nonce) or the Yjs collab constraint.

## 2. Key decisions (mine; revisit before building)

1. **i18n = a hand-rolled, dependency-light `t()` over flat JSON catalogs — no `next-intl`/`react-intl`.** **D1.** A `src/lib/i18n/` module: per-locale flat-key JSON (`messages/en.json`, `messages/<proof>.json`), a server-side `getMessages(locale)` + a client `I18nProvider` exposing `t(key, vars?)` with `{name}`-style interpolation and a count→plural rule. Locale is resolved per-request from a `cairn_locale` cookie → `Accept-Language` → `en` fallback, set on `<html lang dir>`. **Rationale:** the string surface is large but the *machinery* is tiny; `next-intl` brings routing/middleware coupling we don't want on top of the `src/proxy.ts` auth gate, and a flat `t()` keeps the externalization mechanical and reviewable. Missing keys fall back to the key (visible in dev, axe/lint-catchable). RTL handled by `dir` on `<html>` + logical CSS (see D7), not by the i18n lib.
2. **Proof locale = a full RTL locale (Arabic, `ar`) — not a "free" Latin one.** **D2.** Shipping a RTL locale as the second locale *forces* the RTL-ready CSS to actually be exercised (logical properties, mirrored chevrons/drawers) rather than asserted. en + ar proves both the catalog mechanism and the bidi layout. (A machine-assisted `ar` catalog is acceptable for proof; correctness of translation is not a 1.0 gate — the *mechanism* is.)
3. **Favorites + recents live in one new `user_page_prefs` table — NOT a per-view jsonb blob.** **D3.** Migration `0015` adds `user_page_prefs(user_id, workspace_id, page_id, favorite boolean, favorite_order int, last_visited_at timestamptz, ...)` keyed `(user_id, page_id)`. **Rationale:** favorites are *per-user* (not per-page, not per-workspace-doc) and recents are high-write — a relational table is queryable/orderable/prunable (cap recents to N per user) and avoids contention on any shared row. Recents update is a cheap upsert on page open.
4. **Column ergonomics (width/freeze/hide) go in the existing view-config jsonb — NO migration.** **D4.** Per-view, per-column settings (`columnWidths: {propId: px}`, `frozenColumnIds: string[]`, `hiddenColumnIds: string[]`) extend the `db_views` config jsonb, exactly as v0.6.0 put `groupBy`/filters there. **Rationale:** these are *view* presentation, not user prefs and not schema — config jsonb is the established home (v0.6.0 precedent), so this is config-only.
5. **Offline edits = the Yjs IndexedDB offline provider (`y-indexeddb`) + replay-on-reconnect — NOT a hand-rolled outbox.** **D5.** Reuse the existing Yjs doc: add `y-indexeddb` to persist each opened doc locally; the Hocuspocus provider already buffers updates while disconnected and flushes (CRDT-merges) on reconnect. So "queued simple edits" = ordinary Yjs updates made while offline, merged automatically — **no separate outbox, no custom conflict resolution.** **Scope limit (the risk):** offline editing is supported **only for pages already loaded into IndexedDB this session** (i.e. recently-viewed); creating pages, structural ops (move/delete in the tree), database row mutations, and file uploads are **disabled offline** (queued as nothing — UI shows them unavailable). **Rationale:** Yjs/CRDT merge is the *only* correctness-safe queue we have; anything not on the Yjs doc has no automatic conflict story, so we don't pretend to queue it. This keeps us at "read-offline + simple queued edits," explicitly **not** full offline-first.
6. **Service worker = Workbox-generated, with route-scoped strategies; app shell precached, page content runtime-cached, mutations network-only.** **D6.** Via `@serwist/next` (Workbox-for-Next, maintained for App Router). Strategies: **precache** the app shell + static assets (build hash); **stale-while-revalidate** for the page-read API of recently-visited pages (the offline-read corpus, capped/LRU); **network-first** for navigations (fall back to a cached offline shell); **network-only (never cached)** for all auth, mutation (`POST/PUT/PATCH/DELETE`), `/api/files/*` signed URLs, and the Hocuspocus websocket. **Rationale:** caching mutations or signed file URLs is a correctness + security hazard (stale/forged); the SW only ever caches idempotent reads + the shell. SW + manifest must respect the CSP/nonce (registered from a nonce'd script).
7. **a11y is a retrofit with codified conventions + an axe CI gate that fails the build.** **D7.** Conventions: semantic landmarks (`<nav>/<main>/<aside>`), one focus trap utility for modals/menus (keep the native `<details>`/`popover` patterns already used — they're keyboard/AT-friendly for free), visible focus rings (no `outline:none` without replacement), `aria-live` for toasts/save-status, labelled icon-buttons, and **CSS logical properties everywhere** (margin-inline, inset-inline) so RTL (D2) is automatic. CI runs `@axe-core/playwright` against a seeded set of key screens (editor, sidebar, a database view, a modal, the share dialog, sign-in) and **fails on any violation** at the WCAG 2.1 AA tag set. **Rationale:** a CI gate is the only way a retrofit doesn't immediately rot; logical properties make a11y and RTL one job.
8. **Keyboard shortcuts = a single typed registry + a global dispatcher + a generated ⌘/ sheet; command-palette actions read the same registry.** **D8.** `src/lib/shortcuts/registry.ts`: each entry `{ id, keys, scope, labelKey, run() }` (label via `t()`, so shortcuts are localized + the sheet is auto-built). A global listener dispatches by scope (editor vs global) with conflict detection at registration. The ⌘/ sheet renders the registry grouped by scope. **Command-palette actions** (⌘K) surface the same registry's global entries (new page, toggle theme, switch workspace, go to favorites) alongside the existing navigation search — actions and shortcuts are one source of truth. **Rationale:** one registry prevents the classic drift between "what the sheet says" and "what actually fires," and gives i18n + the palette for free.
9. **Block conversion + multi-select are editor-only (ProseMirror commands) — Yjs-safe by construction, no schema.** **D9.** "Turn into" is a ProseMirror `setBlockType`/replace command (with a slash-menu/`/turn` + selection-toolbar entry) constrained to compatible node types; multi-select is a ProseMirror multi-node selection (shift-click/drag) enabling bulk delete/move/convert. Because these are ordinary ProseMirror transactions on the existing doc, they round-trip through Yjs like any edit — **no new node types, no migration** (contrast v0.6.0's new nodes). **Rationale:** keep the riskiest collab surface (new persisted structure) at zero; conversion/selection are transient editor operations.

## 3. Scope

### In scope
- **Responsive UI:** breakpoint pass on the editor, the sidebar as an off-canvas **drawer** on small screens, database table/kanban/gallery/list views adapt (horizontal scroll + sticky frozen cols on mobile, kanban as swipeable columns); touch targets ≥44px; the page header/toolbar collapses.
- **PWA:** web app manifest (name/icons/theme-color/display=standalone), installability, maskable icons, an offline fallback page; `@serwist/next` service worker with the D6 strategy map.
- **Offline (bounded, D5):** `y-indexeddb` on opened docs; read recently-viewed pages offline; edit those loaded docs offline → CRDT-merge on reconnect; a clear **offline status indicator** + disabled-when-offline affordances for unsupported ops (create/move/delete/db-rows/uploads).
- **Accessibility (WCAG 2.1 AA):** keyboard nav across all interactive surfaces, focus management + a shared focus-trap util for modals/menus, ARIA roles/labels/`aria-live`, AA contrast audit of the theme tokens (light + dark), screen-reader manual pass; **`@axe-core/playwright` gate in CI**.
- **Keyboard shortcuts (D8):** the registry + dispatcher + ⌘/ discoverable sheet; conflict detection.
- **i18n (D1/D2):** `src/lib/i18n/` (`t()`, provider, locale resolution), externalize all user-facing strings into `en.json`, a proof `ar.json`, a locale-switcher in settings, `<html lang dir>` wiring, RTL-ready logical CSS.
- **§9 v0.8 items:** column ergonomics (width/freeze/hide per view — config jsonb, **D4**); favorites/pinned + recents (`user_page_prefs`, **D3**) surfaced in the sidebar; command-palette **actions** (**D8**); block conversion + multi-select (**D9**).
- **Migration `0015`** (`user_page_prefs`).

### Deferred
- **Native iOS/Android apps** → post-1.0 (the PWA covers mobile for 1.0 — roadmap non-goal).
- **Full offline-first** (offline page-create, offline tree/structural ops, offline database mutations, offline file upload, background sync of non-Yjs data) → out of scope; explicitly **not** attempted (**D5** risk boundary). Documented limitation.
- **Cross-page / cross-device offline merge guarantees beyond what Yjs gives** → none promised; CRDT merge is the contract.
- **Full localization of every locale** → only the *mechanism* + en + ar (proof) ship; community locales post-1.0. Translation correctness of `ar` is not a gate (**D2**).
- **Per-user theme/density beyond the existing `next-themes` light/dark** → not in this release.
- **Push notifications via the SW** → folds into v0.9.0 notifications work, not here.

## 4. Data model (migration `0015`)
```
user_page_prefs:
  id              uuid pk default gen_random_uuid()
  user_id         uuid not null references users(id)        on delete cascade
  workspace_id    uuid not null references workspaces(id)    on delete cascade
  page_id         uuid not null references pages(id)         on delete cascade
  favorite        boolean not null default false
  favorite_order  integer                                    -- nullable; ordering among pinned
  last_visited_at timestamptz                                -- nullable; null = never (pure favorite row)
  created_at      timestamptz not null default now()
  updated_at      timestamptz not null default now()
  unique (user_id, page_id)
  index (user_id, favorite, favorite_order)                  -- favorites list
  index (user_id, last_visited_at desc)                      -- recents list
```
- **Recents** = rows ordered by `last_visited_at desc`, capped at N (e.g. 20) per user (prune oldest beyond N on upsert, or filter at read). **Favorites** = `favorite = true` ordered by `favorite_order`.
- On `page` soft-delete the pref row stays (FK cascade fires only on hard-delete); favorites/recents readers join `pages` and skip `deleted_at IS NOT NULL`.
- **Column ergonomics (D4):** no schema — `columnWidths`/`frozenColumnIds`/`hiddenColumnIds` extend the `db_views` config jsonb.
- **Offline (D5):** no Postgres schema — IndexedDB (client) via `y-indexeddb`; the offline corpus is purely client-side.
- **Shortcuts / i18n / a11y / block-conversion / multi-select:** no schema, no migration (client/editor only).

## 5. Architecture by area

- **i18n:** `src/lib/i18n/` — `config.ts` (locale list, default, RTL set `{ar}`), `resolve.ts` (cookie→Accept-Language→en, server-side), `messages/en.json` + `messages/ar.json` (flat keys), `provider.tsx` (`I18nProvider` + `useT()` returning `t(key, vars?)` with interpolation + pluralization), `t-server.ts` (server `getT(locale)`). Locale + `dir` set on the root `<html>` in the layout from the resolved locale. A `<LocaleSwitcher>` in settings sets the `cairn_locale` cookie. Externalization is a mechanical sweep of `src/components/**` + `src/app/**` user-facing strings into keys.
- **Responsive UI:** Tailwind 4 breakpoint utilities + container queries where the editor needs them. The sidebar (`src/components/sidebar/*`) becomes a drawer below `md` (off-canvas, focus-trapped, `aria-modal`); a header hamburger toggles it. Database views (`src/components/databases/*`) get mobile layouts: table → horizontal scroll with sticky frozen columns (shares the D4 freeze logic), kanban → swipeable columns, gallery → single-column. The editor toolbar/page header collapse into a menu under `md`.
- **PWA + service worker:** `@serwist/next` wired in `next.config` + a `src/app/sw.ts` (Serwist config implementing the **D6** strategy map: precache shell, SWR for recent-page reads, network-first navigations + offline fallback, network-only for auth/mutations/files/ws). `src/app/manifest.ts` (Next metadata route) emits the manifest; maskable icons under `public/`. SW registration from a nonce'd client script (CSP). An offline indicator component reads `navigator.onLine` + the Yjs provider connection state.
- **Offline (Yjs):** in the collab provider setup (existing `src/components/editor/collab*` / Hocuspocus client), attach a `y-indexeddb` `IndexeddbPersistence` per doc so opened docs persist + load offline; rely on the provider's built-in disconnected-update buffering for replay. Disabled-offline affordances gate create/move/delete/db-mutation/upload UI on connection state.
- **Accessibility:** a shared `src/lib/a11y/focus-trap.ts` (used by the drawer, modals, menus), `aria-live` regions for the save-status + toasts, an audit + fix sweep of roles/labels/contrast across components, theme-token contrast fixes in `globals.css` (`@theme`). CI: `@axe-core/playwright` spec hitting seeded screens; a `pnpm test:a11y` script; gate in the workflow.
- **Keyboard shortcuts:** `src/lib/shortcuts/registry.ts` (typed entries + conflict check) + `src/components/shortcuts/dispatcher.tsx` (global key listener, scope-aware) + `src/components/shortcuts/sheet.tsx` (the ⌘/ overlay, grouped, labels via `t()`).
- **Command-palette actions:** extend the existing `cmdk` palette (`src/components/command-palette/*`) to merge the registry's global *action* entries with navigation results; actions like `new-page`, `toggle-theme` (`next-themes`), `switch-workspace`, `open-favorites`.
- **Favorites/recents:** `src/lib/prefs/user-page-prefs.ts` (pure, db-injected: `toggleFavorite`, `reorderFavorites`, `recordVisit` upsert + prune, `listFavorites`, `listRecents`) + API routes under `src/app/api/prefs/*` (gated by `requireRole`/`requirePageAccess`) + sidebar sections (`<Favorites>`, `<Recents>`) with drag-reorder for favorites.
- **Column ergonomics:** extend `src/lib/databases/views.ts` config validation with the three fields; table/list view components honor widths (resizable column handles), freeze (sticky positioning — shared with the mobile sticky logic), and hide (column visibility menu).
- **Block conversion + multi-select:** editor commands in `src/components/editor/` — a `turnInto` command + selection toolbar/slash entry (compatible-type map), and ProseMirror multi-node selection (shift-click/drag handles) with bulk delete/move/convert. Yjs round-trip audited like v0.6.0 nodes (though no new node types).

- **Integration (Testcontainers):** migration `0015`; `user_page_prefs` CRUD + uniqueness `(user_id, page_id)` + recents ordering/cap + favorites ordering; API routes for prefs (role-gated, cross-workspace → 404 per the access convention).
- **a11y (Playwright + axe):** `@axe-core/playwright` against seeded editor / sidebar (+ drawer open) / a database view / a modal / share dialog / sign-in — **zero AA violations** (CI gate). Manual screen-reader pass checklist (VoiceOver) documented in the plan.
- **Build-verified / smoke:** `pnpm build`; the **docker-compose smoke** (per the release workflow) plus a **Lighthouse PWA + a11y** run (installability, manifest, SW registration, offline-read of a previously-loaded page); Yjs round-trip with `y-indexeddb` attached (offline edit → reconnect → merge); RTL visual check under `ar` (drawer/chevrons mirror; logical-property layout holds).
- **Security regression:** SW + manifest registered under CSP/nonce without violations; SW never caches mutations/auth/signed file URLs/ws (assert the strategy map); reuses the v0.5.1 suite.

## 8. Risks

- **PWA offline + Yjs is the riskiest correctness surface** (the recurring roadmap warning). The mitigation is the hard **D5** scope boundary: only Yjs-doc edits on already-loaded pages are offline-queued (CRDT-merged on reconnect); everything non-Yjs (create/move/delete/db-rows/uploads) is *disabled* offline, not silently queued. Do NOT drift toward full offline-first. Test the merge path explicitly (offline edit → reconnect).
- **Service-worker caching is a correctness + security hazard if mis-scoped.** Caching a mutation, an auth response, or a signed `/api/files` URL is a bug. The **D6** strategy map is allow-listed to idempotent reads + the app shell only, network-only for everything else; assert it in tests and keep SW registration CSP/nonce-clean (don't reintroduce a CSP hole).
- **a11y retrofit rots without a gate.** The `@axe-core/playwright` CI gate failing the build is the load-bearing mitigation; manual screen-reader passes catch what axe can't. Earlier releases were asked not to regress semantic markup/externalized strings — verify that held; budget for the cleanup if it didn't.
- **i18n externalization is a large mechanical sweep** that can miss strings or break interpolation. Missing-key→key fallback keeps it non-fatal and visible; the `ar` RTL proof (**D2**) surfaces hardcoded physical-CSS/LTR assumptions that a Latin proof locale would hide.
- **Shortcut/registry drift + conflicts** — registration-time conflict detection + the single-source-of-truth registry (sheet + palette + dispatcher all read it) prevent "the sheet lies" bugs.
- **Migration `0015` is additive + low-risk** (one new table, no enum/type changes — unlike v0.6.0's `ALTER TYPE`), but recents-pruning logic must be correct (don't prune favorites; cap only recents).

# Cairn v0.9.0 — Admin, Observability, Ops & Import Design

**Status:** Draft (autonomously specced at the user's direction; all design decisions mine, flagged below; revisit before building).
**Date:** 2026-05-22
**Target release:** v0.9.0
**Builds on:** v0.8.0 (mobile/a11y/i18n) — the fourth release of the road-to-1.0 (`roadmap-0.6-to-1.0.md`). The last minor before the v1.0.0 stabilization milestone.

## 1. Purpose

Make Cairn **operable at scale** and **portable**: a real **workspace admin console** (member/role/invite management, settings, transfer-ownership, delete-workspace — the v0.2.0 sole-owner-leave follow-ups), a workspace-scoped **audit log** (also surfaced as a per-page activity feed), optional per-user **2FA (TOTP) + recovery codes** (admin-requirable per workspace), **observability** (structured JSON logging + a Prometheus `/metrics` endpoint), per-workspace **quotas/limits** surfaced in admin, **scheduled backups + retention + optional S3 target** (extends the v0.5.0 backup CLI), **Notion + Markdown-folder import** (best-effort, documented gaps) and a full re-importable **workspace export**.

This release also folds in the §9 (v1.0.0 design doc) items slotted to v0.9: **search filters + scope + saved searches** (search-within-page included), **due-date reminders**, **PDF export + per-page/per-database UI export** (Markdown/CSV/JSON), **bulk operations** (multi-select pages/rows → move/delete/duplicate/tag, bulk trash-restore), and a **workspace-home / default-landing setting**.

This is a security-sensitive release: it adds two new secret classes (TOTP secrets, recovery codes) and a metrics surface that must not leak tenant data. It continues the v0.5.1 hardening posture throughout, and the v0.5.1 secret-leak test must be extended to cover the new secrets.

## 2. Key decisions (mine; revisit before building)

1. **Audit log is an append-only `audit_log` table, written by a single `recordAudit(tx, ...)` helper at the action site (in the `src/lib/...` business helpers, not at the route).** Columns: `id`, `workspace_id`, `actor_user_id` (nullable — system/cron actions), `action` (text enum, e.g. `member.role_changed`, `member.removed`, `invite.created`, `page.published`, `page.unpublished`, `api_key.created/revoked`, `webhook.created/deleted`, `page.deleted`, `database.deleted`, `workspace.settings_changed`, `workspace.ownership_transferred`, `totp.enabled/disabled`, `quota.changed`, `backup.created`, `export.created`, `import.completed`), `target_type` + `target_id` (the affected entity), `metadata` jsonb (before/after diff for role/settings changes — **never secrets**, only ids/role names/flags), `ip` (nullable, from the request when available), `created_at`. **No updates, no deletes** at the app layer (retention/pruning is an explicit admin/CLI action, audited as `audit.pruned`). **Rationale:** writing at the helper (not middleware) means every audited action is recorded inside the same transaction that performed it, so the log can't drift from reality; an enum `action` keeps the viewer + per-page feed query-able and webhook-mappable later.
2. **The per-page activity feed is a *view over* `audit_log`, not a second store.** Audit rows whose `target_type='page'` (and child blocks/comments tied to a page) filtered by `target_id` render the page activity feed; no separate table. **D: page content edits are NOT individually audited** (that's what version history from v0.5.0 already covers — the feed links to version history for "what changed"); the feed records structural/sensitive events (publish, share-setting change, move, restore, member-affecting actions). Avoids audit-log bloat from every keystroke-batch.
3. **TOTP via `otplib` (`@otplib/preset-default`), secrets encrypted at rest (not just hashed), recovery codes hashed.** A new `user_totp` table holds `user_id` (PK/FK), `secret_encrypted` (the TOTP shared secret — must be *reversible* to verify codes, so AES-256-GCM encrypted with a key derived from `AUTH_SECRET` via HKDF, NOT plain hashing), `enabled_at`, `last_used_at`, and `recovery_codes` (a jsonb array of **hashed** codes — one-way, like passwords, via the existing password hasher; consumed/marked-used on use). Enrollment is a two-step confirm (show QR/secret → verify a live code → only then `enabled_at` set). **D: TOTP only; WebAuthn/passkeys deferred post-1.0** (per roadmap §4 / D6). **Rationale:** TOTP secrets are fundamentally different from passwords — they must be decryptable to compute the expected code, so encryption (reversible, keyed) is correct and hashing is wrong; recovery codes are single-use proofs like passwords, so hashing is correct. Keying off `AUTH_SECRET` avoids adding a new required env var while keeping secrets useless in a raw DB dump.
4. **Workspace can *require* 2FA via a settings flag; enforcement is at the auth/session boundary, not per-request.** `workspaces.require_2fa boolean`. On sign-in (and on session refresh), if any of the user's workspaces requires 2FA and the user has no enabled TOTP, they're routed to a forced-enrollment screen before workspace access; a member who already has a session is challenged on next navigation. **D: the workspace *owner* must have 2FA enabled before they can turn on the requirement** (no locking yourself out / locking out via an un-2FA'd owner).
5. **Observability uses `prom-client` for `/metrics` and `pino` for structured JSON logging.** A single `src/lib/observability/metrics.ts` registers a default registry + custom metrics: `http_request_duration_seconds` (histogram, labels `method`, `route` (the *template*, e.g. `/api/pages/[id]` — never the concrete id, to avoid cardinality blowup and id leakage), `status`), `http_requests_total`, `db_query_duration_seconds`, `collab_active_connections` (gauge), `collab_doc_updates_total`, `webhook_delivery_total` (labels `event`, `outcome`), `webhook_delivery_duration_seconds`, `notifications_sent_total`, `backup_runs_total`/`backup_last_success_timestamp`. **D: metrics are aggregate-only and carry NO workspace/user/page identifiers as labels** — they describe the instance, not tenants, so `/metrics` can't be used to enumerate or fingerprint tenant data. Logging via `src/lib/observability/logger.ts` (pino) emits JSON with a request id, never logs request bodies, headers like `authorization`/`cookie`, API keys, TOTP material, or signed-URL signatures (a redaction allow/deny list; reuses + extends the v0.5.1 hygiene rules).
6. **`/metrics` is access-controlled by a bearer token, defaulting to bound-but-protected.** **D: gate `/metrics` behind a `CAIRN_METRICS_TOKEN` env var** — if set, the endpoint requires `Authorization: Bearer <token>` (what a Prometheus scrape config provides); if unset, **`/metrics` returns 404** (off by default — operators opt in). This avoids the footgun of an open metrics endpoint on a homelab box reachable from the LAN, without forcing network-level binding tricks we can't guarantee in a single-container deploy. Documented in `SECURITY.md` + the ops docs.
7. **Quotas are stored as nullable columns on a `workspace_quotas` table (one row per workspace, lazily created), enforced at two choke points.** Columns: `workspace_id` (PK/FK), `storage_bytes_limit` (nullable = unlimited), `storage_bytes_used` (maintained counter), `api_rate_limit_per_min` (nullable = use global default), `member_limit` (nullable). **D: storage is enforced at the file-upload path** (`src/lib/files/*` — reject the upload + return a clear 413-style error when `used + incoming > limit`; the `used` counter is incremented on successful store and decremented on delete/trash-purge, with a CLI `reconcile` to recompute from disk/S3 truth). **API rate limits ride the existing v0.5.1 auth rate-limiter**, parameterized per-workspace. Quotas are read + editable in the admin console (only `owner`/`admin`). **D: quotas are advisory limits an operator sets per workspace — there is no billing.**
8. **Saved searches are a `saved_searches` table; the filter/scope payload is jsonb reusing the database filter vocabulary.** Columns: `id`, `workspace_id`, `user_id` (owner of the saved search — **D: per-user, private; shared/team saved searches deferred**), `name`, `query` (text), `filters` jsonb (`{author, dateRange, types[], scopeDatabaseId?}`), `created_at`. Search-within-page is a pure client/runtime feature (no storage). The search executor (`src/lib/pages/search.ts`) gains a structured filter layer that compiles author/date/type/scope onto the existing FTS+trigram query. **Rationale:** reusing the filter jsonb shape keeps one mental model and lets the saved-search UI share components with database filters.
9. **Due-date reminders ride the existing polled-notification system + a periodic scan; no push, no new transport.** A new `reminders` table: `id`, `workspace_id`, `database_id`, `property_id` (the date property to watch), `row_id`, `user_id` (who to notify — **D: default = the row's assignee/`person` property if present, else the page/db watchers**), `remind_at` (computed = the date value minus a per-reminder `lead_time` offset), `fired_at` (nullable), `created_at`. A scan (`pnpm cli reminders:scan`, also runnable on an interval) finds due `reminders` where `remind_at <= now()` and `fired_at IS NULL`, creates a notification via the v0.3.0 notifications path, and stamps `fired_at`. **D: reminders are configured per-database (which date property + lead time), materialized to `reminders` rows on row create/date-edit**, so the scan is a cheap indexed query rather than a full table sweep. **D: the scan is cron-able like scheduled backups** (external cron or a tiny in-process interval — single-instance ceiling, see §below). Documented as not real-time (fires within one scan interval).
10. **Scheduled backups are a CLI *mode*, scheduled by an external mechanism; the app does not host a cron daemon.** The v0.5.0 backup/restore CLI gains: `backup --schedule` semantics are achieved by an operator-run cron (or systemd timer, or the docker-compose `entrypoint` documented interval) invoking `pnpm cli backup` on a schedule; the CLI gains `--retention-days N` (prune backups older than N), `--target s3://...|local` (reuses the v0.5.0 S3/MinIO `FileStorage` backend), and emits the `backup_runs_total`/`backup_last_success_timestamp` metrics + an `audit_log` row. **D: instrumentation/the container cannot reliably host cron; the mechanism is external cron OR a small documented `CAIRN_BACKUP_INTERVAL`/`CAIRN_REMINDER_INTERVAL` in-process interval ticker that is OFF by default and explicitly single-instance** (running two instances would double-fire — documented ceiling, consistent with the single-instance collab ceiling in the roadmap). No distributed lock for 1.0.
11. **Notion import is best-effort; reuse the markdown→ProseMirror + templates id-rewrite machinery.** A Notion workspace export (the ZIP of HTML or Markdown+CSV that Notion produces) is parsed: Markdown/HTML → the existing `marked`-based markdown→ProseMirror path (from the v0.5.0 markdown import), CSV → inline databases, the Notion page hierarchy → Cairn `parent_id` tree, and intra-export links are rewritten using the **same id-rewrite pass the v0.5.0 templates system uses** when instantiating a template (map old → new ids, fix up links/relations in a second pass). **D: documented fidelity gaps (acceptable for "best-effort"):** synced blocks, complex/computed database properties (formulas/rollups/relations across the boundary become plain values or are dropped with a per-item warning), Notion-hosted file/image URLs (re-hosted if present in the ZIP, else left as external links), comments, and exact column/formatting nuance. The importer produces an **import report** (counts + a list of skipped/degraded items) attached to the resulting workspace + an `audit_log` row. Markdown-folder import is the same pipeline minus the Notion-specific CSV/structure conventions.
12. **Workspace export is a single re-importable archive; export/import are inverses.** A `pnpm cli export --workspace <id>` (and an admin-console button) produces a ZIP containing pages (ProseMirror JSON + a Markdown rendering), databases (schema + rows as JSON + CSV), files (the actual blobs from `FileStorage`), and a manifest. **D: secrets are NOT exported** (API keys, webhook secrets, TOTP, recovery codes, password hashes are excluded — the export is content + structure, re-importable into a fresh workspace where the importer mints new ids via the templates id-rewrite pass). Per-page/per-database UI export is the same renderers surfaced as download buttons (Markdown/CSV/JSON), plus **PDF export** (server-side render of the read-only page → PDF; **D: via the same headless rendering already needed for `/p/` public pages**, rendered to PDF — reuse the read-only node-views from v0.6.0 so every block type prints).
13. **Bulk operations are a multi-select layer over existing single-item mutations, run in one transaction with a partial-failure report.** Multi-select in the page sidebar (pages) and database views (rows) → move / delete (trash) / duplicate / tag (add a select-property value or a page label) / and bulk trash-restore (extends the v0.5.0 trash). **D: bulk ops reuse the existing per-item helpers in a loop inside a transaction, role-checked once up front, returning `{succeeded, failed:[{id, reason}]}`** rather than new bulk SQL — correctness + permission reuse over raw speed (homelab scale). Bulk actions are audited as a single `*.bulk` audit row with a count.
14. **Workspace-home / default-landing is a `workspaces.home_page_id` (nullable) setting in admin.** **D:** if set, opening the workspace lands on that page (a designated dashboard page); if null, falls back to the current behavior (last-visited / first page). Settable by `owner`/`admin` in the admin console. No new table.

## 3. Scope

### In scope
- **Admin console** (`/workspace/[slug]/admin`, role-gated `admin`+): members list with role change + remove; invites (create/revoke/list); workspace settings (name, icon, default-role, `require_2fa`, `home_page_id`); **transfer ownership** (owner-only, target must be a member, both confirm); **delete workspace** (owner-only, typed-confirm, cascade + audit) — closes the v0.2.0 sole-owner-leave follow-ups.
- **Audit log** (`audit_log` table + `recordAudit` helper wired into all sensitive action sites) + an admin viewer (filter by action/actor/date) + the **per-page activity feed** (view over the same table).
- **2FA TOTP** (`user_totp` table; enroll/confirm/disable flows; challenge at sign-in; recovery codes; `workspaces.require_2fa` enforcement; admin "require 2FA" toggle).
- **Observability:** `prom-client` `/metrics` (token-gated, off by default) + `pino` structured JSON logging with secret redaction; instrument request/db/collab/webhook/notification/backup paths.
- **Quotas:** `workspace_quotas` table; storage enforcement at upload + counter maintenance + `reconcile` CLI; per-workspace API rate limit via the v0.5.1 limiter; admin UI to view/set.
- **Scheduled backups:** CLI `--retention-days`, `--target`, metrics + audit emission; documented external-cron / opt-in interval mechanism.
- **Import/export:** Notion ZIP (HTML/MD+CSV) import, Markdown-folder import, full workspace export (ZIP), import report; per-page/per-database UI export (MD/CSV/JSON); **PDF export**.
- **Search:** structured filters (author/date/type) + scope-to-database + **saved searches** (`saved_searches` table) + search-within-page (runtime).
- **Reminders:** `reminders` table + per-database reminder config + `reminders:scan` CLI/interval → notification.
- **Bulk operations:** multi-select pages/rows → move/delete/duplicate/tag + bulk trash-restore, with partial-failure report.
- **Workspace-home setting** (`workspaces.home_page_id`).
- Migrations `0017`, `0018`, `0019` (see §4 — assumes v0.7.0 took `0013–0015` and v0.8.0 took `0016`; **the implementer must use the next free numbers at build time** and renumber if earlier releases consumed more/fewer).

### Deferred
- **WebAuthn / passkeys** → post-1.0 (TOTP covers 1.0; roadmap §4 / D6).
- **Shared/team saved searches** → post-1.0 (per-user only for v0.9).
- **Per-keystroke audit / full content audit** → version history (v0.5.0) covers content diffs; the feed links to it.
- **Distributed scheduling / multi-instance backup-reminder locking** → post-1.0 (single-instance ceiling documented, like the collab ceiling).
- **Recurring tasks / scheduled row creation** → post-1.0 (roadmap §9).
- **Billing / hard-billing quotas** → out of scope (quotas are operator-set advisory limits).
- **Notion full fidelity** (synced blocks, cross-boundary formulas/rollups/relations, comments) → documented best-effort gaps.

## 4. Data model (migrations `0017`–`0019`)

> Numbering assumes v0.6.0=`0013`, v0.7.0≈`0014`–`0015`, v0.8.0≈`0016`. **v0.9.0 takes the next free numbers** — adjust at build time if prior releases consumed a different count. `ALTER TYPE ADD VALUE` (the `audit_action` enum, if enum-typed) runs outside a transaction (the `0011` precedent).

```
-- 0017  (admin + audit + 2FA)
audit_log:        id uuid pk, workspace_id uuid fk, actor_user_id uuid NULL fk,
                  action text NOT NULL,                  -- (enum-like; documented set in §2.1)
                  target_type text NULL, target_id uuid NULL,
                  metadata jsonb NOT NULL default '{}',  -- ids/role-names/flags only; NEVER secrets
                  ip text NULL, created_at timestamptz NOT NULL default now()
                  + index audit_log(workspace_id, created_at desc)
                  + index audit_log(workspace_id, target_type, target_id)   -- per-page feed
user_totp:        user_id uuid pk fk, secret_encrypted bytea NOT NULL,      -- AES-256-GCM (HKDF from AUTH_SECRET)
                  recovery_codes jsonb NOT NULL default '[]',               -- array of {hash, usedAt|null}
                  enabled_at timestamptz NULL, last_used_at timestamptz NULL,
                  created_at timestamptz NOT NULL default now()
workspaces:       + require_2fa boolean NOT NULL default false
                  + home_page_id uuid NULL references pages(id) on delete set null

-- 0018  (quotas + saved searches + reminders)
workspace_quotas: workspace_id uuid pk fk,
                  storage_bytes_limit bigint NULL, storage_bytes_used bigint NOT NULL default 0,
                  api_rate_limit_per_min integer NULL, member_limit integer NULL,
                  updated_at timestamptz NOT NULL default now()
saved_searches:   id uuid pk, workspace_id uuid fk, user_id uuid fk,
                  name text NOT NULL, query text NOT NULL default '',
                  filters jsonb NOT NULL default '{}',                      -- {author,dateRange,types[],scopeDatabaseId?}
                  created_at timestamptz NOT NULL default now()
                  + index saved_searches(workspace_id, user_id)
reminders:        id uuid pk, workspace_id uuid fk, database_id uuid fk, property_id uuid NOT NULL,
                  row_id uuid fk, user_id uuid fk,
                  remind_at timestamptz NOT NULL, fired_at timestamptz NULL,
                  created_at timestamptz NOT NULL default now()
                  + index reminders(remind_at) where fired_at is null        -- partial index; cheap scan
db_properties (config jsonb): + optional reminder config {datePropertyId, leadTime} -- no schema change

-- 0019  (import bookkeeping; small)
import_jobs:      id uuid pk, workspace_id uuid fk, actor_user_id uuid fk,
                  source text NOT NULL,                  -- 'notion' | 'markdown-folder' | 'workspace-archive'
                  status text NOT NULL,                  -- 'running'|'completed'|'failed'
                  report jsonb NOT NULL default '{}',    -- counts + skipped/degraded items
                  created_at timestamptz, completed_at timestamptz NULL
```

- **No schema change** for: search filters (compiled at query time), bulk ops (loop over existing helpers), per-page activity feed (view over `audit_log`), per-page/db/PDF export (renderers over existing content), workspace export archive (built from existing tables).
- **Quota counter** (`storage_bytes_used`) is maintained transactionally at the file store/delete sites + a CLI `reconcile` recomputes truth from `FileStorage`.

## 5. Architecture by area

- **Admin console:** `src/app/(app)/workspace/[slug]/admin/*` (route group, `requireRole('admin')`); members/invites reuse the existing membership helpers (`src/lib/auth/*`, v0.2.0). **Transfer ownership** + **delete workspace** are new `owner`-only server actions in `src/lib/workspaces/*` (typed-confirm, full cascade for delete, both emit `audit_log`); these resolve the v0.2.0 sole-owner-leave TODO. Settings (name/icon/default-role/`require_2fa`/`home_page_id`) are one settings form → one server action.
- **Audit log:** `src/lib/audit/record.ts#recordAudit(tx, {workspaceId, actorUserId, action, target, metadata, ip})` called *inside* each sensitive helper's transaction (role change, invite, publish, key/webhook CRUD, page/db delete, settings, ownership transfer, TOTP enable/disable, quota change, backup/export/import). Viewer: `src/app/(app)/workspace/[slug]/admin/audit/page.tsx` (filterable). Per-page feed: `src/components/pages/activity-feed.tsx` querying `audit_log` by `target_id` (links to version history for content diffs).
- **2FA:** `src/lib/auth/totp.ts` (otplib wrappers: `generateSecret`, `verifyToken`, recovery-code generate/verify/consume); `src/lib/crypto/secret-box.ts` (AES-256-GCM encrypt/decrypt, key = `hkdf(AUTH_SECRET, 'cairn-totp')`). Enrollment + challenge UI under `src/app/(app)/settings/security/*`; the sign-in challenge integrates with the Auth.js v5 credentials callback (`src/lib/auth/config.ts`) — after password verification, if TOTP enabled, require a second factor before issuing the jwt session. `require_2fa` enforcement gate in `src/proxy.ts` (the auth gate) routing un-enrolled members of a requiring workspace to forced enrollment.
- **Observability:** `src/lib/observability/metrics.ts` (prom-client registry + custom metrics) + `src/lib/observability/logger.ts` (pino + redaction). `/metrics` route at `src/app/metrics/route.ts` (token-gated per D6; nodejs runtime). Request timing via a thin wrapper in `src/proxy.ts` (uses the route *template*, never the concrete id). DB timing via a Drizzle logger hook; collab metrics from the Hocuspocus server (v0.3.0); webhook metrics from the v0.5.0 delivery path; backup metrics from the CLI.
- **Quotas:** `src/lib/quotas/*` — `checkStorageQuota(tx, workspaceId, incomingBytes)` at the `src/lib/files/*` upload site; `incrementStorageUsed`/`decrementStorageUsed` at store/delete; `reconcile` CLI command. Per-workspace API rate limit parameterizes the v0.5.1 limiter.
- **Backups/import/export:** extend `src/server/cli.ts` (the v0.5.0 backup/restore entrypoint): `backup --retention-days --target`, `export --workspace`, `import --source notion|markdown-folder|workspace-archive --file`, `reminders:scan`. Import pipeline: `src/lib/import/notion.ts` + `src/lib/import/markdown-folder.ts` reuse `src/lib/markdown/*` (v0.5.0 md→ProseMirror) + the templates id-rewrite pass (`src/lib/templates/*`). Export: `src/lib/export/workspace-archive.ts` (uses `archiver`, already a dep). PDF: `src/lib/export/pdf.ts` rendering the read-only page (reuse v0.6.0 read-only node-views).
- **Search:** `src/lib/pages/search.ts` gains a `compileSearchFilters({author,dateRange,types,scopeDatabaseId})` layer onto the existing FTS+trigram query; saved searches CRUD in `src/lib/search/saved.ts`; search-within-page is a client highlight feature in the editor.
- **Reminders:** `src/lib/reminders/*` — materialize reminder rows on row create / date-property edit (driven by the per-database reminder config in `db_properties.config`); `scanReminders(now)` (the CLI/interval) fires notifications via the v0.3.0 notification helper + stamps `fired_at`.
- **Bulk ops:** `src/lib/bulk/*` — `bulkPages`/`bulkRows({ids, op, args})` role-checked once, looping existing per-item helpers in one transaction, returning `{succeeded, failed}`; UI is a multi-select toolbar in the sidebar + database views.
- **Scheduling mechanism:** documented in ops docs + `entrypoint`/compose: external cron invoking the CLI is the recommended path; an opt-in `CAIRN_BACKUP_INTERVAL` / `CAIRN_REMINDER_INTERVAL` in-process ticker exists for single-instance simplicity, **off by default, explicitly single-instance** (no distributed lock).

## 6. Testing

- **Unit:** TOTP verify (valid/expired/reused-window), recovery-code hash+consume (single-use), `secret-box` encrypt/decrypt round-trip + wrong-key fails; audit `recordAudit` shape + the **secret-redaction assertions** (metadata never contains secrets); logger redaction (authorization/cookie/api-key/totp/signature stripped); metric label cardinality (route template not id; no workspace/user labels); search-filter compiler (author/date/type/scope → SQL); quota check math (under/at/over limit); reminder `remind_at` computation (date − lead time); bulk partial-failure aggregation; Notion-import id-rewrite + fidelity-gap warnings; PDF/MD/CSV/JSON export renderers.
- **Integration (Testcontainers):** migrations `0017`–`0019`; transfer-ownership + delete-workspace cascade + the audit rows they write; 2FA enroll→require→challenge end-to-end at the auth callback; quota enforcement blocks an over-limit upload + counter increments/decrements + `reconcile`; `reminders:scan` fires exactly one notification then is idempotent (`fired_at`); export→import round-trip into a fresh workspace (content + db rows survive, **secrets absent**); Notion-ZIP fixture import produces pages/databases + a report listing degraded items; bulk move/delete/duplicate/tag + bulk trash-restore with a mixed-permission set.
- **Security (extends the v0.5.1 suite):**
  - **Extend the v0.5.1 secret-leak test** to assert TOTP secrets, recovery codes, the `secret_encrypted` bytea, and the metrics token never appear in API responses, logs, the workspace export, or the audit log.
  - `/metrics` returns 404 when `CAIRN_METRICS_TOKEN` unset; 401 with a wrong/absent bearer; 200 only with the right token; the body contains no tenant identifiers.
  - Import is SSRF-safe (re-host only in-archive blobs; external URLs are stored as links, not fetched server-side; if any unfurl/fetch happens it reuses the v0.5.0 SSRF guard).
  - Audit + admin actions are workspace-isolated + role-gated (cross-workspace → 404 per the existing convention; `viewer`/`editor` can't read the audit log or admin console).
- **Build-verified:** admin console, audit viewer, activity feed, security/2FA settings UI, bulk-select toolbars, saved-search + search-within-page UI, PDF export.

## 7. Plan decomposition (~6 plans)

1. **Admin console + transfer/delete + workspace settings** — `0017` (`workspaces.require_2fa`, `home_page_id`), admin route group, members/invites/settings UI, transfer-ownership + delete-workspace server actions (closes v0.2.0 follow-ups), wired to `recordAudit` (helper stub introduced here).
2. **Audit log + per-page activity feed** — `audit_log` table (in `0017`), `recordAudit` helper, wire it into all existing sensitive action sites (role/invite/publish/key/webhook/delete/settings), the admin audit viewer, the per-page activity feed; secret-redaction tests.

## 8. Risks

- **Secret handling is the headline risk.** TOTP secrets must be *encrypted* (reversible) not hashed; recovery codes must be *hashed* (one-way). Getting these backwards breaks 2FA or leaks secrets. The v0.5.1 secret-leak test MUST be extended to cover all new secret classes (secret, recovery codes, metrics token) across responses/logs/export/audit before shipping.
- **`/metrics` leakage / footgun.** An open or high-cardinality metrics endpoint can leak tenant existence or data via labels. Mitigation: off-by-default (404 unless token set), bearer-gated, aggregate-only labels (route template, never concrete ids; no workspace/user labels) — asserted in tests.
- **Locking yourself out via `require_2fa`.** Enforcing 2FA when the owner isn't enrolled, or a wrong sign-in-challenge integration, can lock out a workspace. Mitigation: owner must enroll before enabling the requirement; recovery codes; exhaustive auth-callback tests; a CLI escape hatch (`totp:disable --user`) documented for operators.
- **Notion import fidelity.** Best-effort by design — the risk is silent data loss. Mitigation: the import report enumerates every skipped/degraded item; documented gap list; reuse the proven md→ProseMirror + templates id-rewrite machinery rather than new parsing.
- **Scheduling on a single-instance app.** No cron daemon in-container; the interval ticker double-fires under multiple instances. Mitigation: external cron is the recommended mechanism; the in-process interval is opt-in + documented single-instance-only (consistent with the collab single-instance ceiling) — no distributed lock for 1.0.
- **Quota counter drift.** `storage_bytes_used` can drift from disk/S3 truth under crashes/partial deletes. Mitigation: maintained transactionally at store/delete + a `reconcile` CLI to recompute from `FileStorage` truth.
- **Migration numbering coupling.** `0017`–`0019` assume v0.7.0/v0.8.0's actual migration counts; the implementer must use the next free numbers at build time and renumber if those releases consumed more/fewer than estimated.
- **Audit-log growth.** Append-only + no per-keystroke auditing keeps it bounded, but high-traffic workspaces still grow it — pruning is an explicit, audited admin/CLI action with retention; indexed by `(workspace_id, created_at)` to keep the viewer fast.

# Cairn v0.6.0 — Content, Sharing, Collaboration, Mobile & Operations (combined)

**Status:** Draft (autonomously specced at the user's direction; all design decisions mine, flagged below; revisit before building).
**Date:** 2026-05-22
**Target release:** v0.6.0
**Builds on:** v0.5.1 (security) — a single large consolidated release on the road to 1.0 (`roadmap-0.6-to-1.0.md`).

## 1. Purpose

This is a **large, consolidated v0.6.0 release** that merges what were previously four separate themes (the former v0.6 content/database, v0.7 sharing/collaboration, v0.8 mobile/a11y/i18n, and v0.9 admin/ops/import designs) into one release. It builds directly on v0.5.1 (security hardening); the **next** release is the v1.0.0 stabilization milestone.

The release closes Notion-parity gaps and makes Cairn deep, shareable, usable everywhere, and operable at scale, in five bands of work:

1. **Content & database completeness** — reverse relations, a list view + grouping + richer filters/sort, row hierarchy (sub-items), new block types (toggle, columns, simple table, embed, bookmark, math, same-page synced block), full-page databases, a calc footer, and a table of contents + outline.
2. **Sharing & collaboration depth** — per-page share settings (password / expiry / allow-duplication), a published multi-page public site at `/s/<workspace-slug>`, polymorphic comments on databases + files, a Yjs-native suggestion / track-changes mode, opt-in BYO-SMTP email notifications, page links + backlinks + unlinked mentions + page mentions/embeds, and per-database row templates.
3. **Mobile, accessibility & i18n** — a responsive/mobile UI, a PWA with bounded offline (y-indexeddb), an accessibility pass to WCAG 2.1 AA (with an axe CI gate), a keyboard-shortcut registry + ⌘/ sheet, command-palette actions, block conversion + multi-select, and hand-rolled i18n scaffolding (en + an RTL proof locale).
4. **Admin, observability & ops** — a workspace admin console (members/roles/invites/settings, transfer-ownership, delete-workspace), an append-only audit log + per-page activity feed, TOTP 2FA + recovery codes, observability (`prom-client` `/metrics` + `pino` JSON logging), per-workspace quotas, scheduled backups + retention + optional S3, due-date reminders, favorites/recents, column ergonomics, search filters + saved searches, bulk operations, and a workspace-home setting.
5. **Import / export** — best-effort Notion + Markdown-folder import, a re-importable workspace export, and PDF / per-page / per-database export.

Every new editor node and mark must remain **Yjs-serializable** (the v0.3.0 collab constraint). Every new public/anon surface, secret class, and metrics surface continues the **v0.5.1 security posture** (HMAC-signed access, CSP nonce, SSRF guard, secret-leak test) with security tests extending that suite. Sharing is **per-page, never per-block**.

## 2. Key decisions (mine; revisit before building)

### Content & database

1. **Reverse relations are an explicit, paired property — synced on write, loop-guarded.** Creating a `relation` property gains a "create reverse property" option. When set, a mirrored `relation` property is created on the target database; the two are linked by a `reversePropertyId` in each one's config. Cell writes maintain both sides inside the existing write transaction (add to A→B also adds B→A; remove mirrors); a re-entrancy guard prevents infinite mirroring; deleting one side clears the link on the other (it becomes a plain relation, not auto-deleted). **Rationale:** a real stored property (not a computed view) filters/sorts/rolls-up like any relation; write-time sync keeps reads cheap.
2. **`list` is a new `view_type`; grouping + filters are view-config, not schema.** Migration `0013` adds `list` to the `view_type` enum (`ALTER TYPE ADD VALUE`, same pattern as `0011`). Table **grouping** reuses the kanban `groupBy` config field (now honored by table + list too) — no schema change. **Filter operators** expand `src/lib/databases/filter.ts` with per-type ops (text: contains/starts-with/ends-with/is-empty; number/date: =/≠/</≤/>/≥/between/is-empty; select: is/is-not/is-any-of; checkbox: is) — config-only.
3. **Row hierarchy via a self-FK `parent_row_id` on `db_rows`.** Migration `0013` adds nullable `parent_row_id uuid references db_rows(id) on delete set null` + an index. Views render an expand/collapse tree when a parent is set; `listRows` returns `parentRowId`; cycle-prevention on write. **Rationale:** a first-class column keeps hierarchy cheap to query + distinct from user relations.
4. **New block types are TipTap 3 custom nodes, each verified Yjs-safe.** Toggle (collapsible, holds child content), columns (`columnList` > `column`, single-level), simple table (non-database `table`/`tableRow`/`tableCell` via the official extension), embed (allowlist-only iframe: YouTube/Vimeo/Figma/GitHub-gist/CodeSandbox — **D: allowlist enforced under the CSP**, no arbitrary iframes), bookmark (URL → server-side unfurl to title/desc/favicon, cached), math (KaTeX inline + block), and **synced block**. Each is audited for Yjs round-trip like the v0.3.0 custom-node check.
5. **Synced blocks are same-document in v0.6.0; cross-page deferred.** A synced block has a `syncedBlockId`; the *source* is normal editable content, *mirrors* (same page) render the source read-only and update live (same Yjs doc). **D: cross-page synced blocks deferred post-1.0** — they need a shared sub-document model (extra Yjs/Hocuspocus plumbing). Documented limitation.
6. **TOC + outline derive from heading nodes at render — no stored state.** A `tableOfContents` block renders live links from the doc's headings; the outline sidebar is a UI panel reading the same heading list. No schema, no migration.
7. **Full-page databases + a calc footer fold into this release (formerly the v0.6.x "additional features" set).** A database can be opened as a full page (the database is the page body, not an inline block) — a render mode over the existing inline-database tables, no new store. The **calc footer** is a per-column aggregation row (count/sum/avg/min/max/empty/filled) on table + list views, computed at query time and configured in the `db_views` config jsonb (no schema change).

### Sharing & collaboration

8. **Password links: a per-page password *hash* + a short-lived signed access cookie.** The page's share row gains `link_password_hash` (Argon2id, nullable). An anon visitor to a protected `/p/<slug>` sees a gate; on correct password the server sets an HMAC-signed, expiring cookie (`cairn_pub_<pageId>` = `{pageId, exp}` signed with the `AUTH_SECRET`-derived key, scoped path `/p/<slug>`) — **no password stored client-side**, verification reuses the v0.5.0 HMAC helper (no new secret). **Rationale:** stateless, aligned with the existing signed-URL pattern, a wrong password leaks nothing.
9. **Expiry is a stored timestamp checked server-side; "allow duplication" is a boolean.** The share row gains `expires_at timestamptz NULL` and `allow_duplication boolean NOT NULL DEFAULT false`. Public render checks `expires_at` (expired → 404, never 403, matching the existence-non-leak rule). Duplication, when enabled, exposes a "Duplicate to my workspace" action deep-copying the page tree into the authenticated visitor's workspace (anon prompted to sign in). **D: expiry and password are independent toggles; both can be set.**
10. **Per-page sharing extends the existing publish row, not a new ACL system.** v0.2.0's publish path (`/p/<slug>`) row gains the four columns above. No `page_acls` table, no per-block grain. **D: one share config per page — the page is the unit.**
11. **The public site is a workspace-level published flag + a routed mini-site.** A workspace gains `public_site_slug text UNIQUE NULL` + `public_site_enabled boolean`. When enabled, `/s/<workspace-slug>` renders a navigable site of that workspace's *published* pages (those with a publish row) with a generated nav tree from the page hierarchy, reusing the read-only `publicExtensions()` renderer. Individual pages remain at `/p/<slug>`. **D: the site lists only already-published pages — enabling the site does not bulk-publish.** Per-page password/expiry still gate a page within the site.
12. **Comments on databases + files reuse the existing comment store with a polymorphic anchor.** v0.3.0 comments anchor to a page; this release generalizes to `(target_type, target_id)` where `target_type ∈ {page, db_row, file}`. **D: add a `target_type` enum + `target_id` column to the existing `comments` table (back-fill `page` for existing rows)** rather than a second table — one threading/notification path. Row comments anchor to a `db_rows.id`; file comments to a `files.id`.
13. **Suggestion mode is Yjs-native marks + a lightweight index — not a separate proposed-doc store.** Proposed edits live *in the same Yjs doc* as `suggestion-insert` / `suggestion-delete` marks (+ a `suggestion-block` wrapper) carrying `{suggestionId, authorId, createdAt}` in attrs, syncing live like any content. A small `suggestions` table indexes open suggestions for listing/notification/permission **without parsing the doc**; accept/reject flips the mark inside a Yjs transaction and updates the index. **D: Yjs-in-doc marks (not a shadow document).** Only `editor`+ accept/reject; `viewer` may propose only if granted (default: suggestions require `editor`).
14. **Email = BYO-SMTP, opt-in, with an in-process per-event sender + a digest cron — mirroring the webhook delivery model.** SMTP configured by env (`SMTP_HOST`/`PORT`/`USER`/`PASS`/`FROM`/`SECURE`); **if unset, email is fully disabled** (no-op, surfaced in the prefs UI). Per-event mail rides the existing in-process notification queue; digests are a periodic flush (`CAIRN_DIGEST_CRON`, default daily) batching unread notifications per user. **D: nodemailer; no third-party email SaaS; best-effort with retry/backoff like webhooks, failures logged not fatal.** All outbound links/unfurls pass the SSRF guard.
15. **Backlinks via a write-time `page_links` index, not read-time scans.** Page links are a `pageLink` inline node (`{targetPageId, label}`) inserted via `[[`/`@page` autocomplete. On save, `reindexPageLinks(tx, pageId, content)` walks the ProseMirror JSON, extracts `pageLink`/`pageMention`/`pageEmbed` targets, and upserts a `page_links(source_page_id, target_page_id, kind)` table (delete-then-insert per source). "Linked references" queries `page_links WHERE target_page_id = ?`. **Unlinked mentions** are a read-time FTS search (no index). **D: stored index for linked refs; read-time FTS for unlinked mentions.**
16. **Page mentions and page embeds are TipTap 3 custom nodes, Yjs-audited.** `pageMention` (inline, live page title + link), `pageEmbed` (block, read-only snapshot preview via `publicExtensions()`). Both feed `reindexPageLinks` and get read-only variants for `/p/` + `/s/`. **D: page-embed renders a snapshot preview (title + first blocks) with a link through, not a live nested collab doc** — live transclusion needs the deferred sub-document plumbing.
17. **Per-database row templates extend the v0.5.0 templates system.** A database gains optional named row templates in its config (`rowTemplates: [{id, name, cellDefaults, contentTemplate?}]` jsonb — no new table). "New row" gains a template picker. **D: jsonb config on the database, not a new table.**

### Mobile, accessibility & i18n

18. **i18n = a hand-rolled, dependency-light `t()` over flat JSON catalogs — no `next-intl`/`react-intl`.** A `src/lib/i18n/` module: per-locale flat-key JSON (`messages/en.json`, `messages/<proof>.json`), a server `getMessages(locale)` + a client `I18nProvider` exposing `t(key, vars?)` with `{name}`-style interpolation and a count→plural rule. Locale resolves per-request: `cairn_locale` cookie → `Accept-Language` → `en`, set on `<html lang dir>`. **Rationale:** the string surface is large but the *machinery* is tiny; `next-intl` couples routing/middleware we don't want on top of the `src/proxy.ts` auth gate. Missing keys fall back to the key (visible in dev). RTL via `dir` + logical CSS.
19. **Proof locale = a full RTL locale (Arabic, `ar`) — not a "free" Latin one.** Shipping a RTL locale *forces* the RTL-ready CSS to actually be exercised (logical properties, mirrored chevrons/drawers). A machine-assisted `ar` catalog is acceptable for proof; translation correctness is not a 1.0 gate — the *mechanism* is.
20. **Favorites + recents live in one `user_page_prefs` table — NOT a per-view jsonb blob.** Keyed `(user_id, page_id)` with `favorite`, `favorite_order`, `last_visited_at`. **Rationale:** favorites are per-user and recents are high-write — a relational table is queryable/orderable/prunable (cap recents to N) and avoids contention on shared rows. Recents update is a cheap upsert on page open.
21. **Column ergonomics (width/freeze/hide) go in the existing view-config jsonb — NO migration.** Per-view `columnWidths: {propId: px}`, `frozenColumnIds: string[]`, `hiddenColumnIds: string[]` extend the `db_views` config jsonb (the same home as `groupBy`/filters/calc footer).
22. **Offline edits = the Yjs IndexedDB offline provider (`y-indexeddb`) + replay-on-reconnect — NOT a hand-rolled outbox.** Add `y-indexeddb` to persist each opened doc locally; the Hocuspocus provider buffers updates while disconnected and CRDT-merges on reconnect. So "queued simple edits" = ordinary Yjs updates merged automatically. **Scope limit (the risk):** offline editing is supported **only for pages already loaded into IndexedDB this session**; creating pages, structural ops (move/delete), database row mutations, and file uploads are **disabled offline** (UI shows them unavailable). **Rationale:** CRDT merge is the only correctness-safe queue; non-Yjs data has no automatic conflict story — explicitly **not** full offline-first.
23. **Service worker = `@serwist/next` (Workbox-for-Next, App Router), route-scoped strategies.** **precache** the app shell + static assets; **stale-while-revalidate** for the page-read API of recently-visited pages (capped/LRU); **network-first** for navigations (offline-shell fallback); **network-only (never cached)** for all auth, mutations (`POST/PUT/PATCH/DELETE`), `/api/files/*` signed URLs, and the Hocuspocus websocket. **Rationale:** caching mutations or signed file URLs is a correctness + security hazard; the SW only caches idempotent reads + the shell. SW + manifest respect the CSP/nonce.
24. **a11y is a retrofit with codified conventions + an axe CI gate that fails the build.** Conventions: semantic landmarks (`<nav>/<main>/<aside>`), one focus-trap utility for modals/menus (keep native `<details>`/`popover`), visible focus rings, `aria-live` for toasts/save-status, labelled icon-buttons, and **CSS logical properties everywhere** so RTL is automatic. CI runs `@axe-core/playwright` against seeded key screens (editor, sidebar, a database view, a modal, the share dialog, sign-in) and **fails on any WCAG 2.1 AA violation**.
25. **Keyboard shortcuts = a single typed registry + a global dispatcher + a generated ⌘/ sheet; command-palette actions read the same registry.** `src/lib/shortcuts/registry.ts`: each entry `{id, keys, scope, labelKey, run()}` (label via `t()`). A global listener dispatches by scope with conflict detection at registration. The ⌘/ sheet renders the registry grouped by scope. **Command-palette actions** (⌘K) surface the same registry's global entries (new page, toggle theme, switch workspace, go to favorites) alongside navigation search — one source of truth.
26. **Block conversion + multi-select are editor-only ProseMirror commands — Yjs-safe by construction, no schema.** "Turn into" is a `setBlockType`/replace command (slash-menu/`/turn` + selection-toolbar) constrained to compatible node types; multi-select is a ProseMirror multi-node selection (shift-click/drag) enabling bulk delete/move/convert. Ordinary ProseMirror transactions on the existing doc — **no new node types, no migration**.

### Admin, observability, ops & import

27. **Audit log is an append-only `audit_log` table, written by a single `recordAudit(tx, ...)` helper at the action site** (in `src/lib/...` business helpers, not the route). Columns: `id`, `workspace_id`, `actor_user_id` (nullable for system/cron), `action` (text enum, e.g. `member.role_changed`, `member.removed`, `invite.created`, `page.published/unpublished`, `api_key.created/revoked`, `webhook.created/deleted`, `page.deleted`, `database.deleted`, `workspace.settings_changed`, `workspace.ownership_transferred`, `totp.enabled/disabled`, `quota.changed`, `backup.created`, `export.created`, `import.completed`), `target_type` + `target_id`, `metadata` jsonb (before/after diff — **never secrets**), `ip` (nullable), `created_at`. **No updates/deletes** at the app layer (pruning is an explicit admin/CLI action, audited as `audit.pruned`). **Rationale:** writing at the helper records inside the same transaction that performed the action, so the log can't drift.
28. **The per-page activity feed is a *view over* `audit_log`, not a second store.** Rows with `target_type='page'` filtered by `target_id` render the feed. **D: page content edits are NOT individually audited** (version history from v0.5.0 covers content diffs; the feed links to it); the feed records structural/sensitive events.
29. **TOTP via `otplib`, secrets encrypted at rest (not just hashed), recovery codes hashed.** A `user_totp` table holds `user_id` (PK/FK), `secret_encrypted` (the TOTP shared secret — *reversible* to verify codes, so AES-256-GCM with a key derived from `AUTH_SECRET` via HKDF, NOT hashing), `enabled_at`, `last_used_at`, and `recovery_codes` (jsonb array of **hashed** codes, single-use). Enrollment is two-step (show QR/secret → verify a live code → set `enabled_at`). **D: TOTP only; WebAuthn/passkeys deferred post-1.0.** **Rationale:** TOTP secrets must be decryptable; recovery codes are single-use proofs like passwords.
30. **Workspace can *require* 2FA via a settings flag; enforcement at the auth/session boundary.** `workspaces.require_2fa boolean`. On sign-in / session refresh, if any of the user's workspaces requires 2FA and the user has no enabled TOTP, route to forced enrollment; an existing session is challenged on next navigation. **D: the workspace owner must have 2FA enabled before turning on the requirement** (no lockout).
31. **Observability uses `prom-client` for `/metrics` and `pino` for structured JSON logging.** `src/lib/observability/metrics.ts` registers custom metrics: `http_request_duration_seconds` (labels `method`, `route` template (never concrete id), `status`), `http_requests_total`, `db_query_duration_seconds`, `collab_active_connections`, `collab_doc_updates_total`, `webhook_delivery_total`/`_duration_seconds`, `notifications_sent_total`, `backup_runs_total`/`backup_last_success_timestamp`. **D: metrics are aggregate-only and carry NO workspace/user/page identifiers as labels.** `pino` logging emits JSON with a request id, never logging request bodies, `authorization`/`cookie`, API keys, TOTP material, or signed-URL signatures (a redaction list extending the v0.5.1 hygiene rules).
32. **`/metrics` is access-controlled by a bearer token, defaulting to bound-but-protected.** **D: gate `/metrics` behind `CAIRN_METRICS_TOKEN`** — if set, require `Authorization: Bearer <token>`; if unset, **`/metrics` returns 404** (off by default). Avoids an open metrics endpoint footgun on a LAN-reachable homelab box. Documented in `SECURITY.md` + ops docs.
33. **Quotas are nullable columns on a `workspace_quotas` table (one row per workspace, lazily created), enforced at two choke points.** `storage_bytes_limit` (nullable = unlimited), `storage_bytes_used` (counter), `api_rate_limit_per_min` (nullable = global default), `member_limit` (nullable). **D: storage enforced at the file-upload path** (reject + 413-style error when `used + incoming > limit`; counter incremented on store, decremented on delete/trash-purge, with a CLI `reconcile`). **API rate limits ride the v0.5.1 limiter**, parameterized per-workspace. **D: advisory operator-set limits — no billing.**
34. **Saved searches are a `saved_searches` table; the filter/scope payload is jsonb reusing the database filter vocabulary.** Columns include `user_id` (**D: per-user, private; shared/team saved searches deferred**), `name`, `query`, `filters` jsonb (`{author, dateRange, types[], scopeDatabaseId?}`). Search-within-page is a pure runtime feature (no storage). `src/lib/pages/search.ts` gains a structured filter layer compiling author/date/type/scope onto the existing FTS+trigram query.
35. **Due-date reminders ride the existing polled-notification system + a periodic scan; no push, no new transport.** A `reminders` table: `database_id`, `property_id` (date property), `row_id`, `user_id` (**D: default = the row's assignee/`person` property if present, else page/db watchers**), `remind_at` (= date value − a per-reminder `lead_time`), `fired_at` (nullable). A scan (`pnpm cli reminders:scan`, also interval-runnable) finds due reminders, creates a notification via the v0.3.0 path, and stamps `fired_at`. **D: reminders configured per-database, materialized to `reminders` rows on row create/date-edit**, so the scan is a cheap indexed query. **D: cron-able like backups.** Not real-time (fires within one scan interval).
36. **Scheduled backups are a CLI *mode*, scheduled externally; the app does not host a cron daemon.** The v0.5.0 backup CLI gains `--retention-days N`, `--target s3://...|local` (reuses the v0.5.0 S3/MinIO `FileStorage`), and emits backup metrics + an `audit_log` row. **D: the container can't reliably host cron; the mechanism is external cron OR a small documented `CAIRN_BACKUP_INTERVAL`/`CAIRN_REMINDER_INTERVAL` in-process interval ticker that is OFF by default and explicitly single-instance** (two instances double-fire — documented ceiling, consistent with the single-instance collab ceiling). No distributed lock for 1.0.
37. **Notion import is best-effort; reuse the markdown→ProseMirror + templates id-rewrite machinery.** A Notion export ZIP (HTML or Markdown+CSV) is parsed: MD/HTML → the v0.5.0 `marked`-based md→ProseMirror path, CSV → inline databases, the Notion hierarchy → Cairn `parent_id` tree, intra-export links rewritten with the **same id-rewrite pass the v0.5.0 templates system uses** (old → new ids, second-pass fixup). **D: documented fidelity gaps:** synced blocks, complex/computed db properties (become plain values or dropped with a per-item warning), Notion-hosted file URLs (re-hosted if in the ZIP, else external links), comments, exact formatting nuance. Produces an **import report** + an `audit_log` row. Markdown-folder import is the same pipeline minus the Notion CSV/structure conventions.
38. **Workspace export is a single re-importable archive; export/import are inverses.** `pnpm cli export --workspace <id>` (and an admin button) produces a ZIP of pages (ProseMirror JSON + Markdown), databases (schema + rows as JSON + CSV), files (the blobs from `FileStorage`), and a manifest. **D: secrets are NOT exported** (API keys, webhook secrets, TOTP, recovery codes, password hashes excluded — re-importable into a fresh workspace where the importer mints new ids via the templates id-rewrite pass). Per-page/per-database UI export is the same renderers as download buttons (MD/CSV/JSON), plus **PDF export** (**D: via the same headless read-only render already needed for `/p/`** — reuse the read-only node-views so every block type prints).
39. **Bulk operations are a multi-select layer over existing single-item mutations, run in one transaction with a partial-failure report.** Multi-select in the page sidebar and database views → move / delete (trash) / duplicate / tag / bulk trash-restore. **D: reuse the existing per-item helpers in a loop inside a transaction, role-checked once up front, returning `{succeeded, failed:[{id, reason}]}`** — correctness + permission reuse over raw speed. Bulk actions are audited as a single `*.bulk` row with a count.
40. **Workspace-home / default-landing is a `workspaces.home_page_id` (nullable) setting in admin.** **D:** if set, opening the workspace lands on that page; if null, falls back to last-visited / first page. Settable by `owner`/`admin`. No new table.

## 3. Scope

### In scope

**Content & database**
- Reverse relations (config link + write-time bi-directional sync + UI toggle).
- `list` view type + table/list grouping + expanded filter operators + multi-sort UI.
- Row hierarchy (`parent_row_id` + expand/collapse + set-parent UI + cycle guard).
- New blocks: toggle, columns, simple table, embed (allowlist), bookmark (unfurl), math (KaTeX), same-page synced block — nodes + node-views + slash-menu + read-only/public variants + Yjs-safety.
- TOC block + outline sidebar.
- Full-page databases (render mode) + per-column calc footer (config jsonb).

**Sharing & collaboration**
- Per-page share settings: password (Argon2id + signed cookie), expiry, allow-duplication (+ duplicate-to-workspace action) — UI on the existing share/publish panel.
- Public site: `public_site_slug` + `public_site_enabled` on workspace; `/s/<workspace-slug>` mini-site (nav tree + read-only render); per-page password/expiry still enforced within it.
- Comments on databases + files: polymorphic `(target_type, target_id)` anchor; row + file threads; notifications/@mentions reuse the v0.3.0 path.
- Suggestion mode: Yjs `suggestion-insert`/`-delete`/`-block` marks + `suggestions` index; propose/accept/reject; role gating; read-only suggestion rendering.
- Email notifications: BYO-SMTP (nodemailer), opt-in per-event + digest cron, notification-preferences UI, clean no-op when SMTP unset.
- Wiki/links: `pageLink` node + `[[`/`@page` autocomplete; `page_links` index + "Linked references" panel; unlinked-mentions read-time search; `pageMention` + `pageEmbed` (snapshot).
- Per-database row templates: jsonb `rowTemplates` config + "new row from template" picker.

**Mobile, a11y & i18n**
- Responsive UI: editor breakpoint pass; sidebar off-canvas drawer below `md`; database table/kanban/gallery/list adapt (horizontal scroll + sticky frozen cols, swipeable kanban); touch targets ≥44px; collapsing header/toolbar.
- PWA: manifest (name/icons/theme-color/standalone), installability, maskable icons, offline fallback page; `@serwist/next` SW with the strategy map (decision 23).
- Offline (bounded): `y-indexeddb` on opened docs; read recently-viewed pages offline; edit loaded docs → CRDT-merge on reconnect; offline status indicator + disabled-when-offline affordances.
- Accessibility (WCAG 2.1 AA): keyboard nav everywhere, focus management + shared focus-trap util, ARIA roles/labels/`aria-live`, AA contrast audit (light + dark), screen-reader pass; `@axe-core/playwright` CI gate.
- Keyboard shortcuts: registry + dispatcher + ⌘/ sheet + conflict detection.
- i18n: `src/lib/i18n/` (`t()`, provider, resolution), externalize all strings into `en.json` + proof `ar.json`, settings locale switcher, `<html lang dir>`, RTL logical CSS.
- Column ergonomics (width/freeze/hide, config jsonb); favorites/pinned + recents (`user_page_prefs`) in the sidebar; command-palette actions; block conversion + multi-select.

**Admin, observability, ops & import**
- Admin console (`/workspace/[slug]/admin`, `admin`+): members list (role change + remove); invites (create/revoke/list); workspace settings (name, icon, default-role, `require_2fa`, `home_page_id`); transfer ownership (owner-only, both confirm); delete workspace (owner-only, typed-confirm, cascade + audit) — closes the v0.2.0 sole-owner-leave follow-ups.
- Audit log (`audit_log` + `recordAudit` wired into all sensitive sites) + admin viewer + per-page activity feed (view over the same table).
- 2FA TOTP (`user_totp`; enroll/confirm/disable; sign-in challenge; recovery codes; `require_2fa` enforcement; admin toggle).
- Observability: `prom-client` `/metrics` (token-gated, off by default) + `pino` JSON logging with redaction; instrument request/db/collab/webhook/notification/backup paths.
- Quotas: `workspace_quotas`; storage enforcement at upload + counter + `reconcile` CLI; per-workspace API rate limit; admin UI.
- Scheduled backups: CLI `--retention-days`, `--target`, metrics + audit; documented external-cron / opt-in interval.

## 4. Data model (migrations `0013`–`0022`, contiguous, no collisions)

> Renumbered into one sequential set continuing from v0.5.1's last migration. `ALTER TYPE ADD VALUE` (any enum *addition*) runs **outside a transaction** (the `0011` precedent). `CREATE TYPE` for new enums is transactional.

```
-- 0013  content & database (view_type + row hierarchy)
view_type:        + 'list'                       -- ALTER TYPE ADD VALUE (outside txn; 0011 precedent)
db_rows:          + parent_row_id uuid NULL references db_rows(id) on delete set null
                  + index db_rows(parent_row_id)
-- relation reversePropertyId, grouping, filters, calc footer, column ergonomics,
-- full-page-database mode, row templates: all config jsonb — NO schema change.

-- 0014  per-page share settings (extends the v0.2.0 publish row)
share row:        + link_password_hash   text NULL          -- Argon2id; NULL = no password
                  + expires_at           timestamptz NULL    -- NULL = no expiry
                  + allow_duplication    boolean NOT NULL DEFAULT false

-- 0015  public site (workspaces)
workspaces:       + public_site_slug     text UNIQUE NULL
                  + public_site_enabled  boolean NOT NULL DEFAULT false

-- 0016  polymorphic comments
comment_target:   NEW enum ('page','db_row','file')          -- CREATE TYPE (transactional)
comments:         + target_type comment_target NOT NULL DEFAULT 'page'
                  + target_id   uuid NULL                     -- back-fill = page_id for existing rows
                  + index comments(target_type, target_id)

-- 0017  suggestions index
suggestion_status: NEW enum ('open','accepted','rejected')   -- CREATE TYPE
suggestions:      id uuid pk, page_id uuid REF pages(id) ON DELETE CASCADE,
                  author_id uuid REF users(id),
                  status suggestion_status NOT NULL DEFAULT 'open',
                  created_at timestamptz NOT NULL DEFAULT now(),
                  resolved_at timestamptz NULL, resolved_by uuid NULL
                  + index suggestions(page_id, status)

-- 0018  page links index + email prefs
page_link_kind:   NEW enum ('link','mention','embed')         -- CREATE TYPE
page_links:       source_page_id uuid REF pages(id) ON DELETE CASCADE,
                  target_page_id uuid REF pages(id) ON DELETE CASCADE,
                  kind page_link_kind NOT NULL,
                  PRIMARY KEY (source_page_id, target_page_id, kind)
                  + index page_links(target_page_id)            -- the backlinks query
notification_email_prefs: user_id uuid, workspace_id uuid, notification_type text,
                  email_enabled boolean NOT NULL DEFAULT false,
                  digest_only   boolean NOT NULL DEFAULT false,
                  PRIMARY KEY (user_id, workspace_id, notification_type)

-- 0019  favorites + recents
user_page_prefs:  id uuid pk default gen_random_uuid(),
                  user_id      uuid NOT NULL references users(id)      on delete cascade,
                  workspace_id uuid NOT NULL references workspaces(id) on delete cascade,
                  page_id      uuid NOT NULL references pages(id)      on delete cascade,
                  favorite        boolean NOT NULL default false,
                  favorite_order  integer NULL,
                  last_visited_at timestamptz NULL,
                  created_at timestamptz NOT NULL default now(),
                  updated_at timestamptz NOT NULL default now(),
                  unique (user_id, page_id)
                  + index (user_id, favorite, favorite_order)    -- favorites list
                  + index (user_id, last_visited_at desc)        -- recents list

-- 0020  admin + audit + 2FA
audit_log:        id uuid pk, workspace_id uuid fk, actor_user_id uuid NULL fk,
                  action text NOT NULL,                  -- documented enum-like set in §2.27
                  target_type text NULL, target_id uuid NULL,
                  metadata jsonb NOT NULL default '{}',  -- ids/role-names/flags only; NEVER secrets
                  ip text NULL, created_at timestamptz NOT NULL default now()
                  + index audit_log(workspace_id, created_at desc)
                  + index audit_log(workspace_id, target_type, target_id)   -- per-page feed
user_totp:        user_id uuid pk fk, secret_encrypted bytea NOT NULL,      -- AES-256-GCM (HKDF from AUTH_SECRET)
                  recovery_codes jsonb NOT NULL default '[]',               -- array of {hash, usedAt|null}
                  enabled_at timestamptz NULL, last_used_at timestamptz NULL,
                  created_at timestamptz NOT NULL default now()
workspaces:       + require_2fa  boolean NOT NULL default false
                  + home_page_id uuid NULL references pages(id) on delete set null

-- 0021  quotas + saved searches + reminders
workspace_quotas: workspace_id uuid pk fk,
                  storage_bytes_limit bigint NULL, storage_bytes_used bigint NOT NULL default 0,
                  api_rate_limit_per_min integer NULL, member_limit integer NULL,
                  updated_at timestamptz NOT NULL default now()
saved_searches:   id uuid pk, workspace_id uuid fk, user_id uuid fk,
                  name text NOT NULL, query text NOT NULL default '',
                  filters jsonb NOT NULL default '{}',           -- {author,dateRange,types[],scopeDatabaseId?}
                  created_at timestamptz NOT NULL default now()
                  + index saved_searches(workspace_id, user_id)
reminders:        id uuid pk, workspace_id uuid fk, database_id uuid fk, property_id uuid NOT NULL,
                  row_id uuid fk, user_id uuid fk,
                  remind_at timestamptz NOT NULL, fired_at timestamptz NULL,
                  created_at timestamptz NOT NULL default now()
                  + index reminders(remind_at) where fired_at is null   -- partial index; cheap scan
-- db_properties.config jsonb: + optional reminder config {datePropertyId, leadTime} — no schema change

-- 0022  import bookkeeping (small)
import_jobs:      id uuid pk, workspace_id uuid fk, actor_user_id uuid fk,
                  source text NOT NULL,                  -- 'notion' | 'markdown-folder' | 'workspace-archive'
                  status text NOT NULL,                  -- 'running' | 'completed' | 'failed'
                  report jsonb NOT NULL default '{}',    -- counts + skipped/degraded items
                  created_at timestamptz, completed_at timestamptz NULL
```

**No schema change** for: relation `reversePropertyId`, grouping/filters/multi-sort, calc footer, full-page-database mode, column ergonomics, row templates (`rowTemplates`) — all `db_views`/`databases`/`db_properties` config jsonb; new block/mention/embed/link node attrs + suggestion marks (live in `pages.content`, only derived `page_links` + `suggestions` are tables); TOC/outline (render-derived); offline (`y-indexeddb`, client-only); shortcuts/i18n/a11y/block-conversion/multi-select (client/editor only); search filters (compiled at query time); bulk ops (loop over existing helpers); per-page activity feed (view over `audit_log`); per-page/db/PDF/workspace export (renderers over existing content). The bookmark unfurl cache stores `{title, description, favicon, image}` in the node's attrs at insert time, re-unfurled on demand via a small SSRF-guarded `/api/unfurl?url=`. Quota counter `storage_bytes_used` is maintained transactionally at file store/delete + a CLI `reconcile` recomputes from `FileStorage` truth.

Only `0013` introduces an enum *addition* (`view_type +list`, outside-txn). `0016`/`0017`/`0018` create new enums in-transaction. A future revision adding a value to any existing enum must run outside a transaction (the `0011` precedent).

## 8. Risks

- **This is a very large single release (~23 plans).** Execute area-by-area in the §7 order; keep each plan independently shippable/reviewable; the size raises integration + review burden materially — do not start a later area before the prior area's plans are green, and budget review/smoke time per area, not just at the end. The combined-smoke plan (P23) is the integration backstop, not a substitute for per-plan verification.
- **Yjs-safety of new nodes** is the recurring constraint — columns/toggle/synced/`pageEmbed`/`pageMention`/`pageLink` and the `suggestion-*` marks hold nested content or structure; verify each round-trips through Yjs before shipping (the v0.3.0 audit). The `y-indexeddb` offline-edit→reconnect→merge path is part of this audit.
- **Reverse-relation write sync** can loop or deadlock — the re-entrancy guard + same-transaction writes must be exhaustively tested (add/remove, both directions, deleting a paired property).
- **Suggestion mode is the hardest collab surface** (roadmap **High**) — Yjs-in-doc marks must accept/reject correctly under concurrent edits; the index must never drift from the marks. Scope strictly to insert/delete/block proposals + accept/reject; no comment-on-suggestion threading.
- **Password-link / public-site is a fresh anon attack surface** — wrong password, expired link, unpublished page must all 404 (never 403, never a render); the signed cookie must be unforgeable + non-replayable; reuse the v0.5.0 HMAC signer + SSRF guard (no new secrets).
- **Embeds + unfurl are an SSRF/XSS surface** — embeds are allowlist-only and sandboxed; the unfurl endpoint reuses the v0.5.0 SSRF guard; both get security tests.
- **Email delivery is best-effort, not transactional** — a down SMTP server must never block a notification or request (retry/backoff, log failures, never fatal); the SMTP-unset path is a clean no-op surfaced in the UI.
- **Page-link reindex on every save** is bounded by the page's own link count; the backlinks read is indexed on `target_page_id`; unlinked mentions stay read-time. Watch save-path latency on link-heavy pages.
- **PWA offline + Yjs is the riskiest correctness surface.** The mitigation is the hard scope boundary: only Yjs-doc edits on already-loaded pages are CRDT-merged; everything non-Yjs (create/move/delete/db-rows/uploads) is *disabled* offline, not silently queued. Do NOT drift toward full offline-first.
- **Service-worker caching is a correctness + security hazard if mis-scoped** — caching a mutation, an auth response, or a signed `/api/files` URL is a bug. The strategy map is allow-listed to idempotent reads + the shell; assert it in tests; keep SW registration CSP/nonce-clean.
- **a11y retrofit rots without a gate** — the `@axe-core/playwright` CI gate failing the build is the load-bearing mitigation; manual screen-reader passes catch what axe can't.
- **i18n externalization is a large mechanical sweep** — missing-key→key fallback keeps it non-fatal; the `ar` RTL proof surfaces hardcoded physical-CSS/LTR assumptions a Latin proof would hide.
- **Shortcut/registry drift + conflicts** — registration-time conflict detection + the single-source-of-truth registry (sheet + palette + dispatcher all read it) prevent "the sheet lies" bugs.
- **Secret handling (admin/ops).** TOTP secrets must be *encrypted* (reversible), recovery codes *hashed* (one-way) — getting these backwards breaks 2FA or leaks secrets. Extend the v0.5.1 secret-leak test to cover all new secret classes before shipping.
- **`/metrics` leakage / footgun** — off-by-default (404 unless token set), bearer-gated, aggregate-only labels (route template, no tenant labels), asserted in tests.
- **Locking yourself out via `require_2fa`** — owner must enroll before enabling the requirement; recovery codes; exhaustive auth-callback tests; a CLI escape hatch (`totp:disable --user`) documented.
- **Notion import fidelity** — best-effort; the risk is silent data loss. The import report enumerates every skipped/degraded item; documented gap list; reuse the proven md→ProseMirror + id-rewrite machinery.
- **Scheduling on a single-instance app** — no in-container cron daemon; the interval ticker double-fires under multiple instances. External cron is recommended; the in-process interval is opt-in + single-instance-only (no distributed lock for 1.0).
- **Quota counter drift** — `storage_bytes_used` can drift under crashes/partial deletes; maintained transactionally at store/delete + a `reconcile` CLI to recompute from `FileStorage` truth.
- **Audit-log growth** — append-only + no per-keystroke auditing keeps it bounded; pruning is an explicit, audited admin/CLI action; indexed by `(workspace_id, created_at)`.
- **Migration `0013` `ALTER TYPE ADD VALUE`** — the only enum *addition* in this release; same outside-transaction handling as `0011`. `0016`/`0017`/`0018` create new enums in-transaction.
- **Polymorphic comment back-fill** — `0016` must back-fill `target_type='page'` + `target_id=page_id` for every existing comment in the same migration, or threads detach; covered by an integration test on a seeded dataset.

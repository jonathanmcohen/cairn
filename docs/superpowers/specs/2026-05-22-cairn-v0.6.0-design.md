# Cairn v0.6.0 — Content & Database Completeness Design

**Status:** Draft (autonomously specced at the user's direction; all design decisions mine, flagged below; revisit before building).
**Date:** 2026-05-22
**Target release:** v0.6.0
**Builds on:** v0.5.1 (security) — first release of the road-to-1.0 (`roadmap-0.6-to-1.0.md`).

## 1. Purpose

Close the editor + database gaps that still separate Cairn from Notion parity: **reverse relations**, a **list view** + **table grouping** + **richer filters/sort**, **row hierarchy (sub-items)**, several **new block types**, and a **table of contents + outline**. Self-contained in the editor + database subsystems — no auth/collab/API infra changes, though every new editor node must remain Yjs-serializable (the v0.3.0 collab constraint).

## 2. Key decisions (mine; revisit before building)

1. **Reverse relations are an explicit, paired property — synced on write, loop-guarded.** Creating a `relation` property gains a "create reverse property" option. When set, a mirrored `relation` property is created on the target database; the two are linked by a `reversePropertyId` in each one's config. Cell writes maintain both sides inside the existing write transaction (add to A→B also adds B→A; remove mirrors). A re-entrancy guard prevents infinite mirroring. Deleting one side clears the link on the other (the other becomes a plain relation, not auto-deleted). **Rationale:** a real stored property (not a computed view) so it filters/sorts/rolls-up like any relation; write-time sync keeps reads cheap.
2. **`list` is a new `view_type`; grouping + filters are view-config, not schema.** Migration `0013` adds `list` to the `view_type` enum (`ALTER TYPE ADD VALUE`, same pattern as `0011`). Table **grouping** reuses the kanban `groupBy` config field (now honored by table + list views too) — no schema change. **Filter operators** expand the existing `src/lib/databases/filter.ts` compiler with per-type ops (text: contains/starts-with/ends-with/is-empty; number/date: =/≠/</≤/>/≥/between/is-empty; select: is/is-not/is-any-of; checkbox: is) — config-only.
3. **Row hierarchy via a self-FK `parent_row_id` on `db_rows`.** Migration `0013` adds nullable `parent_row_id uuid references db_rows(id) on delete set null` + an index. Views render an expand/collapse tree when a parent is set; `listRows` returns `parentRowId`; cycle-prevention on write (a row can't be its own ancestor). **Rationale:** a first-class column (not a relation) keeps hierarchy cheap to query + distinct from user relations.
4. **New block types are TipTap 3 custom nodes, each verified Yjs-safe.** Toggle (collapsible, holds child content), columns (a `columnList` > `column` structure), simple table (non-database `table`/`tableRow`/`tableCell` — TipTap has an official table extension), embed (allowlist-only iframe: YouTube/Vimeo/Figma/GitHub-gist/CodeSandbox — **D: allowlist enforced under the CSP**, no arbitrary iframes), bookmark (URL → server-side unfurl to title/desc/favicon, cached), math (KaTeX inline + block), and **synced block**. Each is audited for Yjs round-trip like the v0.3.0 custom-node check.
5. **Synced blocks are same-document in v0.6.0; cross-page deferred.** A synced block has a `syncedBlockId`; the *source* is normal editable content, *mirrors* (same page) render the source's content read-only and update live (same Yjs doc). **D: cross-page synced blocks deferred to v0.6.x** — they need a shared sub-document model (extra Yjs/Hocuspocus plumbing) not worth blocking v0.6.0. Documented limitation.
6. **TOC + outline derive from heading nodes at render — no stored state.** A `tableOfContents` block renders links from the doc's headings (live). The outline sidebar is a UI panel reading the same heading list. No schema, no migration.

## 3. Scope

### In scope
- Reverse relations (config link + write-time bi-directional sync + UI toggle on the relation property panel).
- `list` view type (migration `0013`) + table/list grouping (config) + expanded filter operators + multi-sort UI.
- Row hierarchy: `parent_row_id` (migration `0013`) + expand/collapse in table/list + set-parent UI + cycle guard.
- New blocks: toggle, columns, simple table, embed (allowlist), bookmark (unfurl), math (KaTeX), same-page synced block — nodes + node-views + slash-menu entries + read-only/public variants + Yjs-safety.
- TOC block + outline sidebar.
- Migration `0013` (view_type `+list`; `db_rows.parent_row_id`).

### Deferred
- Cross-page synced blocks → v0.6.x (shared sub-doc model).
- Arbitrary iframe embeds → allowlist only (security/CSP).
- Conditional formatting / per-view column widths / table calc-footer → later (candidate for the v1.0 "additional features" set).
- Nested column-in-column beyond one level → keep columns single-level for v0.6.0.

## 4. Data model (migration `0013`)
```
view_type:        + 'list'                       -- ALTER TYPE ADD VALUE (outside txn; see 0011 precedent)
db_rows:          + parent_row_id uuid NULL references db_rows(id) on delete set null
                  + index db_rows(parent_row_id)
```
- Relation config gains optional `reversePropertyId: string` (jsonb — no schema change to `db_properties.config`).
- New block content lives in `pages.content` (ProseMirror JSON) — no schema. `syncedBlockId`, `embed.url`/`provider`, `bookmark.url`/cached-meta, `math.latex`, `columnList`/`column`, `toggle` are node attrs/structure.
- Bookmark unfurl cache: **D: store the unfurled `{title, description, favicon, image}` in the bookmark node's attrs at insert time** (no new table) — re-unfurl on demand via a small `/api/unfurl?url=` (SSRF-guarded, reusing the v0.5.0 webhook SSRF guard).

## 5. Architecture by area
- **Reverse relations:** extend `src/lib/databases/relations.ts` — `createProperty` for a relation with `createReverse:true` creates the paired property + links both configs; a `syncRelationCells(tx, ...)` helper (called from `createRow`/`updateCells`, beside the existing `validateRelationCells`) mirrors adds/removes with a re-entrancy guard. Property-panel relation editor gains the toggle.
- **Views:** `src/lib/databases/views.ts` validates `list` config (+ optional `groupBy`); `src/components/databases/list-view.tsx` (new); `src/lib/databases/filter.ts` gains the per-type operator table + tests; table view honors `groupBy`. Multi-sort UI in the view config panel.
- **Row hierarchy:** schema + `listRows` returns `parentRowId`; a `setRowParent(tx, {rowId, parentId})` with ancestor-cycle check; table/list render indented expand/collapse.
- **Blocks:** `src/components/editor/blocks/*` — one file per node (`toggle.ts`, `columns.ts`, `table.ts` [wrap `@tiptap/extension-table`], `embed.ts`, `bookmark.ts`, `math.ts` [KaTeX], `synced-block.ts`) + React node-views; register in `baseExtensions()` + `publicExtensions()` (read-only variants for `/p/`); slash-menu entries. New deps: `@tiptap/extension-table` (+ row/cell/header), `katex`, a lightweight unfurl lib or hand-rolled OG-tag parser.
- **TOC/outline:** `tableOfContents` node (renders from `editor` headings) + `src/components/editor/outline.tsx` panel toggled in the page header.
- **Public/read-only:** every new node gets a read-only node-view so published `/p/` pages render them (embeds become static thumbnails or sandboxed allowlist iframes; bookmarks render the cached card; math renders KaTeX; synced/toggle/columns/table render their content).

## 6. Testing
- **Unit:** filter operator compiler (per type, all ops), reverse-relation sync (add/remove mirrors, loop guard), row-hierarchy cycle guard, KaTeX render helper, unfurl OG-parser, allowlist embed-URL validator (+ SSRF on unfurl).
- **Integration (Testcontainers):** migration `0013`; `createProperty` reverse-pair creation + `createRow`/`updateCells` bi-directional sync; `listRows` returns `parentRowId` + grouped/filtered/sorted results; `list` view CRUD.
- **Build-verified:** all new block node-views + list view + outline; Yjs round-trip for each new node (mirror the v0.3.0 custom-node audit — a doc containing every new block survives encode→decode).

## 7. Plan decomposition (~6 plans)
1. **Reverse relations** — config link, `syncRelationCells`, write-site wiring, panel toggle, tests.
2. **List view + grouping + filters + multi-sort** — `0013` (view_type `+list`), filter-operator compiler, list-view component, table grouping, sort UI.
3. **Row hierarchy** — `0013` (`parent_row_id`), `setRowParent` + cycle guard, `listRows` parentRowId, expand/collapse UI.
4. **Blocks pt.1** — toggle, columns, simple table, divider polish; node-views + slash menu + read-only variants + Yjs audit.
5. **Blocks pt.2** — embed (allowlist), bookmark (`/api/unfurl` SSRF-guarded), math (KaTeX), same-page synced block.
6. **TOC + outline + release** — TOC node + outline panel; cross-feature smoke; README/CHANGELOG; version bump `0.6.0`; human-run tag (multi-arch pipeline).

## 8. Risks
- **Yjs-safety of new nodes** is the recurring risk — columns/toggle/synced hold nested content; verify each round-trips through Yjs (the collab constraint) before shipping, per the v0.3.0 audit.
- **Reverse-relation write sync** can loop or deadlock — the re-entrancy guard + same-transaction writes must be exhaustively tested (add/remove, both directions, deleting a paired property).
- **Synced blocks** are the hardest; scoping to same-page in v0.6.0 keeps it tractable — do NOT silently start cross-page.
- **Embeds + unfurl are an SSRF/XSS surface** — embeds are allowlist-only and sandboxed; the unfurl endpoint reuses the v0.5.0 SSRF guard; both get security tests (extends the v0.5.1 suite).
- **Migration `0013` `ALTER TYPE ADD VALUE`** — same outside-transaction handling as `0011`.

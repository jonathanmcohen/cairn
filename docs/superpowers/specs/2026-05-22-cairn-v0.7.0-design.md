# Cairn v0.7.0 — Sharing & Collaboration Depth Design

**Status:** Draft (autonomously specced at the user's direction; all design decisions mine, flagged below; revisit before building).
**Date:** 2026-05-22
**Target release:** v0.7.0
**Builds on:** v0.6.0 (content & database completeness) — second release of the road-to-1.0 (`roadmap-0.6-to-1.0.md`).

## 1. Purpose

Deepen Cairn's sharing surfaces and multiplayer on top of the now-stable collab layer: **per-page share settings** (password-protected public links, link expiry, "allow duplication"), a **published multi-page public site** at `/s/<workspace-slug>`, **comments on databases + files** (deferred from v0.3.0), a **suggestion / track-changes mode** in the editor (built on Yjs), and **opt-in email notifications** via BYO-SMTP with a preferences UI. It also lands the §9 wiki/knowledge-graph items slotted to v0.7: **page links + backlinks + unlinked mentions** (`[[`/`@page` autocomplete), **inline page mentions / page embeds**, and **per-database row templates** (extending the v0.5.0 templates system).

Sharing is **per-page**, never per-block — true per-block ACLs are an explicit 1.0 non-goal (v1.0.0 §4, D3). Every new editor node (page-mention, page-embed, suggestion marks) must stay **Yjs-serializable** (the v0.3.0 collab constraint), and every new public/anon surface reuses the existing security model (HMAC-signed access, CSP nonce, SSRF guard) with security tests extending the v0.5.1 suite.

## 2. Key decisions (mine; revisit before building)

1. **Password links: a per-page password *hash* + a short-lived signed access cookie.** A page's share row gains `link_password_hash` (Argon2id, nullable). An anon visitor to a protected `/p/<slug>` sees a gate; on correct password the server sets an HMAC-signed, expiring cookie (`cairn_pub_<pageId>`, value = `{pageId, exp}` signed with the existing `AUTH_SECRET`-derived key, scoped path `/p/<slug>`) — **no password is ever stored client-side**, and verification reuses the v0.5.0 HMAC helper, not a new secret. **Rationale:** stateless (no server session table for anon), aligned with the existing signed-URL pattern, and a wrong password leaks nothing.
2. **Expiry is a stored timestamp checked server-side; "allow duplication" is a boolean.** The share row gains `expires_at timestamptz NULL` and `allow_duplication boolean NOT NULL DEFAULT false`. Public render checks `expires_at` (expired → 404, never 403, to match the existing existence-non-leak rule). Duplication, when enabled, exposes a "Duplicate to my workspace" action that deep-copies the page tree into the authenticated visitor's workspace (anon visitors are prompted to sign in first). **D: expiry and password are independent toggles; both can be set.**
3. **Per-page sharing extends the existing publish row, not a new ACL system.** v0.2.0 added a publish path (`/p/<slug>`); v0.7.0 reuses that row (whatever holds `slug` + `published_at`) and adds the four columns above. No `page_acls` table, no per-block grain. **D: one share config per page — the page is the unit.**
4. **The public site is a workspace-level published flag + a routed mini-site.** A workspace gains `public_site_slug text UNIQUE NULL` + `public_site_enabled boolean`. When enabled, `/s/<workspace-slug>` renders a navigable site of that workspace's *published* pages (those with a publish row), with a generated nav tree from the page hierarchy, reusing the read-only `publicExtensions()` renderer. Individual pages remain reachable at `/p/<slug>`; the site is an index + nav shell over them. **D: the site lists only already-published pages — enabling the site does not bulk-publish; publishing stays per-page.** Password/expiry on an individual page still gate it within the site.
5. **Comments on databases + files reuse the existing comment store with a polymorphic anchor.** v0.3.0 comments anchor to a page (+ optional block/text range). v0.7.0 generalizes the anchor to `(target_type, target_id)` where `target_type ∈ {page, db_row, file}`. **D: add a `target_type` enum + `target_id` column to the existing `comments` table (back-fill `page` for existing rows) rather than a second comments table** — keeps one threading/notification/reaction path. Row comments anchor to a `db_rows.id`; file comments to a `files.id`.
6. **Suggestion mode is Yjs-native marks + a lightweight suggestions index — not a separate proposed-doc store.** Proposed edits live *in the same Yjs doc* as `suggestion-insert` / `suggestion-delete` marks (and a `suggestion-block` wrapper for block-level proposals) carrying `{suggestionId, authorId, createdAt}` in mark attrs — so they sync live like any other content and survive the collab round-trip. A small `suggestions` table indexes open suggestions `(id, page_id, author_id, status, created_at)` for listing/notification/permission **without parsing the doc**; accept/reject flips the mark (insert→plain text / delete→remove) inside a Yjs transaction and updates the index. **D: Yjs-in-doc marks (not a shadow document) — a shadow doc would double the collab surface and desync; viewers see suggestions inline, editors accept/reject.** Only `editor`+ roles accept/reject; `viewer` may propose only if granted (config) — default: suggestions require `editor`.
7. **Email = BYO-SMTP, opt-in, with an in-process per-event sender + a digest cron — mirroring the webhook delivery model.** SMTP is configured by env (`SMTP_HOST`/`PORT`/`USER`/`PASS`/`FROM`/`SECURE`); **if unset, email is fully disabled** (no-op, surfaced in the prefs UI as "email not configured by the operator"). Per-event mail rides the existing in-process notification queue (the webhook precedent) — when a notification is created and the user opted into email-for-that-type, enqueue a send. Digests are a periodic flush (`CAIRN_DIGEST_CRON`, default daily) that batches unread notifications per user into one email. **D: nodemailer for SMTP; no third-party email SaaS; sender is best-effort with retry/backoff like webhooks, failures logged not fatal.** All outbound links/unfurled content in emails pass the SSRF guard.
8. **Backlinks via a write-time `page_links` index, not read-time scans.** Page links are a `pageLink` inline node (`{targetPageId, label}`) inserted via `[[`/`@page` autocomplete. On page save, a `reindexPageLinks(tx, pageId, content)` walks the ProseMirror JSON, extracts `pageLink`/`pageMention`/`pageEmbed` targets, and upserts a `page_links(source_page_id, target_page_id, kind)` table (delete-then-insert for that source). The "Linked references" panel queries `page_links WHERE target_page_id = ?`. **Unlinked mentions** are a read-time search (FTS on the target page's title across other pages' `content_text`) — cheap and need no index. **D: stored `page_links` table for linked refs (consistent, fast, drives notifications on link); read-time FTS for unlinked mentions (no index churn for a soft signal).**
9. **Page mentions and page embeds are TipTap 3 custom nodes, Yjs-audited like v0.6.0 blocks.** `pageMention` (inline, renders the live page title + link, updates if the page is renamed/trashed), `pageEmbed` (block, renders a read-only preview/transclusion of the target page's content via `publicExtensions()`). Both feed `reindexPageLinks` (decision 8) and both get read-only variants for `/p/` + `/s/`. **D: page-embed renders a *snapshot preview* (title + first blocks) with a link through, not a live nested collab doc — live transclusion needs sub-document plumbing (the v0.6.0 cross-page-synced-block deferral) and is out of scope.**
10. **Per-database row templates extend the v0.5.0 templates system.** A database gains optional named row templates stored in the database config (`rowTemplates: [{id, name, cellDefaults, contentTemplate?}]` jsonb — no new table, mirroring how v0.6.0 kept relation config in jsonb). "New row" gains a template picker; choosing one pre-fills cells (and the row's page body if `contentTemplate` is set). **D: jsonb config on the database, not a new table — row templates are small, per-database, and edited with the database, like views.**

## 3. Scope

### In scope
- **Per-page share settings:** password (Argon2id hash + signed access cookie), expiry (`expires_at`), "allow duplication" (boolean + duplicate-to-workspace action) — UI on the existing share/publish panel.
- **Public site:** `public_site_slug` + `public_site_enabled` on workspace; `/s/<workspace-slug>` mini-site (nav tree of published pages + read-only render); per-page password/expiry still enforced within it.
- **Comments on databases + files:** polymorphic `(target_type, target_id)` anchor on the existing `comments` table; row + file comment threads; notifications/@mentions reuse the v0.3.0 path.
- **Suggestion mode:** Yjs `suggestion-insert`/`suggestion-delete`/`suggestion-block` marks + `suggestions` index table; propose / accept / reject; role gating; read-only suggestion rendering.
- **Email notifications:** BYO-SMTP (nodemailer), opt-in per-event + digest cron, notification-preferences UI (per-type, email vs in-app), disabled cleanly when SMTP unset.
- **Wiki/links:** `pageLink` node + `[[`/`@page` autocomplete; `page_links` write-time index + "Linked references" (backlinks) panel; unlinked-mentions read-time search; `pageMention` + `pageEmbed` nodes (snapshot preview).
- **Per-database row templates:** jsonb `rowTemplates` config + "new row from template" picker.
- **Migrations `0014`+** (see §4).

### Deferred
- **True per-block ACLs** → post-1.0 non-goal (D3); page is the sharing unit.
- **Live page-embed transclusion** (nested collab doc) → out of scope; embeds are snapshot previews (decision 9), same rationale as v0.6.0 cross-page synced blocks.
- **Guest access** (per-page external collaborators without membership) → post-1.0 (v1.0.0 §9); per-page password sharing covers the common case.
- **Graph view** of `page_links` → post-1.0 (v1.0.0 §9 defer); the index exists, the visualization doesn't.
- **Comment reactions/emoji** → post-1.0 (v1.0.0 §9 defer).
- **Third-party email SaaS / transactional providers** → never (self-hostable BYO-SMTP only, D7/decision 7).

## 4. Data model (migrations `0014`+)

`0013` was the last v0.6.0 migration (view_type `+list`, `db_rows.parent_row_id`). v0.7.0 continues from `0014`.

```
0014  share settings (extends the v0.2.0 publish row):
        + link_password_hash   text NULL          -- Argon2id; NULL = no password
        + expires_at           timestamptz NULL    -- NULL = no expiry
        + allow_duplication    boolean NOT NULL DEFAULT false

0015  public site (workspaces):
        + public_site_slug     text UNIQUE NULL
        + public_site_enabled  boolean NOT NULL DEFAULT false

0016  polymorphic comments:
        comment_target: NEW enum ('page','db_row','file')   -- CREATE TYPE
        comments + target_type comment_target NOT NULL DEFAULT 'page'
        comments + target_id   uuid NULL                    -- back-fill = page_id for existing rows
                 + index comments(target_type, target_id)
        -- NOTE: CREATE TYPE is fine in-txn; only ALTER TYPE ADD VALUE must run
        --       outside a transaction (the 0011 precedent). No enum *additions* here,
        --       so 0016 is a normal transactional migration.

0017  suggestions index:
        suggestion_status: NEW enum ('open','accepted','rejected')   -- CREATE TYPE
        suggestions: id uuid PK, page_id uuid REF pages(id) ON DELETE CASCADE,
                     author_id uuid REF users(id), status suggestion_status NOT NULL DEFAULT 'open',
                     created_at timestamptz NOT NULL DEFAULT now(), resolved_at timestamptz NULL,
                     resolved_by uuid NULL
                     + index suggestions(page_id, status)

0018  page links index + email prefs:
        page_link_kind: NEW enum ('link','mention','embed')          -- CREATE TYPE
        page_links: source_page_id uuid REF pages(id) ON DELETE CASCADE,
                    target_page_id uuid REF pages(id) ON DELETE CASCADE,
                    kind page_link_kind NOT NULL,
                    PRIMARY KEY (source_page_id, target_page_id, kind)
                    + index page_links(target_page_id)              -- the backlinks query
        notification_email_prefs: user_id uuid, workspace_id uuid,
                    notification_type text, email_enabled boolean NOT NULL DEFAULT false,
                    digest_only boolean NOT NULL DEFAULT false,
                    PRIMARY KEY (user_id, workspace_id, notification_type)
```

- **Row templates** add no schema: `rowTemplates` jsonb in the existing `databases` config (decision 10), mirroring v0.6.0's relation/view config-in-jsonb pattern.
- **Suggestion marks** add no schema beyond the `0017` index: the proposed edits live in `pages.content` (Yjs/ProseMirror JSON) as marks (decision 6).
- **Page-link/mention/embed node attrs** live in `pages.content` (decision 8/9); only the derived `page_links` index is a table.
- **No enum `ALTER ... ADD VALUE`** is required by v0.7.0 (all new enums are `CREATE TYPE`, transactional). If a future revision *adds* a value to an existing enum, it must run outside a transaction (the `0011` precedent) — flagged here for the implementer.

## 5. Architecture by area

- **Per-page share settings:** extend the publish helper (`src/lib/pages/publish.ts` or equiv.) — `setShareSettings({pageId, password?, expiresAt?, allowDuplication})` (hashes password via Argon2id), `verifyShareAccess(pageId, password)` → issues the signed cookie (reuse the v0.5.0 HMAC signer), `requirePublicPageAccess(slug, req)` checks `published_at`, `expires_at`, and either no-password or a valid cookie (404 on any failure, never 403). `duplicatePublicPage(pageId, intoWorkspaceId)` deep-copies the subtree. Share panel (`src/components/pages/share-panel.tsx`) gains password/expiry/duplication controls.
- **Public site:** workspace settings helper gains `setPublicSite({workspaceId, slug, enabled})` (slug uniqueness validated). New route `src/app/s/[slug]/...` (+ `[slug]/[pageSlug]`) renders a nav tree (recursive-CTE descendants of published pages, the existing raw-SQL pattern) + the read-only `publicExtensions()` doc; CSP nonce + the public layout reused from `/p/`. Anon, cacheable per page subject to expiry.
- **Comments on db/files:** `src/lib/comments/*` generalized to `(targetType, targetId)`; `listComments`, `createComment`, threading, @mentions, and notification fan-out take the polymorphic anchor. Row comment UI in the row-detail panel; file comment UI in the file viewer. Webhook `comment.created` (v1.0 expands events) fires for all target types.
- **Suggestion mode:** new editor marks `src/components/editor/marks/suggestion-insert.ts` / `suggestion-delete.ts` + a `suggestion-block.ts` node; a `SuggestionContext`/toolbar toggle; `src/lib/suggestions/*` for `proposeSuggestion`/`acceptSuggestion`/`rejectSuggestion` (Yjs transaction + `suggestions` index update + notification). Register in `baseExtensions()`; **read-only** rendering in `publicExtensions()` (suggestions shown as annotations, never editable on public surfaces). Role gating via `requireRole`/`requirePageAccess`.
- **Email:** `src/lib/email/transport.ts` (nodemailer, env-driven, disabled if unset), `src/lib/email/templates/*` (per-event + digest, HTML+text), `src/lib/email/queue.ts` hooked into the existing notification creation path (the webhook in-process queue precedent), and a digest flush invoked by a cron/`CAIRN_DIGEST_CRON` (entrypoint-scheduled, single-instance). Outbound links/unfurls pass the SSRF guard (v0.5.0). Prefs API + `src/components/settings/notification-prefs.tsx` (per-type email/in-app/digest toggles), backed by `notification_email_prefs`.
- **Wiki / links:** `pageLink` inline node + `[[`/`@` suggestion plugin (`src/components/editor/page-link-suggestion.ts`, reusing the @mention infra from v0.3.0); `src/lib/pages/page-links.ts#reindexPageLinks(tx, pageId, content)` called from the page-save path (beside FTS trigger sync); "Linked references" panel `src/components/pages/backlinks-panel.tsx` (queries `page_links` + a read-time unlinked-mention FTS search). `pageMention`/`pageEmbed` nodes + node-views with read-only variants.
- **Row templates:** `src/lib/databases/row-templates.ts` (CRUD on the `rowTemplates` jsonb config) + `applyRowTemplate(template, row)`; "new row" picker in the database toolbar; integrates with the v0.5.0 template system surface.

## 6. Testing

- **Unit:** password hash/verify + signed-cookie issue/validate (incl. expiry, tampering); `expires_at` gate logic; `reindexPageLinks` walker (link/mention/embed extraction, delete-then-insert); unlinked-mention search; `applyRowTemplate`; suggestion mark accept/reject transforms; email template render + the SMTP-unset no-op path; SSRF guard on email links.
- **Integration (Testcontainers):** migrations `0014`–`0018`; share-settings CRUD + `requirePublicPageAccess` (no-password / correct / wrong / expired → 404); public-site nav tree + per-page gate within the site; polymorphic comments on `db_row` + `file` + back-filled `page`; `suggestions` index lifecycle (propose → accept/reject → status); `page_links` upsert on save + backlinks query; `notification_email_prefs` + per-event/digest enqueue; row-template apply creating a row.
- **Security (extends the v0.5.1 suite):** anon cannot reach a protected/expired page or an unpublished page in the site (404 not 403, no existence leak); the signed cookie can't be forged or replayed past expiry; CSP nonce present on `/s/` and `/p/` gates; SSRF guard blocks internal URLs in any email unfurl; suggestion/comment/duplication actions enforce workspace + role boundaries; duplication can't copy across workspaces without auth.
- **Build-verified:** share panel, public site, backlinks panel, suggestion toolbar, notification-prefs UI, row-template picker; **Yjs round-trip audit** (the v0.3.0 / v0.6.0 precedent) for `pageLink`, `pageMention`, `pageEmbed`, and the `suggestion-*` marks/node — a doc containing every new node+mark survives encode→decode.

## 7. Plan decomposition (~5 plans)

1. **Per-page share settings + public site** — migration `0014` (password/expiry/duplication) + `0015` (workspace public-site columns); share helper (Argon2id + signed cookie + expiry gate + duplicate action); share panel UI; `/s/<workspace-slug>` mini-site route + nav tree + read-only render; security tests (404-not-403, cookie forgery/expiry, CSP nonce).
2. **Comments on databases + files** — migration `0016` (polymorphic `comment_target` + `target_id`, back-fill); generalize the comment store/threading/@mention/notification path; row + file comment UI; `comment.created` webhook for all target types.
3. **Suggestion / track-changes mode** — migration `0017` (`suggestions` index + status enum); Yjs `suggestion-insert`/`-delete`/`-block` marks+node; propose/accept/reject lib (Yjs txn + index + notification); toolbar + read-only public rendering; role gating; Yjs round-trip audit.
4. **Page links + backlinks + mentions/embeds + row templates** — migration `0018` (`page_links` index + `notification_email_prefs`); `pageLink`/`pageMention`/`pageEmbed` nodes + `[[`/`@page` autocomplete; `reindexPageLinks` on save; backlinks panel + unlinked mentions; per-database `rowTemplates` jsonb config + picker; Yjs round-trip audit for the new nodes.
5. **Email notifications + prefs + release** — BYO-SMTP transport (nodemailer, disabled-if-unset) + per-event queue hook + digest cron + templates + SSRF guard on links; notification-preferences UI backed by `notification_email_prefs`; cross-feature smoke; README/CHANGELOG; version bump `0.7.0`; human-run multi-arch tag (per the v0.5.1 release workflow).

## 8. Risks

- **Suggestion mode is the hardest surface** (the roadmap flags it **High**) — Yjs-in-doc marks must accept/reject correctly under concurrent edits and survive the collab round-trip; the index must never drift from the marks. Scope strictly to insert/delete/block proposals + accept/reject; no comment-on-suggestion threading in v0.7.0. Exhaustive Yjs-audit + concurrency tests, like the v0.3.0 custom-node audit.
- **Password-link / public-site is a fresh anon attack surface** — wrong password, expired link, and unpublished page must all 404 (never 403, never a render); the signed cookie must be unforgeable + non-replayable past expiry; reuse the v0.5.0 HMAC signer and SSRF guard (no new secrets). Security tests extend the v0.5.1 suite.
- **Page-link reindex on every save** could be a write-time cost on link-heavy pages — delete-then-insert is bounded by the page's own link count (small); the backlinks read is indexed on `target_page_id`. Watch for save-path latency; unlinked mentions stay read-time (no index churn).
- **Email delivery is best-effort, not transactional** — a down SMTP server must never block a notification or a request (mirror the webhook queue: retry/backoff, log failures, never fatal); the SMTP-unset path must be a clean no-op surfaced in the UI, not an error.
- **New editor nodes/marks must stay Yjs-serializable** — `pageMention`/`pageEmbed`/`pageLink` + the `suggestion-*` marks each get the round-trip audit before shipping (the recurring v0.3.0/v0.6.0 constraint); page-embed is a snapshot preview, not live transclusion, to avoid the sub-document plumbing deferred since v0.6.0.
- **Polymorphic comment migration back-fill** — `0016` must back-fill `target_type='page'` + `target_id=page_id` for every existing comment in the same migration, or existing threads detach; covered by an integration test on a seeded pre-migration dataset.

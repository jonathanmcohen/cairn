# Cairn v1.0.0 — Road to 1.0 Design & Complete Feature Plan

**Status:** Draft (autonomously specced at the user's direction — "plan every feature for 1.0.0; make the decisions yourself." Every scope call below is mine, flagged as a decision; revisit before building.)
**Date:** 2026-05-22
**Target release:** v1.0.0 (the stable milestone), reached via themed minors v0.6.0 → v0.9.0.
**Builds on:** v0.5.1 (security) — the end of the 0.5.x line.

## 1. What "1.0.0" means

1.0.0 is a **stability + completeness commitment**, not just more features:
- **Feature-complete** against the self-hosted Notion-parity goal the project set out with.
- **Stable public API** (`/api/v1`) with a documented compatibility guarantee + OpenAPI spec.
- **Production-grade ops**: observability, admin console, scheduled backups, documented upgrade path.
- **Accessible + responsive** (WCAG 2.1 AA, mobile via PWA).
- **Secure by default** (continues v0.5.1) + 2FA + auditing.
- **Documented**: a real docs site, not just README.
- **SemVer promise begins**: after 1.0.0, breaking changes require a major bump.

This document enumerates **every feature** targeted for 1.0.0, the decisions on what's in vs deferred, and the release sequence to get there.

## 2. Shipped through v0.5.1 (the baseline — do not re-plan)

Auth/RBAC/OAuth, multi-workspace, pages + TipTap block editor, FTS + trigram search, trash, files (local + S3/MinIO) + markdown import/export, inline databases (table/kanban/gallery + formulas/relations/rollups/calendar/timeline), public read-only sharing, realtime collab (Yjs/Hocuspocus) + presence + comments + @mentions + notifications, public REST API + API keys + webhooks + templates + page version history + backup/restore CLI, and a security suite + CSP/rate-limiting/SECURITY.md. Stack: Next 16, React 19, TS 6, Postgres 16 + Drizzle, TipTap 3, Tailwind 4, Vitest 4.

## 3. Feature plan — every 1.0.0 feature, by themed release

Each minor is a coherent, shippable unit (same spec→plans→subagent-execution workflow). Decisions (**D#**) are mine.

### v0.6.0 — Content & database completeness
*Theme: close the editor + database gaps that separate Cairn from Notion parity.*
- **Reverse/bidirectional relations** (deferred from v0.4.0): a relation auto-maintains a mirror property on the target database. **D1: include — it's the most-requested deferred item.**
- **Database list view** (4th view type) + **table row grouping** (group-by like kanban, but in table) + **expanded filter operators** (contains/starts-with/before-after/is-empty per type) + **multi-property sort UI**.
- **Sub-items / row hierarchy** in databases (parent-row self-relation, expand/collapse).
- **New block types:** toggle/collapsible, columns (multi-column layout), callout (have), divider (have), table (simple non-database table), embed (iframe allowlist), bookmark (URL unfurl), math/LaTeX (KaTeX), synced block (one source, many mirrors via a shared block id). **D2: embeds are allowlist-only (YouTube/Vimeo/Figma/etc.) under the CSP — no arbitrary iframes.**
- **Table of contents** block (auto from headings) + **in-page outline** sidebar.
- **Code block** upgrades: language picker (have lowlight), copy button, line numbers.
- **Migration 0013+** as needed (reverse-relation metadata, block-id index for synced blocks).

### v0.7.0 — Sharing & collaboration depth
*Theme: richer sharing surfaces + deeper multiplayer.*
- **Block-level permissions** (stretch from v0.2.0): per-page share overrides + restrict subtree. **D3: page-level granularity for 1.0; true per-block ACLs deferred to post-1.0 (too complex, low demand).** → reframed as **per-page share settings**: password-protected public links, link expiry, "allow duplication" toggle, and a published **multi-page public site** (a workspace's published pages as a navigable mini-site at `/s/<workspace-slug>`).
- **Comments on databases + files** (deferred from v0.3.0): anchor comments to a row or a file.
- **Suggestion / track-changes mode** in the editor (propose edits, accept/reject) — built on Yjs.
- **Email notifications** (deferred from v0.3.0): digest + per-event, via SMTP (BYO SMTP env). **D4: SMTP only, opt-in; no third-party email SaaS dependency (self-hostable).**
- **Notification preferences** UI (per-type, email vs in-app).

### v0.8.0 — Mobile, accessibility & i18n
*Theme: usable everywhere, by everyone.*
- **Responsive/mobile-optimized UI** (the editor, sidebar drawer, database views adapt to small screens).
- **PWA**: installable, app manifest, service worker for offline READ of recently-viewed pages + queued edits sync on reconnect (Yjs helps). **D5: PWA covers "mobile" for 1.0; native iOS/Android apps deferred post-1.0 (separate track).**
- **Accessibility pass** to WCAG 2.1 AA: keyboard nav everywhere, focus management, ARIA, contrast, screen-reader testing; automated a11y checks (axe) in CI.
- **Keyboard-shortcut system** + a discoverable shortcut sheet (⌘/).
- **i18n scaffolding**: externalize strings, locale switch, ship en + one more locale as proof; RTL-ready CSS.

### v0.9.0 — Admin, observability, ops & import
*Theme: operate it at scale, get data in/out.*
- **Workspace admin console**: member/role management UI, invite management, workspace settings (name/icon/default-role), **transfer ownership**, **delete workspace** (the v0.2.0 sole-owner-leave follow-ups).
- **Audit log**: workspace-scoped record of sensitive actions (role changes, publishes, key/webhook CRUD, deletes) + a viewer.
- **2FA (TOTP)** + recovery codes; admin can require 2FA for a workspace. **D6: TOTP for 1.0; WebAuthn/passkeys deferred post-1.0.**
- **Observability**: structured JSON logging, a `/metrics` Prometheus endpoint (request/db/collab/webhook metrics), health already exists.
- **Quotas/limits**: per-workspace storage + rate limits, surfaced in admin.
- **Scheduled backups**: a cron-able backup mode + retention (extends the v0.5.0 CLI) + optional S3 backup target.
- **Import**: Notion export (ZIP/HTML/Markdown) importer + generic Markdown-folder import; **full workspace export** (everything, re-importable). **D7: Notion import is best-effort (pages + basic databases); fidelity gaps documented.**

### v1.0.0 — Stabilization, API stability, docs, AI (opt-in), polish
*Theme: lock it down and call it 1.0.*
- **API stability**: freeze `/api/v1`, publish an **OpenAPI 3.1 spec** + a generated typed client; document the compatibility guarantee.
- **Performance pass**: virtualized long pages + large database views, lazy-load heavy blocks, query/index audit, large-doc Yjs tuning, Lighthouse budget in CI.
- **Optional AI assist** (BYO LLM): summarize / continue-writing / ask-this-page, via a **bring-your-own OpenAI-compatible endpoint** configured by env, **opt-in, off by default**. **D8: include AI as fully optional + self-hostable (point at a local Ollama/vLLM or any OpenAI-compatible URL); never required, no data leaves the instance unless the operator configures an external endpoint.**
- **Docs site**: a real documentation site (the `/docs` content) — install, configure, API, admin, security.
- **Upgrade/migration guarantees**: documented, tested migration path; a "checkpoint" migration squash if needed.
- **Final security review** (a fresh pass over the v0.5.1 suite + an external-tool manual sweep) + dependency refresh.
- **Polish**: onboarding flow, empty states, error pages, theming/branding (custom logo/accent), command-palette completeness.
- **Version 1.0.0 + the SemVer commitment.**

## 4. Explicit non-goals for 1.0 (deferred to post-1.0 / 2.0)
- **Native mobile apps** (iOS/Android) — PWA covers 1.0; native is a separate track. (**D5**)
- **End-to-end encryption** — out of the 0.x/1.0 scope; revisit for a 2.0 "private" track.
- **Desktop Electron app** — the installable PWA covers desktop.
- **SSO/SAML/SCIM, enterprise directory sync** — OAuth covers 1.0; enterprise auth is a post-1.0 track.
- **WebAuthn/passkeys** — TOTP 2FA covers 1.0. (**D6**)
- **True per-block ACLs** — per-page sharing covers 1.0. (**D3**)
- **AI training / embeddings-based semantic search** — opt-in generative assist only for 1.0; semantic search is post-1.0. (**D8**)
- **Horizontal scaling** of the collab service (multi-replica + Redis) — single-instance documented ceiling stays for 1.0 (homelab scale).
- **Marketplace / plugin system** — post-1.0.

## 5. Release sequence & rationale
1. **v0.6.0 (content/db)** first — highest user-visible value, self-contained in the editor/db subsystems, low infra risk.
2. **v0.7.0 (sharing/collab)** — builds on the stable collab layer; adds the sharing surfaces users ask for.
3. **v0.8.0 (mobile/a11y/i18n)** — cross-cutting polish; do it once the feature surface is mostly complete so there's less churn.
4. **v0.9.0 (admin/ops/import)** — operational maturity + data portability before declaring stable.
5. **v1.0.0 (stabilize)** — freeze API, perf, docs, opt-in AI, final review, ship.

Each minor: spec → numbered plans → subagent-driven execution → eyeball → amd64 release (per the v0.5.1 workflow fix) → tag. Migrations continue from `0013`.

## 7. Key decisions recap (all mine, revisit before building)
- **D1** reverse relations: in (v0.6).
- **D2** embeds allowlist-only under CSP (v0.6).
- **D3** per-page sharing, not per-block ACLs, for 1.0 (v0.7).
- **D4** email via BYO-SMTP only, opt-in (v0.7).
- **D5** PWA for mobile; native apps deferred (v0.8).
- **D6** TOTP 2FA; passkeys deferred (v0.9).
- **D7** Notion import best-effort, documented gaps (v0.9).
- **D8** AI assist optional + BYO OpenAI-compatible endpoint, off by default, self-hostable (v1.0).

## 8. Risks
- **Scope:** 1.0 is large (≈28 plans). The themed-minor sequence keeps each release shippable + reviewable; don't merge themes.
- **Editor churn (v0.6):** new block types + synced blocks must stay Yjs-serializable (the v0.3.0 collab constraint) — verify each block round-trips through Yjs, like the v0.3.0 custom-node audit.
- **PWA offline + Yjs (v0.8):** offline editing then sync-on-reconnect is the hardest correctness surface; scope it to read-offline + queued-simple-edits, not full offline-first.
- **AI optionality (v1.0):** the AI path must be genuinely off-by-default and leak no content to any endpoint unless the operator configures one — assert in tests + SECURITY.md.
- **API freeze (v1.0):** anything shipped under `/api/v1` before 1.0 is a compatibility commitment after — audit the surface before freezing; breaking changes go to `/api/v2` post-1.0.
- **a11y/i18n retrofitting (v0.8):** cheaper if some conventions (semantic markup, externalized strings) start earlier — note for v0.6/0.7 implementers to not regress a11y.

## 9. Additional features (expanded scope — "what else for 1.0", 2026-05-22)

A second pass of feature ideas beyond §3, each with a decision (**target minor**, or **defer**). These fold into the existing themed minors — they do not add new releases.

### Wiki / knowledge graph (Notion-parity gap)
- **Page links + backlinks** — `[[`/`@page` autocomplete to link pages; a "Linked references" (backlinks) panel + "Unlinked mentions". **→ v0.7** (sharing/links theme). High value, moderate effort.
- **Inline page mentions / page embeds** — mention a page inline; embed a page's preview. **→ v0.7.**
- **Graph view** (page-link graph visualization). **→ defer post-1.0** (heavy, low core value).

### Database depth (beyond v0.6)
- **Full-page databases** — a database as a top-level page (not only an inline block); the real parity gap after inline DBs. **→ v0.6.x** (extends v0.6; or early v0.7).
- **Calculation footer** — per-column aggregations (sum/avg/count/min/max/%-empty) at the bottom of table/list views. **→ v0.6.x.**
- **Conditional formatting** — color rows/cells by rule. **→ v1.0 polish** (or v0.6.x if cheap).
- **Per-database row templates** — "new row from template" presets. **→ v0.7** (extends the v0.5.0 templates system).
- **Column width / freeze / hide per view** — table ergonomics. **→ v0.8** (UI polish).

### Search & navigation
- **Search filters + scope + saved searches** — filter results by author/date/type, scope to a database, save queries; search-within-page. **→ v0.9.**
- **Favorites / pinned pages + recents** — per-user sidebar customization. **→ v0.8.**
- **Command-palette actions** — not just navigation: run actions (new page, toggle theme, switch workspace) from ⌘K. **→ v0.8** (with the keyboard system).
- **Block conversion + multi-select** — turn a block into another type; drag/shift-select multiple blocks. **→ v0.8.**

### Tasks, reminders, activity
- **Due-date reminders** — a database date property fires a notification ahead of time. **→ v0.9** (rides the notifications + admin theme).
- **Per-page activity feed** — who changed what, when (folds into the v0.9 audit log, surfaced per-page). **→ v0.9.**
- **Recurring tasks / scheduled row creation** — **→ defer post-1.0.**

### Export, import, portability (beyond v0.9 Notion import)
- **Page → PDF export** (print-quality). **→ v0.9.**
- **Per-page / per-database export** (Markdown/CSV/JSON) from the UI (the lib exists; surface it). **→ v0.9.**
- **Bulk operations** — multi-select pages/rows → move/delete/duplicate/tag; bulk trash-restore. **→ v0.9.**

### API & integrations (before the v1.0 freeze)
- **Expand `/api/v1`** — comments, search, file upload/download, notifications endpoints; consistent cursor pagination + rate-limit headers everywhere. **→ v1.0** (audit + expand the surface *before* freezing it).
- **More webhook events** — `comment.created`, `member.added/removed`, `page.published/unpublished`. **→ v1.0** (API stability).

### Collaboration & polish
- **Comment reactions / emoji** — **→ defer post-1.0** (minor).
- **Onboarding tour + seeded sample content** on first workspace; configurable **workspace home/dashboard**. **→ v1.0 polish** (home) / **v0.9** (admin default-home setting).
- **Guest access** — per-page external collaborators without full membership. **→ defer post-1.0** (sharing-model complexity; per-page password sharing in v0.7 covers the common case).

### Decision summary (new items only)
- **Into existing minors:** page links/backlinks + page mentions (v0.7), per-db row templates (v0.7), full-page databases + calc footer (v0.6.x), column ergonomics + favorites/recents + command-palette actions + block conversion/multi-select (v0.8), search filters/saved + due-date reminders + per-page activity + PDF/UI export + bulk ops + workspace-home setting (v0.9), `/api/v1` expansion + more webhook events + onboarding/home + conditional formatting (v1.0).
- **Deferred post-1.0:** graph view, recurring tasks, comment reactions, guest access (all also in §4's spirit — keep 1.0 focused).

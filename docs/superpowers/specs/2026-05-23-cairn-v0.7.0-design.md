# Cairn v0.7.0 — Extensibility, permissions, automation & operations depth

> Status: **design approved**. Single large release after v0.6.0; explicitly NOT split into 0.7+0.8. Follows v0.6.0's area-by-area execution pattern (spec → numbered plans → subagent-driven). The headline feature is the MCP server; everything else either supports it (PATs, dev settings, ACLs, token-usage audit), extends shipped v0.5 / v0.6 surfaces (scheduled S3 backup, webhook dashboard, audit, `/healthz`), or adds new top-level subsystems (vector search, two-way connectors, bulk import/export, automation engine).

---

## 1. Goals & non-goals

**Goals.** Open Cairn to agents (MCP) with the per-user authz primitives those agents need (PATs + page ACLs). Add depth to admin/observability (`/healthz`, webhook delivery dashboard, token-usage log). Add new subsystems for semantic search, automation, two-way DB connectors. Polish backup/import-export to close v0.5 / v0.6 deltas.

**Non-goals (deferred to v1.0 stabilization).**
- Frozen public API + OpenAPI spec.
- Onboarding tour + sample content + theming/branding.
- BYO-LLM AI assist features (summarize, continue-writing, ask-this-page).
- Performance pass (Lighthouse budget, virtualized large pages).
- Native iOS/Android apps; cross-page synced blocks; per-block ACLs; graph view of page links; recurring tasks; SSO/SAML/SCIM; passkeys; distributed scheduling; arbitrary iframe embeds; third-party email SaaS.

---

## 2. Decisions (the eight design points settled in brainstorm)

Each is a binding constraint for the plans below.

### 2.1 MCP transport — both Streamable HTTP + SSE fallback

Ship Streamable HTTP as the primary transport at `POST /api/mcp` (single endpoint, returns JSON or SSE per request shape — current MCP spec direction, supported by Claude Desktop / Cursor / Cline / Continue). Ship a thin SSE-fallback shim at `GET /api/mcp/sse` + `POST /api/mcp/messages` for first-generation clients. Both gated by the same bearer-token auth. The ~2× surface to maintain is accepted for client compatibility.

### 2.2 MCP write-tool safety — per-token tool allowlist + presets

Per-PAT `mcp_tools` allowlist (array of stable tool IDs). Tool dispatch requires (a) the PAT carries the tool's declared scope (e.g. `mcp:write`) AND (b) the tool ID is in the PAT's allowlist AND (c) the acting user's workspace role + page ACL allows the underlying mutation. Empty allowlist = no MCP access regardless of scope. Dev-settings UI surfaces named presets ("read-only", "full CRUD", "write-minus-destructive") so users don't pick 30 boxes manually. No per-call agent-confirmation prompts (UX-fragile across clients).

### 2.3 Embedding-model hosting — bundled local + BYO env override

Ship `all-MiniLM-L6-v2` (~80MB ONNX, MIT license) bundled in the Cairn container as the default embedding model via `onnxruntime-node`. Honor `CAIRN_EMBEDDING_URL` + `CAIRN_EMBEDDING_MODEL` + `CAIRN_EMBEDDING_API_KEY` env to override with an OpenAI-compatible endpoint (Ollama, OpenAI, Together, vLLM, anything compatible). Two code paths (`local` / `remote`), one shared `embed(text): Promise<Float32Array>` interface; secret-leak suite covers the API-key env. Image size grows by ~80-100MB.

### 2.4 Page-permission precedence — ACL overrides role per subtree

Effective permission for `(user, page)` = explicit ACL on the page if one exists; else inherit from the nearest ancestor with an explicit ACL; else fall through to the user's workspace role. **Owner role bypasses the ACL chain entirely** (recovery + ownership guarantee). Public-share (`/p/<id>`) is a separate axis — applies only to anonymous visitors; logged-in members always route through the role+ACL resolver. ACLs are full overrides for that subtree (a workspace editor with "view-only" ACL on Page X can only view X and its descendants).

### 2.5 Tokens — coexist with v0.5 api_keys (separate table)

Keep `api_keys` exactly as shipped in v0.5 (workspace-scoped, single role, `cairn_sk_*`). Add `personal_access_tokens` table (per-user, multi-scope, per-token MCP-tool allowlist, `cairn_pat_*`). Shared auth-middleware dispatches on token-kind. Audit-event names distinct (`api_key.*` vs `pat.*`) so the token-usage log can attribute correctly. No migration of existing api_keys.

### 2.6 Automation/rules engine — UI form builder

Settings page form builder with dropdowns: trigger event (from a closed enum of v0.5 webhook events + the new v0.7 events) → condition (field + operator + value, reusing the v0.6 search-filter / db-filter operator vocab) → action (notify-user, send-webhook, set-property, create-page-from-template). Rule persists as a normalized DB row (jsonb config blob keyed by trigger type). No JS sandboxing, no JSON editor (UI is the contract for v0.7; JSON export deferred).

### 2.7 Two-way DB connectors — hybrid push+poll + LWW per-cell + conflict-review inbox

Adapter interface (`fetchAll(connectorState) → Row[]` / `applyChanges(diff) → ack` / optional `subscribe(callback) → unsubscribeFn`). Use push when the external service offers it (Google Sheets via Drive webhooks; Airtable via webhooks); poll on a configurable interval for sources that don't (CSV file-path watch). Conflict resolution = last-write-wins per cell using `last_synced_at` stamps; rows with both-side-changed-since-last-sync land in a per-connector "conflict review" inbox for explicit user resolution. Scope-cut ordering: ship the Sheets adapter first, Airtable second, CSV third — one connector per plan.

### 2.8 Open `/healthz` + token-gated `/metrics` (P20 stays as-is)

Ship a new always-open `GET /healthz` returning minimal JSON `{ status, version, db, uptime_seconds }` for K8s/load-balancer liveness probes. **Keep the v0.6 P20 `/metrics` token gate verbatim** — Prometheus operators configure bearer auth in their `scrape_config`. No new metric series open up.

## 3. Feature areas

Eight plan groups (G1–G8) — ~25-30 numbered plans total. Each group is independently shippable; G2-G7 all depend on G1's authz primitives.

### G1. Authz primitives (foundation)

**Plans (approx 5):** PAT table + middleware · Scopes + per-token tool allowlist · Page ACLs (table + inheritance resolver + role precedence) · Dev-settings UI (mint/revoke + token-usage timeline + MCP connection info) · Token-usage audit log.

**Schema (one migration):**

```sql
CREATE TABLE personal_access_tokens (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  workspace_id  uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  name          text NOT NULL,
  token_hash    text NOT NULL UNIQUE,
  token_prefix  text NOT NULL,
  scopes        text[] NOT NULL,
  mcp_tools     text[] NOT NULL DEFAULT '{}',
  expires_at    timestamptz,
  last_used_at  timestamptz,
  created_at    timestamptz NOT NULL DEFAULT now(),
  revoked_at    timestamptz
);
CREATE INDEX personal_access_tokens_user_workspace_idx
  ON personal_access_tokens (user_id, workspace_id) WHERE revoked_at IS NULL;

CREATE TABLE page_acls (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  page_id     uuid NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
  user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  permission  text NOT NULL CHECK (permission IN ('view','comment','edit')),
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now(),
  UNIQUE (page_id, user_id)
);

CREATE TABLE token_usage_log (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id  uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  token_kind    text NOT NULL CHECK (token_kind IN ('api_key','pat')),
  token_id      uuid NOT NULL,
  user_id       uuid REFERENCES users(id) ON DELETE SET NULL,
  route         text NOT NULL,
  status        integer NOT NULL,
  mcp_tool      text,
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX token_usage_log_token_id_created_at_idx ON token_usage_log (token_id, created_at DESC);
CREATE INDEX token_usage_log_workspace_id_created_at_idx ON token_usage_log (workspace_id, created_at DESC);
```

**Scopes vocab (closed set):**

```
pages:read         databases:read         comments:read         files:read
pages:write        databases:write        comments:write        files:write
pages:destructive  databases:destructive  comments:destructive  files:destructive
mcp:read           mcp:write              mcp:destructive
admin
```

`admin` supersedes the per-resource scopes (workspace-admin-equivalent). Scopes grant *permission to attempt*; the acting user's role + page ACL gates *success* (so a token can't escalate beyond what the minting user could do).

**Auth middleware (`src/lib/auth/token.ts`):**

`resolveToken(authHeader): Promise<TokenContext | null>` — parses `Bearer <secret>`, dispatches on prefix (`cairn_sk_` → api_keys lookup; `cairn_pat_` → personal_access_tokens lookup), returns `{ kind, tokenId, userId?, workspaceId, scopes, mcpTools }` or null. Wired into every `/api/v1/*` and `/api/mcp/*` route as the auth boundary. Updates `last_used_at` fire-and-forget.

`requireScope(ctx, scope)` throws `HttpError(403)` if ctx.scopes doesn't include the requested scope.

**Page ACL resolver (`src/lib/pages/acl.ts`):**

```ts
type EffectivePermission = 'view' | 'comment' | 'edit' | 'admin' | 'owner';

async function resolveEffectivePermission(
  db: Db,
  args: { userId: string; pageId: string },
): Promise<EffectivePermission | null>;
```

Implementation: recursive CTE walking `pages.parent_id` upward from `pageId`, LEFT JOIN `page_acls (user_id = $userId)`, return the first hit. If no ACL hits anywhere up the tree, fall back to the user's workspace role (owner / admin / editor / viewer → mapped to edit / edit / edit / view). Owner bypass: if workspace role is `owner`, return `'owner'` unconditionally.

Wrapped in React `cache()` per request. `requirePageAcl(pageId, minPermission)` mirrors v0.6 `requirePageAccess` — returns `{page, ctx, effectivePermission}` or throws.

**Dev-settings UI (`/settings/developer`, server component):**

1. *Tokens* — table of current PATs (name, prefix, scopes, allowlist count, last_used_at, expires_at). "Mint new" opens a dialog: name, scopes multi-select with named presets (Read-only, Full CRUD, Write-minus-destructive, MCP read-only, MCP full), MCP-tool allowlist (shown only if any `mcp:*` selected; multi-select of tool IDs with descriptions), expiry select. On submit, server returns plaintext token ONCE in a modal with copy + download buttons.
2. *MCP connection info* — server URL (`${PUBLIC_URL}/api/mcp`), supported transports, copy-ready Claude Desktop / Cursor config snippets pre-filled with the selected token.
3. *Token usage* — paginated timeline per token (route template, status, MCP tool, timestamp). Keyset-cursor pagination over `token_usage_log` mirroring v0.6 P18 audit viewer.

**Audit event vocab additions (v0.6 `AuditAction` literal union):**

```
'pat.created' | 'pat.revoked' | 'pat.expired'
'page_acl.created' | 'page_acl.changed' | 'page_acl.removed'
```

**`mcp.tool_called` events** log to `token_usage_log` only (not `audit_log`) — too high-cardinality for the audit feed.

**Secret-hygiene additions to v0.5.1 / v0.6 suite:**

`FORBIDDEN_SECRET_PREFIXES` adds `'cairn_pat_'`. `FORBIDDEN_KEYS` adds `'CAIRN_EMBEDDING_API_KEY'`. Token-leak tests assert PAT secret never appears in API responses (PATs list, `personal_access_tokens` row select), audit metadata, token-usage log, or workspace-archive export.

### G2. MCP server

**Plans (approx 3):** Streamable HTTP transport + tool registry · SSE fallback shim · Tool-level scope+allowlist+ACL enforcement + tests.

**Tool registry (`src/lib/mcp/tools.ts`):**

Hardcoded array of tool descriptors:

```ts
type ToolDescriptor = {
  id: string;             // e.g. 'pages.read'
  description: string;    // shown to the LLM
  scope: Scope;           // required scope (e.g. 'pages:read')
  destructive: boolean;   // true if action is non-recoverable
  inputSchema: ZodSchema; // tool args
  handler: (ctx: TokenContext, args: unknown) => Promise<unknown>;
};
```

Initial tool set (~20 tools, all reading the existing v0.5 / v0.6 library helpers):

```
pages.list, pages.read, pages.create, pages.update, pages.delete, pages.move
databases.list, databases.read, databases.create_row, databases.update_row, databases.delete_row
rows.list, rows.update_cells
search.fts, search.semantic
comments.list, comments.create
files.list, files.read_signed_url
workspaces.info
```

**Transport endpoints (`src/app/api/mcp/route.ts`, `src/app/api/mcp/sse/route.ts`, `src/app/api/mcp/messages/route.ts`):**

- `POST /api/mcp` — Streamable HTTP. Accepts JSON-RPC 2.0 requests; returns JSON or SSE based on the request type per spec.
- `GET /api/mcp/sse` — SSE fallback. Maintains a long-lived connection for the client to read server→client events.
- `POST /api/mcp/messages?sessionId=...` — SSE fallback. Client→server tool calls; routed to the SSE stream identified by `sessionId`.

Both transports share a single dispatcher (`src/lib/mcp/dispatcher.ts`) — parses JSON-RPC envelope, validates against tool registry, calls handler. The dispatcher is the integration point for the three enforcement layers (scope check → allowlist check → ACL/role check via the underlying tool handler).

**Tool-call enforcement order:**

1. `resolveToken(authHeader)` — token kind = `pat`, scopes loaded.
2. `tool = registry[toolId]` — 404-equivalent if unknown.
3. `tool.scope` must be in `ctx.scopes` — else MCP-spec scope error.
4. `tool.id` must be in `ctx.mcpTools` — else MCP-spec tool-not-allowed error.
5. Tool handler executes the underlying library call (`@/lib/pages/update`, etc.) which itself calls `requirePageAcl(pageId, 'edit')` — final permission check happens there.

Every tool invocation logs to `token_usage_log` (success OR error). MCP-side rate-limit reuses the v0.5.1 in-process token-bucket pattern keyed by `(token_id, tool_id)`.

**Test surface:** dispatcher unit tests (envelope shape), per-tool integration tests (against Testcontainers Postgres), MCP-protocol smoke (Streamable HTTP roundtrip + SSE fallback roundtrip), secret-leak extension (PAT token never in tool-response payloads).

### G3. Observability + ops delta

**Plans (approx 2):** `/healthz` + token-usage audit event types · Webhook delivery dashboard UI + HMAC-signing surface UX.

**`/healthz` (`src/app/healthz/route.ts`):**

```ts
GET /healthz → 200 {
  status: 'ok',
  version: <package.json version>,
  db: 'ok' | 'unreachable',
  uptime_seconds: number,
}
```

Always open (no auth). Touches the DB with a `SELECT 1` to validate connectivity. Returns 503 on DB failure. Suitable for K8s liveness probe / load-balancer health check.

**`/metrics` — unchanged from v0.6 P20.** Still token-gated; new metric series added for MCP traffic (`mcp_tool_called_total`, `mcp_tool_duration_seconds`, with `tool` label from the closed registry — bounded cardinality).

**Webhook delivery dashboard (`/settings/admin/webhooks/<id>/deliveries`):**

Per-webhook delivery timeline (existing `webhook_deliveries` table, no schema change). Columns: timestamp, event, status, attempts, last_status, error excerpt. Actions: manual replay (re-enqueues a delivery), copy-payload (with HMAC signature header shown), copy-as-curl. Admin-gated (`requireRole('admin')`). Surfaces the v0.5 P2 HMAC signing — display the secret prefix only (`cairn_whsec_xxxx`), with "rotate" CTA that mints a new secret + invalidates the old.

### G4. Vector / semantic search

**Plans (approx 3):** pgvector + embedding service (bundled + BYO override) · Embedding update pipeline (on-write fire-and-forget + reindex CLI) · Search route union (FTS + semantic).

**Schema (one migration with `CREATE EXTENSION IF NOT EXISTS vector`):**

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE page_embeddings (
  page_id     uuid PRIMARY KEY REFERENCES pages(id) ON DELETE CASCADE,
  workspace_id uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  embedding   vector(384) NOT NULL,                  -- 384 = all-MiniLM-L6-v2 dim
  content_hash text NOT NULL,                         -- sha256 of content_text; skip re-embed if unchanged
  updated_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX page_embeddings_embedding_idx
  ON page_embeddings USING hnsw (embedding vector_cosine_ops);
CREATE INDEX page_embeddings_workspace_idx ON page_embeddings (workspace_id);
```

**Embedding service (`src/lib/search/embed.ts`):**

```ts
interface EmbeddingProvider {
  embed(text: string): Promise<Float32Array>;
  dim: number;       // 384 for all-MiniLM-L6-v2
  model: string;     // for telemetry; e.g. 'all-MiniLM-L6-v2'
}
```

Two implementations:
- `LocalEmbeddingProvider` — bundled `all-MiniLM-L6-v2.onnx` via `onnxruntime-node`; tokenization via `@xenova/transformers` (bundled tokenizer files).
- `RemoteEmbeddingProvider` — POSTs to `CAIRN_EMBEDDING_URL` (OpenAI-compatible `/embeddings` endpoint) with `CAIRN_EMBEDDING_API_KEY`.

Factory `getEmbeddingProvider()` returns Remote if `CAIRN_EMBEDDING_URL` is set, else Local. Cached as singleton.

**Embedding update pipeline:**

- On-write fire-and-forget: page-save helpers (`src/lib/pages/update.ts`) `setImmediate(() => embedPage(pageId))` after the DB commit (same pattern as v0.6 P11 email send).
- Reindex CLI: `pnpm cli reindex-embeddings [--workspace <id>]` walks pages where `content_hash` differs (or row missing), batches embedding calls, upserts. Single-instance ceiling per v0.6 P21 documented.
- Backfill on schema apply: a one-time job enqueued post-migration that walks every page and embeds — single-instance, opt-in via `CAIRN_BACKFILL_EMBEDDINGS=1` env on first boot post-upgrade.

**Search route union (`src/app/api/search/route.ts` modified):**

Existing FTS+trigram path stays. Add optional `?mode=semantic` query param that runs `searchSemantic(workspaceId, query, k)` — embed the query, run a cosine-distance kNN against `page_embeddings`. Default mode stays `fts` (regression-safe). Combined mode (`?mode=hybrid`) returns FTS rank + semantic rank, merged via RRF (reciprocal rank fusion) at the result-row level.

MCP tool `search.semantic` mounts the same code path.

### G5. Bulk import/export + scheduled S3 backup/restore

**Plans (approx 2):** Bulk import/export UI (over v0.6 P21 lib) · Scheduled S3 backup + restore CLI delta.

**Bulk import/export UI:**

v0.6 P21 already shipped `runImport` + `runWorkspaceExport` libs + the `cli import` / `cli export` subcommands. v0.7 adds the *workspace settings UI* surface:
- `/settings/import` — file picker, source select (notion / markdown-folder / workspace-archive), target workspace, progress + report. Drives the same lib through a new `POST /api/imports` route that streams the import (Server-Sent Events) so progress shows live. Admin-gated.
- `/settings/export` — workspace export with download-from-S3 link (delta on top of P21's `--out` filesystem-only path).

**Scheduled S3 backup + restore CLI:**

- `pnpm cli backup --schedule "<cron-spec>"` — writes a `cron_schedules` row (new tiny table: `id`, `command`, `cron_spec`, `next_run_at`, `last_run_at`, `enabled`). A new entrypoint singleton (`src/server/scheduler.ts`) reads it, sleeps to `next_run_at`, exec's the CLI. Single-instance ceiling per v0.6 P21 (documented).
- `pnpm cli restore --from-s3 <bundle-path>` — pulls bundle from configured `FileStorage` (S3/MinIO) to `--out` dir, then runs the existing `restore --in` path. Closes the v0.5 / v0.6 P21 gap where backups go to S3 but restore expected a local file.

**Schema (one migration):**


### G6. Automation / rules engine

**Plans (approx 3):** Rule storage + event subscriber · Action runners (notify / set-property / create-page / send-webhook) · UI form builder + tests.

**Schema (one migration):**

```sql
CREATE TABLE automation_rules (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id  uuid NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  name          text NOT NULL,
  trigger_event text NOT NULL,                                       -- e.g. 'row.created', 'page.updated'
  condition     jsonb NOT NULL DEFAULT '{}',                          -- {property, operator, value}
  action_type   text NOT NULL,                                       -- 'notify' | 'send_webhook' | 'set_property' | 'create_page'
  action_config jsonb NOT NULL,                                      -- action-type-specific
  enabled       boolean NOT NULL DEFAULT true,
  created_by    uuid NOT NULL REFERENCES users(id) ON DELETE SET NULL,
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX automation_rules_workspace_trigger_idx
  ON automation_rules (workspace_id, trigger_event) WHERE enabled = true;

CREATE TABLE automation_runs (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  rule_id      uuid NOT NULL REFERENCES automation_rules(id) ON DELETE CASCADE,
  trigger_payload jsonb NOT NULL,
  status       text NOT NULL,    -- 'success' | 'failed' | 'condition_unmet'
  error        text,
  created_at   timestamptz NOT NULL DEFAULT now()
);
```

**Event subscriber (`src/lib/automation/dispatcher.ts`):**

Hooks into the same internal event bus the v0.5 webhook dispatcher reads from (`src/lib/webhooks/dispatch.ts#emit`). When an event fires, the subscriber:
1. Loads enabled rules for the workspace matching the trigger event (cached per workspace).
2. Evaluates each rule's condition against the event payload (operator vocab from v0.6 filter compiler: text-contains, equals, gt/lt/between, is-empty, etc.).
3. Invokes the action runner for matching rules.
4. Records an `automation_runs` row.

Fire-and-forget from the calling transaction (`setImmediate` post-commit, never blocks the write). Errors swallowed but logged to `pino` (v0.6 P20).

**Action runners (`src/lib/automation/actions/*.ts`):**

- `notify`: enqueues a notification via v0.3.0 path (`createNotification`).
- `send_webhook`: enqueues a custom webhook delivery via v0.5 P2 dispatcher.
- `set_property`: updates a db_cell (`{databaseId, propertyId, value}` from action_config; rowId from trigger payload).
- `create_page`: instantiates a template via v0.5 P3 template instantiator (`{templateId, parentId, titleTemplate}` from action_config; titleTemplate supports `{{trigger.row.title}}` etc.).

**UI (`/settings/automation`):**

Rule-list table + "New rule" form: trigger event (dropdown from closed enum), condition (Property+Operator+Value rows, reusing the v0.6 filter UI), action (type select → action-specific param form). Per-rule edit + enable/disable + delete + last-run status.

### G7. Two-way DB connectors

**Plans (approx 4):** Adapter interface + sync engine + conflict-review inbox · Sheets adapter · Airtable adapter · CSV adapter + connector-UI.

**Adapter interface (`src/lib/connectors/adapter.ts`):**

```ts
interface ConnectorAdapter {
  kind: 'google_sheets' | 'airtable' | 'csv';
  authConfigSchema: ZodSchema;          // per-adapter OAuth/API-key/file-path config
  fetchAll(state: ConnectorState): Promise<ExternalRow[]>;
  applyChanges(state: ConnectorState, diff: Diff): Promise<{ ack: AckedChange[] }>;

```

**Schema (one migration):**

```sql
  UNIQUE (connector_id, cairn_row_id)

  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),

  row_id        uuid REFERENCES db_rows(id) ON DELETE SET NULL,
  property_id   uuid REFERENCES db_properties(id) ON DELETE SET NULL,
  cairn_value   jsonb,
  external_value jsonb,
  cairn_ts      timestamptz NOT NULL,
  external_ts   timestamptz NOT NULL,
  resolved_at   timestamptz,
  resolution    text,                                       -- 'cairn' | 'external' | 'manual'
  created_at    timestamptz NOT NULL DEFAULT now()
);
```

**Sync engine (`src/lib/connectors/sync.ts`):**

Single sync orchestrator. Per connector:
1. Adapter `fetchAll` → external rows.
2. Diff against Cairn rows via `connector_row_map`.
3. For each row: compare `cell_hashes` (last synced) vs current Cairn + current external. Three cases:
   - Only Cairn changed → push to external.
   - Only external changed → apply to Cairn.
   - Both changed since `last_synced_at` → write `connector_conflicts` row, do nothing.
4. Adapter `applyChanges(diff)` for push-to-external batch.
5. Update `connector_row_map.cell_hashes` + `last_synced_at`.

Triggered via:
- Push (adapter `subscribe` callback) — Sheets/Airtable webhooks fire `triggerSync(connectorId)`.
- Poll (cron entry per connector) — `pnpm cli connector:sync [--connector <id>]` runs every N min for adapters without push (CSV).

**Conflict review inbox (`/settings/connectors/<id>/conflicts`):**

Table of unresolved conflict rows; per-row "Use Cairn" / "Use External" / "Edit" buttons. Resolution writes the chosen value to the appropriate side (or both, if Edit) and stamps `resolved_at`.

## 6. Risks

1. **MCP spec churn** — Streamable HTTP is the current direction but the spec is young. Mitigation: implement against the published 2025 spec snapshot vendored into the repo, ship SSE fallback for older clients (per 2.1).
2. **Per-token tool allowlist UX overwhelms users** — 20+ tools to pick from. Mitigation: named presets ("read-only", "full CRUD", "write-minus-destructive", "MCP read-only", "MCP full") covering 90% of intended uses; advanced multi-select for power users.
3. **ACL inheritance perf** — recursive CTE per page-access check. Mitigation: cached per-request via React `cache()`; the CTE is a tight walk up `parent_id` (depth ≤ ~10 in typical Notion-shaped trees).
4. **Bundled embedding model adds ~80MB to image + ONNX-runtime native bindings** — Apple Silicon / cross-arch builds need both `linux/amd64` and `linux/arm64` ONNX binaries. Mitigation: confirm `onnxruntime-node` ships prebuilds for both archs before settling on it; alternative is `@xenova/transformers` which wraps ORT and handles arch selection.
5. **Two-way connector sync correctness** — LWW per-cell can lose user intent in pathological cases. Mitigation: conflict-review inbox catches "both sides edited since last sync"; document the LWW semantics in the connector setup UI.
6. **Connector auth-config encrypted-at-rest needs decrypt-on-sync path** — same shape as v0.6 TOTP secret-box. Mitigation: reuse `src/lib/crypto/secret-box.ts` verbatim; key derived from `AUTH_SECRET` (no new secret).
7. **Single-instance ceiling now covers 3+ schedulers** — operator confusion. Mitigation: consolidate documentation in `docs/operations.md` "Schedulers" section; surface a one-line `/healthz` field if more than one scheduler is enabled (`schedulers_enabled: ['backups', 'connectors', ...]`).

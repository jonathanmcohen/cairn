# Cairn v0.5.1 — Security Testing & Secure-by-Default Design

**Status:** Draft (autonomously specced at the user's direction; design decisions made on their behalf and flagged below; not interactively brainstormed). Subject to revision before implementation.
**Date:** 2026-05-21
**Target release:** v0.5.1 (patch)
**Builds on:** v0.5.0 (platform & ops — adds the largest attack surface: public API, API keys, webhooks)

## 1. Purpose

Prove Cairn is **secure by default** and keep it that way. This release adds (a) an automated security-regression test suite that exercises the app's authz/isolation/leakage boundaries as adversarial negative tests, (b) secure-by-default hardening that's currently missing (security response headers, auth-endpoint rate limiting, cookie/secret hygiene checks), and (c) supply-chain + secret scanning in CI. It is a patch release: no new product features, no schema change. The deliverable is confidence — encoded as tests and gates that fail loudly on regression — plus a written `SECURITY.md`.

Because v0.5.0 introduces the public REST API, API keys, and outbound webhooks, **v0.5.1 must follow v0.5.0** so the security suite covers that surface too.

## 2. Security surface inventory (what we are verifying)

The app's security mechanisms accumulated across v0.1.0–v0.5.0:

| Area | Mechanism | Test focus |
|---|---|---|
| AuthN | Auth.js v5 credentials (bcrypt) + OAuth invite-gate; `jwt` sessions | bad creds rejected; OAuth gate denies non-invited; password never returned/logged |
| AuthZ / RBAC | `requireRole`/`hasMinRole`/`requirePageAccess`, `owner>admin>editor>viewer` | each role's ceiling enforced; viewer cannot mutate; editor cannot admin |
| Multi-tenant isolation | everything workspace-scoped; cross-workspace → **404 not 403** | a user in WS-A cannot read/mutate WS-B pages/dbs/rows/comments/files/notifications/api-keys/webhooks; existence never leaked |
| File access | HMAC-signed URLs (`?sig=&exp=`), `/api/files` allowlisted | missing/forged/expired sig → 401; no path traversal; signature is the only gate |
| Public sharing | `/p/<slug>` gated on `published=true AND deleted_at IS NULL`; public DB endpoint via page publication; `noindex` | unpublished/deleted/unknown → 404; no draft leakage; embedded DB only readable while host page published |
| Collab | short-lived collab JWT (5 min), `authorizeCollab` (token.pageId === doc), viewer read-only no awareness | forged/expired/wrong-page token rejected; viewer cannot write |
| API (v0.5.0) | workspace-scoped API keys (sha256-hashed, prefix shown once), bearer auth, in-process rate limit | revoked/expired key rejected; key can't exceed its role; rate limit trips; no plaintext key stored/logged |
| Webhooks (v0.5.0) | per-hook HMAC signature, **SSRF guard** (block loopback/link-local/private) | signature present + correct; SSRF guard blocks internal targets |
| Input validation | Zod on every route/body; Drizzle parameterized SQL; raw CTEs parameterized | malformed input rejected; SQL-injection attempts inert; no string-built SQL |
| Content rendering | TipTap/ProseMirror JSON; public read-only render | stored content can't inject script on the public path (XSS) |
| Secrets | `AUTH_SECRET`, DB creds, S3 creds, per-hook secrets via env | not in logs, not in API responses, not in client bundle; backup bundle flagged sensitive |

## 3. Secure-by-default gaps to CLOSE (net-new hardening, not just tests)

These are likely-missing defaults found while inventorying; v0.5.1 adds them:

1. **Security response headers** — the app does not set a Content-Security-Policy or the standard hardening headers. Add (via `next.config` `headers()` and/or the `proxy.ts` layer): `Content-Security-Policy` (scoped to self + the collab WS origin + signed file URLs), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` / `frame-ancestors 'none'` (the public `/p/` path may relax to allow embedding if desired — default DENY), `Referrer-Policy: strict-origin-when-cross-origin`, `Strict-Transport-Security` (prod only), `Permissions-Policy` (deny camera/mic/geo). The public render path keeps `noindex`.
2. **Auth-endpoint rate limiting** — login + signup + the collab-token mint currently have no brute-force protection. Add an in-process per-IP+identifier token bucket (reuse the rate-limit primitive from the v0.5.0 API plan). Documented single-instance ceiling.
3. **Cookie hardening verification** — assert (in tests) every auth/session/active-workspace cookie is `httpOnly`, `sameSite=lax` (or stricter), `secure` in production, and scoped `path=/`.
4. **Secret hygiene** — a test asserting API responses + server logs never include `passwordHash`, `token_hash`, `AUTH_SECRET`, webhook secrets, or raw API keys; and a build-time check that no secret env var leaks into the client bundle (only `NEXT_PUBLIC_*` may).

## 4. Key decisions (made autonomously; revisit before building)

1. **Automated tests are the primary deliverable; no external DAST in CI.** The suite is Vitest + Testcontainers adversarial integration tests (negative authz/isolation/leakage cases) plus a security-focused smoke against the docker stack. We do **not** wire an external dynamic scanner (OWASP ZAP/Burp) into CI for v0.5.1 — it adds infra and flakiness; instead `SECURITY.md` documents an optional manual ZAP pass. Rationale: reproducible, fast, homelab-appropriate, fails-on-regression.
2. **Hardening ships as code, not just findings.** v0.5.1 doesn't merely report gaps — it closes §3 (headers, rate limiting) with real middleware + tests.
3. **Supply-chain gates added to CI.** Add `pnpm audit --audit-level=high` (fail on high/critical), `gitleaks` secret scan, and a header-assertion check. The existing release workflow already gates SLSA provenance/SBOM/attestation on public-repo visibility — keep that; document it as the supply-chain story for public deploys.
4. **Tenant-isolation test is exhaustive and table-driven.** One parametrized suite walks every workspace-scoped resource (pages, databases, properties, rows, views, comments, files, notifications, api-keys, webhooks, templates, page-versions) asserting cross-workspace access → 404. New resource types added later must extend this table (documented convention).
5. **Threat model is documented, lightweight (STRIDE-lite).** `SECURITY.md` records the trust boundaries (browser ↔ Next, Next ↔ collab WS, Next ↔ Postgres, public anon path, API-key clients, outbound webhooks), the per-boundary controls, the accepted residual risks (single-instance rate limiting; in-process webhook delivery; homelab threat profile), and how to report a vulnerability.

## 5. Scope

### In scope
- Adversarial security-regression test suite (`tests/security/*`): RBAC ceilings, table-driven cross-workspace isolation (→404), file-URL signature forgery/expiry, public-sharing leakage, collab-token forgery, API-key scope/expiry/rate-limit, webhook SSRF + signature, input-validation/injection inertness, XSS-on-public-render, secret-non-leakage.
- Secure-by-default hardening (§3): security headers, auth/collab-token rate limiting, cookie + secret-hygiene assertions.
- CI: `pnpm audit` gate, `gitleaks` secret scan, a security-headers assertion in the smoke.
- `SECURITY.md` (threat model, controls, residual risks, vuln-reporting) + README security section.
- A security-focused docker smoke (`scripts/smoke-security.sh`): headers present, anon cannot reach authed/cross-tenant resources, rate limit trips, forged tokens rejected.
- Version bump `0.5.1`, human-run tag.

### Deferred / out of scope
- External DAST (ZAP/Burp) automation in CI → documented manual procedure only.
- WAF, distributed rate limiting (Redis), bot/CAPTCHA → not for homelab scale.
- Formal third-party pen test / audit → out of band.
- Encryption-at-rest beyond Postgres/host-level, E2E encryption → explicitly out of the 0.x line.
- 2FA/MFA, SSO/SAML → future, not this patch.

## 6. Architecture by area

- **Test suite layout:** `tests/security/` — `isolation.test.ts` (table-driven cross-workspace 404 over all resources), `rbac.test.ts` (role ceilings per route), `file-signing.test.ts` (forge/expire HMAC), `public-leakage.test.ts` (unpublished/deleted → 404, no draft content), `collab-token.test.ts` (forged/expired/wrong-page), `api-keys.test.ts` (scope/expiry/revoke/rate-limit), `webhooks-ssrf.test.ts` (SSRF guard + signature), `injection.test.ts` (SQL/zod inertness), `xss-public.test.ts` (script in stored content not executed on `/p/`), `secret-leak.test.ts` (responses/logs/bundle clean). Reuse existing `tests/helpers` (Testcontainers, fixtures, the `__set` session mock).
- **Security headers:** `src/lib/security/headers.ts` (the header map + CSP builder, pure + unit-tested) applied in `next.config.mjs` `headers()` for static/most routes, with the public `/p/` path getting its own (still-locked-down) policy. Verify the CSP doesn't break the editor (TipTap inline styles), the collab WS connection (`connect-src` includes `COLLAB_URL`), or signed file images (`img-src` includes self).
- **Rate limiting:** `src/lib/security/rate-limit.ts` — reuse/generalize the v0.5.0 API token-bucket; a `withRateLimit(keyFn, opts)` wrapper applied to `signIn`/signup/`/api/collab/token`. Keyed by IP (from `x-forwarded-for`, trust-proxy-aware) + identifier. In-memory; documented ceiling.
- **Secret hygiene:** `tests/security/secret-leak.test.ts` greps representative API responses + a captured log buffer for known secret shapes; a build-time assertion (script) scans `.next` client chunks for non-`NEXT_PUBLIC_` env values.
- **CI:** extend `.github/workflows/ci.yml` with a `security` job: `pnpm audit --audit-level=high`, `gitleaks detect`, and run the `tests/security` suite. (The security tests also run in the normal `pnpm test`.)
- **`SECURITY.md`:** threat model (STRIDE-lite), trust boundaries + controls table (mirrors §2), residual risks, supported versions, vuln-reporting contact/process.

## 7. Plan decomposition

Single plan (it's a patch): `2026-05-21-cairn-v0.5.1-security.md`, tasks:
1. **Tenant-isolation + RBAC suite** — table-driven cross-workspace 404 over all resources; role-ceiling negative tests. (Pure regression value; may surface real isolation bugs to fix.)
2. **Boundary-token suites** — file-URL signature forgery/expiry, collab-token forgery, public-sharing leakage, API-key scope/expiry/revoke.
3. **Injection / XSS / secret-leak suites** — zod/SQL inertness, script-in-content not executed on public render, secrets absent from responses/logs/bundle.
4. **Security headers** — `headers.ts` + CSP builder (unit-tested) wired into `next.config`/public path; verify editor + collab + images still work.
5. **Rate limiting** — generalized token bucket on login/signup/collab-token; webhook SSRF-guard test (guard itself ships in v0.5.0).
6. **CI supply-chain + SECURITY.md + smoke** — `pnpm audit` + `gitleaks` + security job; `scripts/smoke-security.sh` (headers, anon/cross-tenant denial, rate-limit trip); `SECURITY.md`; version bump `0.5.1`; human-run tag.

## 8. Risks
- **CSP can break the app silently** (editor inline styles, collab WS, signed images, OAuth redirects). Build the policy incrementally and verify each surface (editor mount, `/p/` render, collab connect, image load, Google/GitHub redirect) in the smoke before locking it down. Start in report-only if needed, then enforce.
- **Rate limiting false-positives** behind a reverse proxy if `x-forwarded-for` isn't trusted correctly — make the trust-proxy behavior explicit and test it; don't lock out legitimate homelab users.
- **In-process rate limiting + webhook delivery** are single-instance — same documented ceiling as v0.5.0; not a regression, but state it in `SECURITY.md`.
- **A security test that finds a real bug** is success, not failure — if the isolation/RBAC suite surfaces a leak, fix it within this release (the fix is the point).
- `pnpm audit` may flag transitive advisories with no fix available — allow a reviewed, time-boxed ignore list (documented), don't block indefinitely on un-fixable upstream advisories.
